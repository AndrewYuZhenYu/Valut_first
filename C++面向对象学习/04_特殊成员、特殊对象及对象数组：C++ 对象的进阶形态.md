## 二、对象数组

### 2.1 对象数组的实质与声明要则

> [!important] 对象数组的实质
> 对象数组是**同类多个对象的集合**，在内存中**连续存储**。数组中的每一个元素都是一个完整的对象，各自拥有独立的成员数据（非静态），同时共享同一份成员函数代码。
>
> **与内置类型数组的本质区别**：内置类型数组（如 `int arr[3];`）的元素只分配了空间，其值是未初始化的垃圾值；而对象数组的每一个元素在定义时都会**自动调用构造函数**，是“已经构造好的对象”。这一区别决定了对象数组必须满足“类存在可用的构造函数”这一前提。

**核心声明规则**：如果对象所属的类**不包含无参构造函数**，也没有**带有完全缺省参数的构造函数**，那么在声明对象数组时，**必须通过初始化列表为每一个数组元素显式传递参数**。否则，编译器无法为数组元素找到可用的构造函数，会直接报编译错误。

```cpp
// 定义一个只有双参构造函数的复数类
class CComplex {
    double mR, mI;
public:
    CComplex(double zR, double zI);   // 只有双参构造，无全缺省参数
    void Show() const { cout << mR << "+" << mI << "i" << endl; }
};

// 场景一：没有无参构造，必须用初始化列表
void f() {
    // CComplex zCArray[2];          // ❌ 编译错误：没有匹配的无参构造函数
    CComplex zCArray[2] = {          // ✅ 正确：初始化列表逐元素传参
        CComplex(2, 3),              // 构造 zCArray[0]，实部 2，虚部 3
        CComplex(5, 6)               // 构造 zCArray[1]，实部 5，虚部 6
    };
    zCArray[0].Show();               // 输出：2+3i
    zCArray[1].Show();               // 输出：5+6i
}
```

**逐行解读**：

- `CComplex(double zR, double zI);` —— 用户在类中显式定义了一个双参构造函数。此时，编译器**不再自动生成**缺省的无参构造函数。
- `// CComplex zCArray[2];` —— 如果尝试直接声明包含两个元素的对象数组，编译器会尝试为每个元素调用无参构造 `CComplex()`，但由于类中没有这个函数，因此编译失败，报错类似 `no matching function for call to 'CComplex::CComplex()'`。
- `CComplex zCArray[2] = { CComplex(2, 3), CComplex(5, 6) };` —— 使用初始化列表，显式指定每个元素的构造函数参数。`zCArray[0]` 调用 `CComplex(2, 3)`，`zCArray[1]` 调用 `CComplex(5, 6)`。这种写法在 C++11 之前是唯一可行的方式；C++11 之后也支持 `CComplex zCArray[2] = { {2, 3}, {5, 6} };` 这种简写形式（编译器会自动推断为调用双参构造）。
- `zCArray[0].Show();` —— 通过数组下标访问元素，调用其成员函数。这说明每个元素都是一个独立的对象，可以正常使用。

**补充说明**：如果类中提供了带有全缺省参数的构造函数，那么数组声明时可以省略初始化列表。此时每个元素都会使用缺省值进行构造。

```cpp
// 提供一个带全缺省参数的构造函数
class CComplex {
    double mR, mI;
public:
    CComplex(double zR = 0, double zI = 0);   // 全缺省，支持无参调用
};

void g() {
    CComplex zCArray[2];   // ✅ 合法：每个元素调用 CComplex(0, 0)
}
```

**边界情况分析**：

| 类中构造函数情况 | `T arr[n];` | `T arr[n] = { ... };` |
| :--- | :--- | :--- |
| 无任何自定义构造（编译器生成缺省构造） | ✅ 合法，每个元素调用缺省构造（不初始化内置成员） | ✅ 合法，按列表构造，剩余元素调用缺省构造 |
| 只有全缺省参数构造 | ✅ 合法，每个元素用缺省值构造 | ✅ 合法，按列表构造，剩余元素用缺省值构造 |
| 只有带参构造（无全缺省） | ❌ 编译错误 | ✅ 合法，必须为每个元素提供参数（或部分提供，剩余报错） |
| 既有带参构造，又有无参构造 | ✅ 合法，每个元素调用无参构造 | ✅ 合法，按列表构造，剩余元素调用无参构造 |

### 2.2 构造与析构的执行过程

> [!important] 对象数组的构造/析构顺序
> 当定义对象数组时，**构造函数按数组下标递增的顺序**（从 0 到 n-1）逐个调用。当数组的生命周期结束（离开作用域或执行 `delete[]`）时，**析构函数按数组下标递减的顺序**（从 n-1 到 0）逆序调用。

```cpp
#include <iostream>
using namespace std;

class CComplex {
    double mR, mI;
public:
    // 构造函数，打印构造信息
    CComplex(double zR = 0, double zI = 0) : mR(zR), mI(zI) {
        cout << "构造复数 [" << mR << "," << mI << "]" << endl;
    }
    // 析构函数，打印析构信息
    ~CComplex() {
        cout << "析构复数 [" << mR << "," << mI << "]" << endl;
    }
};

int main() {
    // 定义包含 3 个元素的对象数组
    CComplex arr[3] = { CComplex(1, 1), CComplex(2, 2), CComplex(3, 3) };
    cout << "--- 数组定义完成，开始使用 ---" << endl;
    return 0;
}
```

**运行结果与深度解读**：

```text
构造复数 [1,1]          ← arr[0] 构造
构造复数 [2,2]          ← arr[1] 构造
构造复数 [3,3]          ← arr[2] 构造
--- 数组定义完成，开始使用 ---
析构复数 [3,3]          ← arr[2] 析构
析构复数 [2,2]          ← arr[1] 析构
析构复数 [1,1]          ← arr[0] 析构
```

- **构造顺序**：先 `arr[0]`（构造 `[1,1]`），再 `arr[1]`（构造 `[2,2]`），最后 `arr[2]`（构造 `[3,3]`）。这是从数组起始地址向高地址方向依次构造的过程。
- **析构顺序**：`main` 函数返回时，数组 `arr` 的生命周期结束。析构函数从数组末尾开始逆序调用：先 `arr[2]`（析构 `[3,3]`），再 `arr[1]`（析构 `[2,2]`），最后 `arr[0]`（析构 `[1,1]`）。这模拟了“栈”的弹出顺序。
- **为什么逆序析构**：对象之间可能存在构造依赖关系。例如 `arr[1]` 在构造时可能使用了 `arr[0]` 的某些信息。为了保证析构时依赖关系仍然成立，必须逆序析构——先销毁依赖者，再销毁被依赖者。

> [!note] 异常安全机制
> 如果数组在构造过程中，某个元素的构造函数抛出异常，那么已经构造成功的元素会按照**构造顺序的逆序**被自动析构，保证已经分配的资源被正确释放。例如 `arr[2]` 的构造函数抛出异常，则 `arr[1]`、`arr[0]` 会依次析构，而 `arr[2]` 本身不会析构（因为它没有构造完成）。这是 C++ 异常安全机制的重要组成部分，称为“栈展开”（stack unwinding）。

### 2.3 new[] 与对象数组的绑定

```cpp
CComplex *pArr = new CComplex[3];   // 在堆上分配 3 个对象
```

**逐行解读**：

- `new CComplex[3]` —— 在堆上分配足够容纳 3 个 `CComplex` 对象的内存空间，并**逐个调用无参构造函数**。
- **前提条件**：类必须包含无参构造函数（或带有全缺省参数的构造函数），否则编译报错。这与栈上对象数组的要求一致。这是因为 `new[]` 无法为每个元素传递不同的参数，只能统一调用无参构造。
- `new[]` 的限制：`new CComplex[3]` **无法为每个元素传递不同的参数**。所有元素都只能使用同一个无参构造进行初始化。如果需要每个元素有不同的初值，应该使用 `std::vector<CComplex>`，配合 `emplace_back` 或 `push_back` 来逐个添加元素：

```cpp
#include <vector>
std::vector<CComplex> v;
v.emplace_back(2, 3);    // 构造 [2,3]
v.emplace_back(5, 6);    // 构造 [5,6]
```

```cpp
delete[] pArr;   // 释放堆上的对象数组
```

**逐行解读**：

- `delete[] pArr;` —— 与 `new[]` 配对使用。它会**逆序调用**每个元素的析构函数（从 `pArr[2]` 到 `pArr[0]`），然后释放底层内存。
- **严重错误**：如果误用 `delete pArr;`（缺少 `[]`），则只会调用第一个元素的析构函数，导致其余元素未析构，可能造成资源泄漏或堆破坏（未定义行为）。在有些编译器实现中，`delete` 与 `delete[]` 的底层内存布局不同（`new[]` 会在内存块头部记录元素个数），混用会导致内存管理器读取错误的元数据，直接崩溃。

> [!warning] 对象数组常见错误总结
> 1. **无无参构造时声明数组**：`T arr[n];` 会编译错误，必须使用初始化列表。
> 2. **无无参构造时 new 数组**：`new T[n]` 会编译错误，因为 `new[]` 只支持无参构造。
> 3. **delete 与 delete[] 混用**：对对象数组使用 `delete` 而非 `delete[]` 是未定义行为，可能导致部分元素析构失败或堆内存损坏。
> 4. **初始化列表数量少于数组大小**：未显式初始化的元素会尝试调用无参构造。如果类没有无参构造，则编译错误；如果有，则使用默认值。
> 5. **数组下标越界**：C++ 原生数组不做边界检查，越界访问是未定义行为，可能破坏相邻对象的内存。

## 三、静态成员

### 3.1 成员类型声明要领

> [!note] 数据类型与存储类型
> - **数据类型**：规定数据的存储格式（如 `int`、`double`、`char*`、自定义类）。
> - **存储类型**：规定生命周期或存储特性（如 `auto`、`static`、`register`、`extern`）。
>
> 成员数据的允许类型：数据类型可以是任何标准数据类型或自定义类型（**包括指针类型**）；存储类型只能是 `auto` 或 `static`。
>
> 成员函数允许类型：普通成员函数、`static` 静态成员函数。

```cpp
class CExample {
    double *mA;          // ✅ 指针型数据成员：指向 double 的指针
    static long mNo;     // ✅ 静态数据成员：属于类，所有对象共享
    // register char mC; // ❌ 错误：register 不能修饰成员
    // extern float mD;  // ❌ 错误：extern 不能修饰成员
};
```

**逐行解读**：

- `double *mA;` —— 合法的指针型成员变量。它的生命周期和资源管理需要程序员在构造/析构函数中手动处理。指针型成员是造成“浅拷贝”问题的根源（详见上一讲拷贝构造部分）。
- `static long mNo;` —— 合法的静态数据成员声明。它不属于任何具体的对象，而是属于类本身，所有对象共享同一份存储。`static` 在这里是“存储类型”，而不是“数据类型”。
- `register` 和 `extern` 这两种 C 语言中常见的存储类型修饰符，**不允许**用于修饰类的成员。`register` 原本建议编译器将变量放入寄存器，但现代编译器会自动优化，该关键字在 C++17 后被弃用；`extern` 表示变量定义在别处，但成员变量必须在类内声明、类外定义，因此不需要也不允许 `extern`。
- C++11 之后，`auto` 可以用于成员声明，但必须带有初始值（例如 `auto mX = 0;`），编译器会根据初始值推导类型。这在模板编程中偶尔使用。

### 3.2 静态数据成员

> [!important] 静态数据成员的核心特征
> - **属于类，不属于对象**：静态数据成员独立于任何对象而存在，是从属于类的属性。可以把它理解为“类的全局变量”。
> - **所有对象共享一份**：同一个类的所有对象访问的是同一块内存。一个对象修改了静态成员，其他对象看到的也是修改后的值。
> - **存储位置**：存储在全局/静态存储区，**不占用对象的内存空间**。因此 `sizeof(对象)` 的结果不包含静态成员。
> - **必须在类外定义并初始化**：类内的 `static` 关键字只是声明，不分配内存。必须在源文件（`.cpp`）中给出定义和初始化，否则链接时会报错（`undefined reference`）。
> - **访问方式**：推荐使用 `类名::成员名`。虽然也可以通过 `对象.成员名` 访问，但容易误导人以为它属于对象。
> - **生命周期**：从程序启动时分配，直到程序结束时销毁，与对象的生命周期无关。
> - **典型用途**：对象计数、共享资源管理、链表中的头指针/尾指针、单例模式中的实例指针等。

```cpp
// Complex.h 头文件
class CComplex {
    double mR, mI;
    static int mNo;                    // ① 静态数据成员声明（类内）
public:
    CComplex(double zR = 0, double zI = 0);
    static int GetCount();             // 静态成员函数声明
};

// Complex.cpp 源文件
int CComplex::mNo = 0;                 // ② 静态数据成员定义并初始化（类外）
```

**逐行解读**：

- ① `static int mNo;` —— 在类内部**声明**一个静态数据成员。此时只告诉了编译器“这个类有一个叫 `mNo` 的静态成员”，但**并没有分配内存**。它相当于一个“承诺”，告诉编译器“我将在类外给出它的定义”。
- ② `int CComplex::mNo = 0;` —— 在类外部（源文件中）**定义并初始化**。这一行才真正分配了存储空间，并将初始值设为 `0`。注意，这里**不能再写 `static` 关键字**（写了也不会报错，但语义上不必要，且容易引起困惑）。如果漏掉这一行，链接器将找不到 `mNo` 的定义，导致链接错误，报错类似 `undefined reference to 'CComplex::mNo'`。

**为什么必须类外定义？** 因为静态成员不属于任何对象，它的存储分配不能依赖于对象的创建。如果允许在类内定义并分配存储，那么当多个源文件包含该头文件时，就会出现重复定义的链接错误。因此 C++ 采用“类内声明、类外定义”的模式，保证全程序只有一份定义。

**对象计数示例**：

```cpp
// 构造函数中增加计数
CComplex::CComplex(double zR, double zI) : mR(zR), mI(zI) {
    mNo++;                             // 每构造一个对象，共享计数 +1
}

// 析构函数中减少计数
CComplex::~CComplex() {
    mNo--;                             // 每析构一个对象，共享计数 -1
}
```

**逐行解读**：

- 在构造函数体内，`mNo++` 操作的是**全类共享**的那一份静态数据成员。无论构造的是哪一个具体的 `CComplex` 对象，`mNo` 都会递增。
- 在析构函数体内，`mNo--` 同理，实时维护当前存活对象的数量。
- **注意**：静态数据成员**不能**在构造函数的初始化列表中进行初始化，因为它不属于任何一个对象。它只能在类外定义时初始化，或者在成员函数体内进行赋值修改。
- **一个常见的误区**：把 `mNo` 放在初始化列表中写 `CComplex(...) : mR(zR), mI(zI), mNo(0) { }` 是错误的，编译器会报错。因为初始化列表中的每一项都是在构造“当前对象的成员”，而 `mNo` 不是当前对象的成员。

**进一步观察**：静态数据成员可以在没有创建任何对象的情况下被访问和修改：

```cpp
int main() {
    CComplex::SetCount(10);   // 假设有静态函数 SetCount，直接通过类名调用
    // 此时 mNo = 10，但没有创建任何 CComplex 对象
    CComplex c1;              // 构造后 mNo = 11
    return 0;
}
```

这说明静态成员的生命周期和对象是解耦的。

### 3.3 静态成员函数

> [!important] 静态成员函数的核心特征
> - **没有 `this` 指针**：静态成员函数不依赖于任何对象，因此没有隐含的 `this` 指针。它们不“知道”是哪个对象调用了自己。
> - **只能访问静态成员**：由于没有 `this`，静态成员函数无法直接访问非静态数据成员或调用非静态成员函数。它只能访问类的静态数据成员和其他静态成员函数。
> - **不能声明为 `const` 或 `volatile`**：`const` 和 `volatile` 修饰的是成员函数隐含的 `this` 指针。静态成员函数没有 `this`，因此不能用这两个关键字修饰。编译器会直接报错。
> - **调用方式**：推荐使用 `类名::函数名()`。也可以通过 `对象.函数名()` 调用，但只是为了语法上的方便，本质上与对象无关。即使对象是 `const` 的，静态函数也可以被调用。
> - **典型用途**：访问/修改静态数据成员、提供工具函数（如工厂方法）、提供全局配置的读写接口。

```cpp
class CComplex {
    double mR, mI;
    static int mNo;
public:
    CComplex(double zR = 0, double zI = 0);
    static void IsLucky1();                       // 静态成员函数：只能访问静态成员
    static void IsLucky2(const CComplex& zC);     // 静态成员函数：通过参数访问对象
};

void CComplex::IsLucky1() {
    if (mNo == 8)                                 // ✅ 正确：访问静态成员
        cout << "C[" << mNo << "] is lucky!" << endl;
    // cout << mR;                                // ❌ 错误：无 this，不能直接访问非静态成员
}

void CComplex::IsLucky2(const CComplex& zC) {
    if (zC.mR == 8 && zC.mI == 8 && mNo == 8)     // ✅ 通过参数访问对象成员
        cout << "lucky" << endl;
}
```

**逐行解读**：

- `IsLucky1` 函数中，`mNo` 是静态数据成员，可以直接访问；`mR` 是非静态成员，由于没有 `this` 指针指明是哪个对象的 `mR`，因此**不能**直接访问。如果尝试写 `cout << mR;`，编译器会报错：`invalid use of member 'CComplex::mR' in static member function`。
- `IsLucky2` 函数接收了一个 `const CComplex& zC` 参数。通过这个参数，可以用 `zC.mR` 和 `zC.mI` 访问传入对象的成员。这是在静态成员函数中操作非静态数据的标准做法——**通过参数传入对象，代替隐含的 `this`**。
- 静态成员函数既可以通过类名调用，也可以通过对象调用。例如 `CComplex::IsLucky1()` 和 `zC.IsLucky1()` 效果相同。即使 `zC` 是 `const` 对象，也可以调用静态成员函数，因为静态函数根本不涉及 `this`。

**调用方式的对比**：

| 调用方式 | 适用函数 | 说明 |
| :--- | :--- | :--- |
| `obj.func()` | 普通成员函数、静态成员函数 | 普通函数依赖 `obj`，静态函数“借用”语法 |
| `ptr->func()` | 普通成员函数、静态成员函数 | 指针版调用 |
| `类名::func()` | **仅静态成员函数** | 明确表示类级别操作，推荐 |

### 3.4 作用域

C++ 中的作用域分为多个层级，理解这些层级对于名称查找和可见性至关重要。

| 作用域类型 | 范围 | 说明 |
| :--- | :--- | :--- |
| **文件作用域** | 整个 `.cpp` 源文件 | 全局变量、静态全局变量、函数定义。`#include` 的头文件内容也会被展开到此处。 |
| **函数作用域** | 函数体内部 | 函数的局部变量、形式参数、函数返回值。 |
| **复合语句作用域** | `{}` 块内部 | 例如 `for` 循环头部定义的变量、`if` 块内部定义的变量。 |
| **类作用域** | 类定义内部 | 涵盖该类的所有成员函数作用域。成员名在类内可直接访问。 |

**文件作用域示例**：

```cpp
// Complex.h 头文件
extern int zLuck;              // 声明：告诉编译器 zLuck 定义在别的地方

// ComplexRoutine.cpp 源文件
#include "Complex.h"
static int zLuck = 9;          // ⚠️ 静态全局变量：仅本文件可见
```

**逐行解读**：

- 头文件中使用 `extern int zLuck;` 声明了一个具有**外部链接**的全局变量，表示它可能在别的源文件中定义。
- 但在 `.cpp` 源文件中，使用 `static int zLuck = 9;` 定义了一个具有**内部链接**的静态全局变量。
- 这就造成了一个问题：头文件声明的是外部链接的 `zLuck`，而源文件中定义的是内部链接的 `zLuck`。**两者同名，但指向不同的实体**。这通常是一个设计错误，会导致链接时出现意料之外的行为（例如在其他源文件中访问 `zLuck` 时，可能链接到另一个未定义的符号）。
- **正确做法**：如果要在头文件中用 `extern` 声明，那么在源文件中定义时就不应加 `static` 关键字。二者必须保持一致。

**类作用域示例**：

```cpp
class CComplex {
    double mR, mI;
public:
    CComplex(double zR, double zI);
};

CComplex::CComplex(double zR, double zI) {
    mR = zR;                   // 在类作用域内，mR 可以直接访问
    mI = zI;
}

int main() {
    CComplex zC(2, 1);
    // cout << mR;             // ❌ 错误：main 函数不在类作用域内，且 mR 是私有成员
    return 0;
}
```

**逐行解读**：

- 在成员函数 `CComplex::CComplex` 内部，直接使用 `mR` 和 `mI` 是合法的，因为这里处于**类作用域**内。
- 在 `main` 函数中，尝试访问 `mR` 会编译错误。原因有两个：第一，`main` 不在类作用域内；第二，`mR` 是 `private` 成员，外部无法访问。

**复合语句作用域的补充说明**：

```cpp
void f() {
    for (int i = 0; i < 10; i++) {   // i 的作用域仅限于 for 循环体
        // ...
    }
    // cout << i;                    // ❌ 错误：i 已经超出作用域
}
```

在 C++ 中，`for` 循环头部定义的变量 `i` 属于**复合语句作用域**，循环结束后即销毁。这保证了变量的最小可见性，避免命名污染。这一规则也适用于 `if`、`while`、`switch` 等语句块。

## 四、const 对象与 volatile 对象（对比分析）

### 4.1 共同机制

> [!important] const / volatile 对象的限定机制
> `const` 和 `volatile` 都是**对象限定符**，它们通过改变成员函数隐含的 `this` 指针类型来约束访问权限：
>
> | 对象类型 | `this` 指针类型 | 可调用的成员函数 |
> | :--- | :--- | :--- |
> | 普通对象 | `T* const` | 普通成员函数、`const` 成员函数、`volatile` 成员函数 |
> | `const` 对象 | `const T* const` | 只能调用 `const` 成员函数 |
> | `volatile` 对象 | `volatile T* const` | 只能调用 `volatile` 成员函数 |
> | `const volatile` 对象 | `const volatile T* const` | 只能调用 `const volatile` 成员函数 |

**深层原因**：成员函数的调用本质上是将调用者的地址作为隐含的 `this` 参数传给函数。如果 `this` 是指向 `const` 的指针（`const T*`），那么函数体内任何修改成员的操作都会在编译期被禁止。这就保证了 `const` 对象的安全性。同理，`volatile` 保证每次访问都从内存重读，不会被编译器优化掉。

### 4.2 const 对象

```cpp
class CComplex {
    double mR, mI;
    mutable int mAccessCount;              // mutable：允许在 const 函数中修改
public:
    CComplex(double zR = 0, double zI = 0) : mR(zR), mI(zI), mAccessCount(0) {}
    void Display() const {                 // const 成员函数
        ++mAccessCount;                    // ✅ mutable 成员在 const 函数中可修改
        cout << mR << "+" << mI << "i" << endl;
    }
    void SetValue(double, double);         // 普通成员函数
};

void f() {
    const CComplex zC(2, 3);               // const 对象必须初始化
    zC.Display();                          // ✅ 正确：const 对象调用 const 成员函数
    // zC.SetValue(5, 6);                  // ❌ 错误：const 对象不能调用非 const 成员函数
}
```

**逐行解读**：

- `mutable int mAccessCount;` —— `mutable` 修饰符允许该成员在 `const` 成员函数中被修改。这通常用于缓存、计数器等逻辑上不改变对象状态的场景。从“语义”的角度看，`mAccessCount` 只是记录被访问次数，不改变复数本身的值，所以可以声明为 `mutable`。
- `const CComplex zC(2, 3);` —— 声明一个 `const` 对象，必须在定义时初始化（调用构造函数）。此后，其成员不能被修改。
- `zC.Display();` —— `Display` 被声明为 `const` 成员函数，承诺不修改非 `mutable` 成员，因此可以被 `const` 对象调用。
- `zC.SetValue(...)` —— `SetValue` 是普通成员函数，可能修改成员，编译器禁止 `const` 对象调用它。这是编译期检查，不是运行时检查。

**const 成员函数的声明与定义必须一致**：

```cpp
class CComplex {
    // ...
    void Display() const;      // 声明带 const
};

void CComplex::Display() const {   // 定义也必须带 const
    // ...
}
```

如果声明带了 `const`，但定义漏写 `const`，编译器会认为这是两个不同的函数重载，导致链接错误（`undefined reference`）。反之亦然。

### 4.3 volatile 对象

```cpp
class CTest {
    int mX, mY;
public:
    CTest(int x = 0, int y = 0) : mX(x), mY(y) {}
    void SetValue(int i, int j) volatile {   // volatile 成员函数
        mX = i;
        mY = j;
    }
    int GetX() volatile { return mX; }       // 每次调用都从内存重新读取
};

void f() {
    volatile CTest zT(2, 3);                 // volatile 对象
    zT.SetValue(5, 6);                       // ✅ 正确：volatile 对象调用 volatile 函数
    // zT.GetX();                            // 若 GetX 不是 volatile，则编译错误
}
```

**逐行解读**：

- `volatile CTest zT(2, 3);` —— 声明一个 `volatile` 对象。这意味着该对象的值可能在程序控制之外被修改（例如被硬件、操作系统或其他线程修改）。
- `void SetValue(int i, int j) volatile` —— `volatile` 成员函数保证每次访问成员时都从内存中重新读取，而不会被编译器优化缓存到寄存器中。这对于访问硬件寄存器的代码非常重要。
- `zT.SetValue(5, 6);` —— `volatile` 对象只能调用带有 `volatile` 限定符的成员函数。因为普通函数可能被编译器优化，造成对 `volatile` 对象的读取被缓存，违背了 `volatile` 的语义。

**volatile 的使用场景**：

| 场景 | 说明 |
| :--- | :--- |
| 硬件寄存器访问 | 寄存器值可能被硬件随时修改，每次读取必须从内存重读。 |
| 信号处理函数 | `volatile sig_atomic_t` 用于信号处理中的共享标志。 |
| 并发编程中的共享标志 | 早期 C/C++ 中用于多线程共享标志，但现代 C++ 推荐使用 `std::atomic`。 |

**volatile 的局限性**：`volatile` 只保证“每次访问重读”，**不保证原子性**，也不提供内存序（memory ordering）约束。在多线程环境下，仅用 `volatile` 做同步是错误的，必须使用 `std::atomic`、互斥锁等同步机制。

### 4.4 const 与 volatile 的组合

```cpp
class CDevice {
    int mStatus;
public:
    int ReadStatus() const volatile {   // 既只读，又每次重读
        return mStatus;
    }
};
```

`const volatile` 对象表示“既不可修改、又可能被外部改变”，常用于硬件状态寄存器。它只能调用同时带 `const` 和 `volatile` 的成员函数。

## 五、成员对象

### 5.1 复合类与成员对象

> [!important] 复合类的概念
> 如果一个类中的成员是**另一个类的对象**，那么这个成员被称为**成员对象**，包含该成员对象的类被称为**复合类**。复合类体现的是 "has-a"（拥有）关系。例如，一个 `CCircle`（圆）拥有一个 `CPoint`（点）作为其圆心。

```cpp
// Point.h 头文件
#ifndef CPOINT_H
#define CPOINT_H

class CPoint {
    double mX, mY;
public:
    CPoint(double zX = 0, double zY = 0);
    void Show() const;
};

#endif
```

```cpp
// Circle.h 头文件
#include "Point.h"

class CCircle {
    CPoint mCenter;          // 成员对象：圆心
    double mRadius;          // 半径
public:
    CCircle(double zX = 0, double zY = 0, double zR = 1);
    CCircle(CPoint zP, double zR = 1);
    void Show() const;
};
```

**复合类与继承的区别**：

| 关系 | 关键字 | 语义 | 示例 |
| :--- | :--- | :--- | :--- |
| 组合（has-a） | 成员对象 | 圆**拥有**一个点作为圆心 | `CCircle` 含 `CPoint` |
| 继承（is-a） | `public` 继承 | 圆**是一种**形状 | `CCircle` 继承 `CShape` |

本讲只讨论组合关系，继承将在后续讲次展开。

### 5.2 复合类构造：必须使用初始化列表

```cpp
// Circle.cpp 源文件
#include "Circle.h"

// 构造函数一：通过坐标值初始化圆心
CCircle::CCircle(double zX, double zY, double zR) : mCenter(zX, zY) {
    mRadius = zR;
}

// 构造函数二：通过另一个 CPoint 对象初始化圆心
CCircle::CCircle(CPoint zP, double zR) : mCenter(zP) {
    mRadius = zR;
}
```

**逐行解读**：

- `: mCenter(zX, zY)` —— **成员对象 `mCenter` 必须在构造函数的初始化列表中进行构造**。在进入 `CCircle` 构造函数的函数体之前，`mCenter` 会先被构造成 `CPoint(zX, zY)`。如果不在初始化列表中指定构造参数，编译器会尝试调用 `mCenter` 的无参构造函数。如果 `CPoint` 没有无参构造，就会导致编译错误。
- `: mCenter(zP)` —— 用另一个 `CPoint` 对象来初始化 `mCenter`，这会调用 `CPoint` 的拷贝构造函数。注意，这里传入的是 `CPoint` 的值，而不是引用，所以会先发生一次拷贝构造（参数传递），然后再用这个副本初始化 `mCenter`（又一次拷贝构造）。如果改用 `const CPoint& zP` 可以省去第一次拷贝。
- `mRadius = zR;` —— 普通内置类型的成员可以在函数体内赋值，也可以放在初始化列表中。放在初始化列表中效率更高，因为省去了先默认初始化再赋值的步骤。

> [!warning] 必须使用初始化列表的场景
> 1. 成员对象**没有无参构造函数**（或全缺省参数构造函数），必须在初始化列表中传递参数。
> 2. 成员对象是 `const` 类型，必须在初始化列表中初始化。
> 3. 成员对象是引用类型，必须在初始化列表中初始化。
> 4. 需要调用成员对象的带参构造函数，而不是默认构造。

### 5.3 构造与析构的顺序

> [!important] 复合类对象的生命周期顺序
> **构造过程**：
> 1. 分配复合类对象所需的内存空间。
> 2. **按成员在类中的声明顺序**，依次构造成员对象。**注意：这个顺序由声明顺序决定，与构造函数初始化列表的书写顺序无关。**
> 3. 执行复合类自身的构造函数体。
>
> **析构过程**：
> 4. 执行复合类自身的析构函数体。
> 5. **按成员声明顺序的逆序**，依次析构成员对象。
> 6. 释放对象占用的内存空间。

**可视化示例**：

```cpp
#include <iostream>
using namespace std;

class CPoint {
public:
    CPoint(double x = 0, double y = 0) {
        cout << "构造 CPoint(" << x << "," << y << ")" << endl;
    }
    ~CPoint() {
        cout << "析构 CPoint" << endl;
    }
};

class CCircle {
    CPoint mCenter;          // 成员对象
    double mRadius;
public:
    CCircle(double x = 0, double y = 0, double r = 1) : mCenter(x, y), mRadius(r) {
        cout << "构造 CCircle(半径 " << mRadius << ")" << endl;
    }
    ~CCircle() {
        cout << "析构 CCircle" << endl;
    }
};

int main() {
    CCircle zC(1, 1, 2);
    return 0;
}
```

**输出与解读**：

```text
构造 CPoint(1,1)        ← 1. 成员对象 mCenter 先构造
构造 CCircle(半径 2)     ← 2. 复合类自身 CCircle 后构造
析构 CCircle            ← 3. 复合类自身先析构
析构 CPoint             ← 4. 成员对象后析构
```

**顺序记忆口诀**：**成员先生、自身后生；自身先死、成员后死。**

**为什么是这样的顺序？** 因为复合类自身的构造函数体可能依赖于成员对象已经构造完成。例如 `CCircle` 的构造函数体可能调用 `mCenter.Show()`，此时 `mCenter` 必须已经构造好。析构时反过来，复合类自身的析构函数体可能还需要访问成员对象，所以自身先析构，成员后析构。

### 5.4 初始化次序陷阱

```cpp
class CTriangle {
    CPoint mVertex1, mVertex2, mVertex3;   // 声明顺序：V1 → V2 → V3
public:
    CTriangle(double x1, double y1, double x2, double y2, double x3, double y3);
};

CTriangle::CTriangle(double x1, double y1, double x2, double y2, double x3, double y3)
    : mVertex2(x2, y2), mVertex3(x3, y3), mVertex1(x1, y1)   // 列表书写顺序：V2 → V3 → V1
{
}
```

**逐行解读**：

- 在构造函数的初始化列表中，书写的顺序是 `mVertex2`、`mVertex3`、`mVertex1`。
- **实际的构造顺序**与列表书写顺序无关，而是严格按照成员在类中的**声明顺序**：`mVertex1` 先构造，然后是 `mVertex2`，最后是 `mVertex3`。
- 编译器通常会针对“初始化列表顺序与声明顺序不一致”的情况给出警告（例如 GCC 的 `-Wreorder`）。
- **析构顺序**是构造顺序的逆序：`mVertex3` → `mVertex2` → `mVertex1`。

> [!warning] 为什么要严格按声明顺序书写初始化列表
> 如果成员 A 的初始化依赖于成员 B，而 B 在初始化列表中书写在 A 之前，但在类中声明在 A 之后，那么实际构造时，A 会先于 B 被初始化。此时 A 拿到的可能是 B 的未初始化值（垃圾值）。**始终按声明顺序书写初始化列表**，可以避免这类隐蔽的逻辑错误。

## 六、综合例程：静态计数与复合类生命周期

```cpp
#include <iostream>
using namespace std;

class CPoint {
public:
    CPoint(double x = 0, double y = 0) {
        cout << "CPoint(" << x << "," << y << ")" << endl;
    }
    ~CPoint() {
        cout << "~CPoint" << endl;
    }
};

class CCircle {
    CPoint mCenter;                    // 成员对象
    double mRadius;
    static int sCount;                 // 静态计数：记录当前存活的圆对象数
public:
    CCircle(double x = 0, double y = 0, double r = 1) : mCenter(x, y), mRadius(r) {
        ++sCount;
        cout << "CCircle(半径 " << mRadius << ") 当前对象数：" << sCount << endl;
    }
    ~CCircle() {
        --sCount;
        cout << "~CCircle 当前对象数：" << sCount << endl;
    }
    static int GetCount() { return sCount; }
};

// 静态成员必须在类外定义
int CCircle::sCount = 0;

int main() {
    cout << "--- 进入 main ---" << endl;
    CCircle c1(1, 1, 2);               // 构造：CPoint → CCircle，计数 1
    {
        CCircle c2(2, 2, 3);           // 构造：CPoint → CCircle，计数 2
    }                                   // 析构 c2：CCircle → CPoint，计数 1
    cout << "当前圆对象数：" << CCircle::GetCount() << endl;   // 输出 1
    return 0;                           // 析构 c1：CCircle → CPoint，计数 0
}
```

**输出与解读**：

```text
--- 进入 main ---
CPoint(1,1)                 ← c1 的成员 mCenter 先构造
CCircle(半径 2) 当前对象数：1 ← c1 自身后构造，静态计数加 1
CPoint(2,2)                 ← c2 的成员 mCenter 先构造
CCircle(半径 3) 当前对象数：2 ← c2 自身后构造，静态计数加 1
~CCircle 当前对象数：1       ← c2 自身先析构，静态计数减 1
~CPoint                     ← c2 的成员 mCenter 后析构
当前圆对象数：1
~CCircle 当前对象数：0       ← c1 自身先析构，静态计数减 1
~CPoint                     ← c1 的成员 mCenter 后析构
```

**解读要点**：

- 静态成员 `sCount` 在构造函数和析构函数中分别进行增减，实时反映了“当前存活的 `CCircle` 对象数量”。
- 每个 `CCircle` 对象的构造都伴随着其成员 `mCenter` 的构造，析构时也遵循“自身先、成员后”的顺序。
- 这个综合示例把**静态成员**（对象计数）、**成员对象**（复合类生命周期）、**局部作用域**（`c2` 的构造和析构）三个方面串联了起来，形成了一个完整的闭环。

## 七、常见错误与易错点汇总

> [!warning] 对象数组
> 1. 类没有无参构造，却声明 `T arr[n];`，导致编译错误。必须使用初始化列表。
> 2. 类没有无参构造，却使用 `new T[n]`，导致编译错误。
> 3. 对对象数组混用 `delete` 和 `delete[]`，导致未定义行为。
> 4. 构造顺序按下标递增，析构顺序按下标递减。
> 5. 使用 `new T[n]` 时，所有元素都只能使用无参构造，无法逐个传递不同参数。

> [!warning] 静态成员
> 6. 静态数据成员在类内声明后，**必须在类外定义并初始化**，否则链接错误。
> 7. 静态成员函数**没有 `this` 指针**，不能直接访问非静态成员。
> 8. 静态成员函数**不能**声明为 `const` 或 `volatile`。
> 9. `sizeof(对象)` 的结果**不包含**静态成员的大小。
> 10. 静态成员函数可以通过对象调用，但本质上与对象无关，推荐用类名调用。

> [!warning] const / volatile 对象
> 11. `const` 对象必须初始化，且只能调用 `const` 成员函数。
> 12. `volatile` 对象只能调用 `volatile` 成员函数。
> 13. 声明和定义中的限定符（`const`/`volatile`）必须严格一致。
> 14. 需要时使用 `mutable` 允许 `const` 函数修改特定成员。
> 15. `volatile` 不保证原子性，多线程同步应使用 `std::atomic`。

> [!warning] 成员对象
> 16. 如果成员对象没有无参构造，**必须**在初始化列表中构造。
> 17. 构造顺序由**声明顺序**决定，与初始化列表书写顺序无关。
> 18. 析构顺序与构造顺序相反：复合类自身先析构，成员对象后析构。
> 19. `const` 成员对象和引用成员对象必须在初始化列表中初始化。

## 九、总结与速查

> [!summary] 本讲核心速查
>
> **1. 对象数组**
> - 类无无参构造时，必须使用初始化列表逐元素给参。
> - 构造按下标递增，析构按下标递减。
> - `new T[n]` 要求类有无参构造；`delete[]` 必须配对使用。
>
> **2. 静态成员**
> - 静态数据成员：属于类、所有对象共享、类外定义、`sizeof` 不包含。
> - 静态成员函数：无 `this`、只能访问静态成员、不能声明为 `const`/`volatile`。
> - 用途：对象计数、共享资源、工具函数。
>
> **3. const / volatile 对象**
> - `const` 对象：必须初始化，只能调用 `const` 成员函数，`mutable` 成员例外。
> - `volatile` 对象：每次访问都从内存重新读取，只能调用 `volatile` 成员函数。
> - 通过限定 `this` 指针类型实现访问控制。
>
> **4. 成员对象**
> - 复合类：成员是另一个类的对象。
> - 构造：成员对象先构造（按声明顺序），复合类自身后构造。
> - 析构：复合类自身先析构，成员对象后析构（逆序）。
> - 初始化列表的书写顺序与声明顺序不一致时，以声明顺序为准。

> [!tip] 一句话记忆
> **数组逐个构造、静态全体共享、const 只读、volatile 重读、成员先生后死。**

> 5. `volatile` 对象为什么只能调用 `volatile` 成员函数？
> 6. 以下代码的构造/析构顺序如何？
>    ```cpp
>    class A { public: A() { cout << "A"; } ~A() { cout << "~A"; } };
>    class B { A m; public: B() { cout << "B"; } ~B() { cout << "~B"; } };
>    int main() { B b; return 0; }
>    ```
> 7. 成员对象的初始化列表顺序与声明顺序不一致时，实际按哪个顺序构造？为什么？
> 8. 为什么 `new CComplex[3]` 无法为每个元素传递不同的构造参数？如果需要不同参数，应该怎么做？

> [!example] 参考答案要点（简）
> 1. 类有全缺省参数构造时合法；否则必须用初始化列表逐元素给参。
> 2. 静态成员不属于对象，需单独分配存储；不定义则链接错误（`undefined reference`）。
> 3. 不能。`const` 修饰 `this`，静态函数无 `this`。
> 4. `SetValue` 非 `const` 成员函数，`const` 对象不能调用。
> 5. `volatile` 要求每次访问重读，普通函数可能被优化缓存。
> 6. 输出 `A B ~B ~A`：成员先构造（`A`）、自身后构造（`B`）；自身先析构（`~B`）、成员后析构（`~A`）。
> 7. 按**声明顺序**。标准规定以避免依赖未初始化成员。
> 8. `new[]` 只支持无参构造，无法逐个传递参数；应使用 `std::vector<CComplex>` 配合 `emplace_back` 逐个添加元素。
