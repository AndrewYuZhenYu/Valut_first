## 二、友元的引入（5.1）

### 2.1 封装的两面性

面向对象封装的核心是：**把数据（私有成员）藏起来，只通过公开成员函数访问**。这带来安全性，但也带来两个问题：

1. **访问效率**：外部若需要频繁读取成员，每次都要调用 `GetX()`、`GetY()`，函数调用有开销。
2. **表达能力**：有些操作天然是“跨类”或“跨对象”的，例如“计算两点距离”“两个集合互相转换”，这些操作不属于任何一个类，但又必须访问两边的私有数据。

> [!important] 友元的本质
> 友元是**类主动授予**的一种**访问特权**：在类定义体内用 `friend` 声明某个外部函数或类为“朋友”，允许它访问本类的**私有（private）和保护（protected）成员**。
>
> 关键点：
> - 友元是**单向的**：A 声明 B 为友元，B 能访问 A 的私有成员，但 A 不能访问 B 的私有成员（除非 B 也声明 A）。
> - 友元是**类主动授权**，不是“外部强行闯入”。
> - 友元**破坏了封装**，因此应谨慎使用，只授予真正必要的函数或类。

### 2.2 成员函数间接访问 vs 友元直接访问

以“两点距离”为例，对比两种实现：

```cpp
// 方式一：通过公有成员函数访问（无友元）
double DistanceZGS(const CPoint& zP1, const CPoint& zP2) {
    double dX = zP2.GetX() - zP1.GetX();   // 调用公有函数
    double dY = zP2.GetY() - zP1.GetY();
    return sqrt(dX * dX + dY * dY);
}
```

**解读**：`GetX()`、`GetY()` 是公有成员函数，每次读取都要函数调用。若 `CPoint` 有大量私有成员，就需要写大量 `GetXxx()` 函数，接口膨胀；若 `GetXxx()` 不是内联的，高频调用还有性能开销。

```cpp
// 方式二：友元直接访问
class CPoint {
    double mX, mY;
public:
    CPoint(double zX = 0, double zY = 0);
    double GetX() const;
    double GetY() const;
    friend double Distance(const CPoint&, const CPoint&);   // 声明友元
};

double Distance(const CPoint& zP1, const CPoint& zP2) {
    double dX = zP2.mX - zP1.mX;   // 直接访问私有成员
    double dY = zP2.mY - zP1.mY;
    return sqrt(dX * dX + dY * dY);
}
```

**解读**：`Distance` 被声明为友元后，可以直接访问 `zP2.mX`、`zP1.mX`，无需经过 `GetX()`。优点是**无函数调用开销、代码简洁**；代价是 `Distance` 与 `CPoint` 的**内部表示强耦合**——若 `CPoint` 将来把 `mX` 改名为 `mReal`，`Distance` 也必须改。这就是友元的“负面效应”。

> [!warning] 友元的引入原则
> - 只有**确实需要直接访问私有成员**、且**通过公有接口无法高效/简洁实现**时，才考虑友元。
> - 友元应尽量**少而集中**，不要随意扩大授权范围。
> - 优先考虑：能否通过公有成员函数实现？能否把操作设计为成员函数？只有都不行时，才用友元。

## 三、友元函数（5.2）

### 3.1 友元函数的声明、定义与使用规则

> [!important] 友元函数的声明语法
> 在类定义体内（`public`、`private`、`protected` 均可，位置不影响语义）：
> ```cpp
> friend <返回类型> <函数名>(<参数表>);          // 一般函数作友元
> friend <返回类型> <类名>::<函数名>(<参数表>);   // 另一个类的成员函数作友元
> ```
>
> **语法要领**：
> 1. `friend` 声明**不是成员函数**，它只是“授权声明”，函数本身定义在类外。
> 2. 友元函数**没有 `this` 指针**，因此必须通过**对象参数**访问成员（如 `zP.mX`）。
> 3. 若友元函数参数用到尚未定义的类，需要**超前声明**（先 `class CPoint;`，再使用 `CPoint&`）。
> 4. `friend` 声明的位置（`public`/`private`）**不影响**其权限——友元始终能访问全部私有/保护成员。
> 5. 友元函数**不是类的成员**，调用方式与普通函数相同（`Distance(p1, p2)`），不能用 `p1.Distance(p2)`。

> [!important] 友元的三大特性
> | 特性 | 含义 | 为什么这样设计 |
> | --- | --- | --- |
> | **不传递** | A 是 B 的友元，B 是 C 的友元，**不意味着** A 是 C 的友元。 | 授权是“点对点”的，每个类只对自己信任的对象授权。若传递，A 可能通过 B 间接获得 C 的访问权，超出 C 的授权意愿，破坏封装的可控性。 |
> | **不对称** | A 是 B 的友元，**不意味着** B 是 A 的友元。 | 授权是单向的，由被访问方主动授予。A 需要 B 的数据，B 不一定需要 A 的数据；若强制对称，会扩大不必要的授权。 |
> | **不继承** | 基类的友元**不会**自动成为派生类的友元。 | 派生类可能有新的私有成员，基类的友元未必可信；友元关系是类级别的，不会随继承扩散。（后续继承讲次展开） |

### 3.2 一般函数作友元：两点距离例程

**文件组织**：

```text
Point.h                声明 CPoint 类，声明友元 Distance
Point.cpp              实现 CPoint 成员函数 + 实现 Distance
DistanceFromPointToPoint.cpp   主程序
```

```cpp
// Point.h
#if !defined(CPOINT_H)         // ① 包含保护：防止重复包含
#define CPOINT_H

class CPoint {
    double mX, mY;             // ② 私有成员
public:
    CPoint(double zX = 0, double zY = 0);   // 构造
    double GetX() const;                    // 公有读取
    double GetY() const;
    friend double Distance(const CPoint&, const CPoint&);   // ③ 友元声明
};

#endif
```

**逐行解读**：

- ① `#if !defined(CPOINT_H) / #define / #endif` —— **包含保护**。防止同一 `.cpp` 中多次 `#include "Point.h"` 导致类重复定义。现代 C++ 也可用 `#pragma once`。
- ② `double mX, mY;` —— 私有成员，外部不可直接访问。
- ③ `friend double Distance(const CPoint&, const CPoint&);` —— 声明 `Distance` 为友元。**注意**：这里只是声明，`Distance` 不是 `CPoint` 的成员函数，它的定义在 `Point.cpp` 中。

```cpp
// Point.cpp
#include "Point.h"
#include <cmath>
using namespace std;

CPoint::CPoint(double zX, double zY) : mX(zX), mY(zY) {}   // 构造

double CPoint::GetX() const { return mX; }                  // 公有读取
double CPoint::GetY() const { return mY; }

// 友元函数定义：注意不加 CPoint::，不是成员函数
double Distance(const CPoint& zP1, const CPoint& zP2) {
    double dX = zP2.mX - zP1.mX;   // 直接访问私有成员
    double dY = zP2.mY - zP1.mY;
    return sqrt(dX * dX + dY * dY);
}
```

**逐行解读**：

- `CPoint::CPoint(...)` —— 构造函数定义，`类名::` 表明是成员函数。
- `double CPoint::GetX() const` —— 成员函数定义，`const` 表示不修改成员。
- `double Distance(...)` —— **友元函数定义，没有 `CPoint::` 前缀**。因为它不是成员函数，只是被授权访问 `CPoint` 私有成员的外部函数。
- `zP2.mX`、`zP1.mX` —— 直接访问私有成员，合法（因为 `Distance` 是友元）。

```cpp
// DistanceFromPointToPoint.cpp（主程序）
#include <iostream>
#include "Point.h"
using namespace std;

int main() {
    CPoint zP1(0, 0), zP2(3, 4);
    cout << "距离 = " << Distance(zP1, zP2) << endl;   // 输出 5
    return 0;
}
```

**逐行解读**：

- `Distance(zP1, zP2)` —— 普通函数调用方式，**不能用** `zP1.Distance(zP2)`。
- 输出 `5`，验证 `sqrt(3² + 4²) = 5`。

> [!note] 友元函数与成员函数的对比
> | 对比项 | 成员函数 | 友元函数 |
> | --- | --- | --- |
> | 是否属于类 | 是 | 否 |
> | 是否有 `this` | 有 | 无 |
> | 访问私有成员方式 | 直接（`mX`） | 通过对象参数（`zP.mX`） |
> | 调用方式 | `obj.func()` | `func(obj)` |
> | 定义是否加 `类名::` | 是 | 否 |
> | 能否被继承 | 是 | 否（不是成员） |

### 3.3 类成员函数作友元：跨类成员设置例程

**问题**：`COne` 的成员函数 `SetMemberOfCTwo` 需要修改 `CTwo` 的私有成员 `mY1`、`mY2`。如何授权？

**解法**：在 `CTwo` 中声明 `COne::SetMemberOfCTwo` 为友元。

```cpp
// One.h
#if !defined(CONE_H)
#define CONE_H

class CTwo;                    // ① 超前声明：CTwo 尚未定义

class COne {
    int mX1, mX2;
public:
    COne(int zX1, int zX2);
    int GetX1() const;
    int GetX2() const;
    void SetMemberOfCTwo(CTwo& zTwo) const;   // ② 成员函数声明，参数用到 CTwo&
};

#endif
```

**逐行解读**：

- ① `class CTwo;` —— **超前声明**（forward declaration）。因为 `COne` 的成员函数参数用到 `CTwo&`，此时 `CTwo` 还没定义，必须先告诉编译器“有这么一个类”。超前声明只声明类名，不涉及类的大小和成员，因此足以声明“引用/指针参数”。
- ② `void SetMemberOfCTwo(CTwo& zTwo) const;` —— 成员函数声明，参数是 `CTwo` 的引用。**引用不需要完整类型**，所以超前声明足够。

```cpp
// Two.h
#if !defined(CTWO_H)
#define CTWO_H

#include "One.h"               // ③ 需要 COne 的完整定义（因为下面用到 COne::）

class CTwo {
    int mY1, mY2;
public:
    CTwo(int zY1, int zY2);
    int GetY1() const;
    int GetY2() const;
    friend void COne::SetMemberOfCTwo(CTwo&) const;   // ④ 声明 COne 的成员函数为友元
};

#endif
```

**逐行解读**：

- ③ `#include "One.h"` —— `CTwo` 需要声明 `COne::SetMemberOfCTwo` 为友元，必须知道 `COne` 的完整定义（否则不知道 `SetMemberOfCTwo` 是什么、参数是什么）。因此要包含 `One.h`。
- ④ `friend void COne::SetMemberOfCTwo(CTwo&) const;` —— **类成员函数作友元**的语法：`friend <返回类型> <类名>::<函数名>(<参数表>)`。注意 `const` 也要写，且必须与 `COne` 中的声明一致，否则编译器认为是不同函数。

```cpp
// One.cpp
#include "One.h"
#include "Two.h"               // 需要 CTwo 的完整定义才能访问 mY1、mY2

COne::COne(int zX1, int zX2) : mX1(zX1), mX2(zX2) {}
int COne::GetX1() const { return mX1; }
int COne::GetX2() const { return mX2; }

void COne::SetMemberOfCTwo(CTwo& zTwo) const {
    zTwo.mY1 = mX1 + mX2;      // 直接访问 CTwo 私有成员（因为被授权为友元）
    zTwo.mY2 = mX1 - mX2;
}
```

**逐行解读**：

- `#include "Two.h"` —— `SetMemberOfCTwo` 要访问 `zTwo.mY1`、`zTwo.mY2`，必须知道 `CTwo` 的完整定义。
- `zTwo.mY1 = mX1 + mX2;` —— 直接访问 `CTwo` 的私有成员。**只有** `COne::SetMemberOfCTwo` 这个函数有此权限，`COne` 的其他成员函数没有。

```cpp
// Two.cpp
#include "Two.h"

CTwo::CTwo(int zY1, int zY2) : mY1(zY1), mY2(zY2) {}
int CTwo::GetY1() const { return mY1; }
int CTwo::GetY2() const { return mY2; }
```

```cpp
// FriendFunctionBetweenTwoClasses.cpp（主程序）
#include <iostream>
#include "One.h"
#include "Two.h"
using namespace std;

int main() {
    COne zOne(7, 1);
    CTwo zTwo(3, 8);
    cout << "zTwo.mY1 = " << zTwo.GetY1() << endl;   // 3
    cout << "zTwo.mY2 = " << zTwo.GetY2() << endl;   // 8
    zOne.SetMemberOfCTwo(zTwo);                       // 修改 zTwo
    cout << "zTwo.mY1 = " << zTwo.GetY1() << endl;   // 8（7+1）
    cout << "zTwo.mY2 = " << zTwo.GetY2() << endl;   // 6（7-1）
    return 0;
}
```

**逐行解读**：

- `zOne.SetMemberOfCTwo(zTwo);` —— 调用 `COne` 的成员函数，传入 `CTwo` 对象。
- 函数内直接修改 `zTwo.mY1`、`zTwo.mY2`，因为 `COne::SetMemberOfCTwo` 是 `CTwo` 的友元。
- 输出验证：`mY1 = 7+1 = 8`，`mY2 = 7-1 = 6`。

> [!warning] 类成员函数作友元的易错点
> 1. **必须超前声明或包含**：`CTwo` 声明 `COne::SetMemberOfCTwo` 为友元前，必须先知道 `COne` 的存在。若只需要类名，用 `class COne;` 超前声明；若需要成员函数签名，必须 `#include "One.h"`。
> 2. **包含顺序**：通常 `One.h` 中 `class CTwo;` 超前声明，`Two.h` 中 `#include "One.h"`。若反过来，容易形成循环包含。
> 3. **签名必须一致**：`friend void COne::SetMemberOfCTwo(CTwo&) const;` 中的 `const`、参数类型必须与 `COne` 中的声明完全一致，否则编译器认为是不同函数，友元授权无效。

### 3.4 集合转换例程：友元前后对比

**问题**：整数集合 `CIntSet` 与实数集合 `CRealSet` 需要互相转换。转换操作不属于任何一个类，但又需要访问两边的私有数组 `mElems` 和元素个数 `mCard`。

**无友元方案**：在各自类中提供 `SetToReal`、`SetToInt` 成员函数，通过公有接口逐个添加元素。

```cpp
// 无友元：通过公有 AddItem 逐个转换
void CIntSet::SetToReal(CRealSet& zSet) const {
    zSet.Empty();                          // 公有接口清空
    for (int i = 0; i < mCard; i++)
        zSet.AddItem(mElems[i]);           // 公有接口逐个添加
}

void CRealSet::SetToInt(CIntSet& zSet) const {
    zSet.Empty();
    for (int i = 0; i < mCard; i++)
        zSet.AddItem((int)mElems[i]);      // 公有接口逐个添加
}
```

**解读**：缺点是每次添加都调用 `AddItem`，有函数调用开销；且 `AddItem` 内部还要检查重复元素，可能重复扫描。接口虽然没膨胀，但**效率较低**。

**有友元方案**：声明全局函数 `SetToReal`、`SetToInt` 为两个类的友元，直接访问数组。

```cpp
// IntSet.h（节选）
class CRealSet;                // 超前声明

class CIntSet {
    int mElems[MAXCARD];
    int mCard;
public:
    // ...
    friend void SetToReal(const CIntSet& zISet, CRealSet& zRSet);
};
```

```cpp
// RealSet.h（节选）
class CIntSet;                 // 超前声明

class CRealSet {
    double mElems[MAXCARD];
    int mCard;
public:
    // ...
    friend void SetToInt(const CRealSet& zRSet, CIntSet& zISet);
};
```

```cpp
// 友元函数定义（示意）
void SetToReal(const CIntSet& zISet, CRealSet& zRSet) {
    zRSet.mCard = zISet.mCard;                     // 直接访问私有成员，一次赋值
    for (int i = 0; i < zISet.mCard; i++)
        zRSet.mElems[i] = zISet.mElems[i];         // 直接复制数组
}

void SetToInt(const CRealSet& zRSet, CIntSet& zISet) {
    zISet.mCard = zRSet.mCard;
    for (int i = 0; i < zRSet.mCard; i++)
        zISet.mElems[i] = (int)zRSet.mElems[i];    // 注意：可能产生重复元素，需额外检查
}
```

**解读**：

- `zRSet.mCard = zISet.mCard;` —— 直接访问两边私有成员，一次赋值完成，比逐个 `AddItem` 高效。
- `(int)zRSet.mElems[i]` —— 实数转整数，可能截断（如 `6.3` 变 `6`）。转换后可能出现重复元素（如 `6.3`、`6.5` 都变 `6`），需要额外去重——这是友元方案**仍需注意的业务逻辑问题**，友元只解决“访问权限”，不解决“算法正确性”。

## 四、友元类（5.3）

### 4.1 友元类的概念

> [!important] 友元类
> 若在类 A 中声明 `friend class B;`，则 **B 的所有成员函数**都可以访问 A 的私有/保护成员。
>
> 与友元函数的区别：
> - 友元函数：只授权**一个函数**。
> - 友元类：授权**整个类的所有成员函数**。授权范围更大，应更谨慎。

**语法**：

```cpp
class A {
    friend class B;    // B 是 A 的友元类
    // ...
};
```

### 4.2 整数栈例程

**问题**：用链表实现整数栈。`CStack` 需要访问 `CNode` 的私有成员 `mData`、`pPrev` 来完成入栈/出栈。最简单的办法是把 `CStack` 声明为 `CNode` 的友元类。

**文件组织**：

```text
Node.h / Node.cpp       结点类声明与实现
Stack.h / Stack.cpp     栈类声明与实现
StackRoutine.cpp        主程序
```

```cpp
// Node.h
#ifndef CNODE_H
#define CNODE_H

class CStack;              // ① 超前声明：CNode 中声明 CStack 为友元

class CNode {
    int mData;             // 数据
    CNode *pPrev;          // 前驱指针
public:
    CNode(int zData, CNode *pNode);
    friend class CStack;   // ② 声明 CStack 为友元类
};

#endif
```

**逐行解读**：

- ① `class CStack;` —— 超前声明。`CNode` 中要声明 `CStack` 为友元，必须先告诉编译器“有这么一个类”。
- ② `friend class CStack;` —— 声明 `CStack` 为友元类。此后 `CStack` 的**所有成员函数**都能访问 `CNode` 的 `mData`、`pPrev`。

```cpp
// Stack.h
#ifndef CSTACK_H
#define CSTACK_H

#include "Node.h"           // ③ 需要 CNode 的完整定义

class CStack {
    CNode *pTop;            // 栈顶指针
public:
    CStack();
    void Push(int zData);
    int Pop();
    ~CStack();
};

#endif
```

**逐行解读**：

- ③ `#include "Node.h"` —— `CStack` 有成员 `CNode *pTop`，声明指针只需超前声明；但 `Stack.cpp` 中要 `new CNode`、访问 `pNode->pPrev`，需要完整定义。因此 `Stack.h` 包含 `Node.h` 更安全。

```cpp
// Node.cpp
#include "Node.h"

CNode::CNode(int zData, CNode *pNode) : mData(zData), pPrev(pNode) {}
```

**逐行解读**：

- `mData(zData), pPrev(pNode)` —— 初始化列表，构造结点，`pPrev` 指向原栈顶。

```cpp
// Stack.cpp
#include "Stack.h"

CStack::CStack() : pTop(nullptr) {}    // 空栈

void CStack::Push(int zData) {
    CNode *pNode = new CNode(zData, pTop);   // 新结点指向前栈顶
    pTop = pNode;                             // 更新栈顶
}

int CStack::Pop() {
    if (pTop) {                               // 栈非空
        CNode *pNode = pTop;                  // 暂存栈顶
        pTop = pTop->pPrev;                   // 栈顶下移
        int zData = pNode->mData;             // 取数据（直接访问 CNode 私有成员）
        delete pNode;                         // 释放结点
        return zData;
    }
    return 0;                                 // 栈空返回 0
}

CStack::~CStack() {
    CNode *pNode = pTop;
    while (pTop) {                            // 逐个释放
        pTop = pTop->pPrev;
        delete pNode;
        pNode = pTop;
    }
}
```

**逐行解读与内存变化**：

- `new CNode(zData, pTop)` —— 创建新结点，`pPrev` 指向原栈顶。`CStack` 能调用 `CNode` 构造（公有），合法。
- `pTop->pPrev` —— **直接访问 `CNode` 的私有成员 `pPrev`**。因为 `CStack` 是 `CNode` 的友元类，所有成员函数都有此权限。
- **`Push` 的内存变化**：假设栈中已有 `[10]`，`pTop` 指向 `10` 结点。执行 `Push(23)`：
  1. `new CNode(23, pTop)` 创建新结点，`mData=23`，`pPrev` 指向 `10` 结点。
  2. `pTop = pNode`，栈顶指针指向 `23` 结点。
  3. 此时链表：`pTop → [23] → [10] → nullptr`。
- **`Pop` 的内存变化**：`pTop` 指向 `[23]` 结点。执行 `Pop()`：
  1. `pNode = pTop`（暂存 `[23]`）。
  2. `pTop = pTop->pPrev`（栈顶下移到 `[10]`）。
  3. `zData = pNode->mData`（取 `23`）。
  4. `delete pNode`（释放 `[23]`）。
  5. 返回 `23`。此时链表：`pTop → [10] → nullptr`。
- `~CStack()` —— 循环释放所有结点，防止内存泄漏。每次 `delete pNode` 后 `pNode = pTop` 准备释放下一个，直到 `pTop` 为 `nullptr`。

```cpp
// StackRoutine.cpp（主程序）
#include <iostream>
#include "Stack.h"
using namespace std;

int main() {
    CStack zS;
    int zData;
    for (int i = 0; i < 10; i++) {
        cout << "zData = ";
        cin >> zData;
        zS.Push(zData);                       // 入栈 10 个
    }
    for (int i = 0; i < 6; i++)
        cout << zS.Pop() << " ";              // 出栈 6 个
    cout << endl;
    return 0;
}
```

**逐行解读**：

- 入栈 10 个数据，出栈 6 个（后进先出），输出最后入栈的 6 个。
- `main` 结束时 `zS` 析构，释放剩余 4 个结点。

### 4.3 友元类的使用原则

> [!warning] 友元类使用原则
> - 友元类授权范围大（整个类），应**比友元函数更谨慎**。
> - 典型场景：两个类**紧密协作**、实现同一数据结构的两部分（如栈与结点、容器与迭代器）。
> - 不要为了“方便”随意声明友元类，否则封装形同虚设。
> - 若只需一个函数访问，优先用**友元函数**而非友元类。

## 五、C++ 面向对象程序组织规范（5.4）

### 5.1 程序构建流程

```text
编辑阶段 → 编译阶段 → 链接阶段 → 运行阶段
```

| 阶段 | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| **编辑** | 源代码（`.h`、`.cpp`） | 源文件 | 编写代码 |
| **编译** | 每个 `.cpp` 独立编译 | 目标文件（`.obj`/`.o`） | 预处理（展开 `#include`、`#define`）、编译、汇编 |
| **链接** | 多个目标文件 + 系统库 | 可执行文件（`.exe`） | 解析外部符号、合并代码段 |
| **运行** | 可执行文件 | 运行结果 | 加载到内存执行 |

**关键点**：

- **每个 `.cpp` 独立编译**：编译器一次只处理一个 `.cpp`，`#include` 把头文件内容**文本展开**到 `.cpp` 中。
- **链接阶段解析符号**：若某函数只声明未定义，编译通过但链接报错（`undefined reference`）。
- **头文件不参与编译**：头文件只是被 `#include` 展开到 `.cpp` 中，本身不生成目标文件。

### 5.2 文件组织规范

> [!important] 项目组织结构规范
> 1. **主程序单独存放**在一个 `.cpp` 中（如 `main.cpp`、`XXXRoutine.cpp`）。
> 2. **每个类的声明和实现分别存放**：
>    - 声明放 `.h` 头文件（如 `Point.h`）。
>    - 成员函数实现放同名 `.cpp` 源文件（如 `Point.cpp`）。
> 3. **函数声明、定义、使用三者原型必须一致**（返回类型、参数类型、`const` 限定）。
> 4. **内联函数、类模板、函数模板**的所有代码放同一头文件（因为需要在使用处可见才能展开/实例化）。
> 5. **头文件用包含保护**：`#ifndef/#define/#endif` 或 `#pragma once`。
> 6. **文件命名**：类名与文件名对应（`CPoint` → `Point.h`、`Point.cpp`），便于查找。

**示例**：复数类项目组织

```text
Complex.h              声明 CComplex 类
Complex.cpp            实现 CComplex 成员函数
ComplexRoutine.cpp     主程序
```

```cpp
// Complex.h
#ifndef COMPLEX_H
#define COMPLEX_H

class CComplex {
    double mR, mI;
public:
    CComplex(double zR = 0, double zI = 0);
    ~CComplex();
    void SetValue(double zR, double zI);
    void Show() const;
};

#endif
```

```cpp
// Complex.cpp
#include <iostream>
#include "Complex.h"
using namespace std;

CComplex::CComplex(double zR, double zI) : mR(zR), mI(zI) {}
CComplex::~CComplex() {}
void CComplex::SetValue(double zR, double zI) { mR = zR; mI = zI; }
void CComplex::Show() const { cout << mR << "+" << mI << "i" << endl; }
```

```cpp
// ComplexRoutine.cpp
#include "Complex.h"

int main() {
    CComplex zC(1, 2);
    zC.Show();
    return 0;
}
```

> [!note] 头文件的作用
> - **模块间接口规定**：头文件告诉使用者“这个类/函数长什么样”（声明），隐藏“怎么实现”（定义在 `.cpp`）。
> - **团队协作交流**：A 写 `Point.h` + `Point.cpp`，B 只需 `#include "Point.h"` 就能使用 `CPoint`，无需看实现。
> - **包含保护**：防止重复包含导致的重复定义。

### 5.3 预编译指令

**`#include`**：

```cpp
#include <iostream>    // 系统库头文件：尖括号，编译器到系统目录查找
#include "Point.h"     // 用户头文件：双引号，先查当前目录，再查系统目录
#include "d:\\课堂例程\\Complex.h"   // 绝对路径（不推荐，移植性差）
```

**`#define` 宏定义**：

```cpp
#define PI 3.1415926
#define Area(r) (PI * (r) * (r))   // 有参宏：参数和整体都加括号
```

**逐行解读**：

- `#define PI 3.1415926` —— 无参宏，预处理阶段把 `PI` 文本替换为 `3.1415926`。
- `#define Area(r) (PI * (r) * (r))` —— 有参宏。**参数和整体都要加括号**，否则 `Area(R - blue)` 会展开为 `PI * R - blue * R - blue`，结果错误。
- **宏的缺陷**：无类型检查、副作用（如 `Area(i++)` 自增两次）。C++ 推荐用 `const` 常量 + `inline` 函数替代宏。

**条件编译**：

```cpp
#define DEBUG_    // 定义调试开关

#include <iostream>
using namespace std;

int main() {
    double zR = 6;
#if defined(DEBUG_)
    cout << "Radius = " << zR << endl;   // 仅当 DEBUG_ 定义时编译
#endif
    cout << "Area = " << 3.14 * zR * zR << endl;
    return 0;
}
```

**逐行解读**：

- `#define DEBUG_` —— 定义调试宏。
- `#if defined(DEBUG_) ... #endif` —— 条件编译：若 `DEBUG_` 已定义，则编译 `cout << "Radius..."`；否则跳过。用于发布时关闭调试输出，不增加运行时开销。

### 5.4 类名在不同场景下的使用限制（类型完整性）

这是本讲容易被忽略但很重要的部分：**类名在不同上下文中，对“完整类型”的要求不同**。

> [!important] 类型完整性的两条规则
> 1. **只需“类名可见”**（超前声明足够）：引用、指针、函数原型中的参数类型、友元声明、返回类型声明。
> 2. **需要“类完整定义”**（必须 `#include` 头文件）：定义对象、访问成员、`sizeof`、继承基类、作为成员对象（非指针/引用）。

**为什么？** 因为编译器需要知道对象的大小、成员布局才能生成代码。超前声明只告诉编译器“有这么一个类型”，但不知道它多大、有哪些成员，因此不能定义对象。

**示例：类名在本类定义体中的应用**

```cpp
class CObject {
    int mID;
    // CObject zObject;          // ❌ 错误：类内不能包含自身的完整对象
    static CObject zStaticObject; // ✅ 静态成员：类外定义
    CObject *pObject;             // ✅ 指针：本类名在此已可见
    static CObject *pStaticObject;// ✅ 静态指针
public:
    CObject(int zID);
    ~CObject();
};

CObject CObject::zStaticObject = CObject(0);   // 类外定义静态对象
CObject* CObject::pStaticObject = nullptr;      // 类外定义静态指针
```

**逐行解读**：

- `// CObject zObject;` —— **错误**。若允许，`CObject` 包含 `CObject`，大小无限递归，编译器无法确定 `sizeof(CObject)`。这是“类内不能包含自身完整对象”的根本原因。
- `static CObject zStaticObject;` —— **合法**。静态成员不占对象内存，类外定义时 `CObject` 已完整，可以构造。
- `CObject *pObject;` —— **合法**。指针大小固定（与 `CObject` 大小无关），类内只需知道 `CObject` 这个名字。
- 类外定义 `CObject CObject::zStaticObject = CObject(0);` —— 静态成员必须在类外定义，此时 `CObject` 完整，可调用构造函数。

**类名应用场景速查**：

| 场景 | 需要的类名信息 | 示例 |
| --- | --- | --- |
| 函数原型中的参数类型（引用/指针） | **超前声明**即可 | `void f(CTwo&);` 只需 `class CTwo;` |
| 友元类声明 | **超前声明**即可 | `friend class CStack;` 只需 `class CStack;` |
| 定义变量或参数（非引用/指针） | **完整定义**（`#include` 头文件） | `CTwo zT;` 需 `#include "Two.h"` |
| 本类定义体中定义成员对象指针 | **本类名已可见**（无需超前声明自身） | `CNode *pPrev;` |
| 本类定义体中定义静态成员对象 | **类内声明，类外定义**（类外时类型完整） | `static CObject zStaticObject;` |
| 本类定义体中定义普通成员对象（自身） | **禁止**（无限递归） | `CObject zObject;` ❌ |

## 六、综合例程：友元 + 文件组织 + 条件编译

**目标**：实现一个简单的“学生成绩比较”功能，演示友元函数、文件组织、条件编译的综合使用。

```cpp
// Student.h
#ifndef CSTUDENT_H
#define CSTUDENT_H

class CStudent {
    int mScore;
    char mName[20];
public:
    CStudent(const char* name = "", int score = 0);
    int GetScore() const;
    const char* GetName() const;
    friend bool IsBetter(const CStudent& a, const CStudent& b);   // 友元函数
};

#endif
```

```cpp
// Student.cpp
#include <cstring>
#include "Student.h"

CStudent::CStudent(const char* name, int score) : mScore(score) {
    strncpy(mName, name, 19);
    mName[19] = '\0';
}

int CStudent::GetScore() const { return mScore; }
const char* CStudent::GetName() const { return mName; }

// 友元函数：直接比较私有成员
bool IsBetter(const CStudent& a, const CStudent& b) {
    return a.mScore > b.mScore;    // 直接访问私有 mScore
}
```

```cpp
// StudentRoutine.cpp（主程序）
#include <iostream>
#include "Student.h"
using namespace std;

int main() {
    CStudent s1("Tom", 85), s2("Jerry", 92);
#ifdef DEBUG_
    cout << "调试：s1=" << s1.GetName() << "(" << s1.GetScore() << ")" << endl;
    cout << "调试：s2=" << s2.GetName() << "(" << s2.GetScore() << ")" << endl;
#endif
    if (IsBetter(s1, s2))
        cout << s1.GetName() << " 成绩更高" << endl;
    else
        cout << s2.GetName() << " 成绩更高" << endl;
    return 0;
}
```

**逐行解读**：

- `friend bool IsBetter(...)` —— 在 `CStudent` 中声明友元函数。
- `a.mScore > b.mScore` —— 友元函数直接访问私有 `mScore`，无需 `GetScore()`。
- `#ifdef DEBUG_` —— 条件编译，调试时输出学生信息，发布时关闭。

## 七、常见错误与易错点汇总

> [!warning] 友元函数
> 1. **友元函数定义不加 `类名::`**：`double Distance(...)` 而非 `double CPoint::Distance(...)`。
> 2. **调用方式错误**：`Distance(p1, p2)`，不是 `p1.Distance(p2)`。
> 3. **`friend` 声明位置不影响权限**：写在 `private` 或 `public` 中效果相同。
> 4. **类成员函数作友元**：签名必须与类中声明完全一致（含 `const`），且需要超前声明或 `#include`。
> 5. **超前声明只用于引用/指针参数**：若要定义对象，必须 `#include` 完整头文件。

> [!warning] 友元类
> 6. **不传递**：A 友元 B，B 友元 C，A 不是 C 的友元。
> 7. **不对称**：A 友元 B，B 不自动友元 A。
> 8. **不继承**：基类友元不自动成为派生类友元。
> 9. **授权范围大**：友元类所有成员函数都有权限，应谨慎使用。

> [!warning] 程序组织
> 10. **头文件必须包含保护**：`#ifndef/#define/#endif`，防止重复包含。
> 11. **声明与定义一致**：返回类型、参数类型、`const` 必须完全匹配。
> 12. **内联函数、模板放头文件**：否则链接错误。
> 13. **`.cpp` 独立编译**：每个 `.cpp` 只包含自己需要的头文件，不重复定义全局变量。
> 14. **静态成员类外定义**：类内只声明，类外定义分配存储。
> 15. **类内不能包含自身完整对象**：否则大小无限递归，编译错误。

## 九、总结与速查

> [!summary] 本讲核心速查
>
> **1. 友元引入**
> - 封装带来安全，但也带来效率与表达问题。
> - 友元是类主动授予的访问特权，单向、不传递、不继承。
>
> **2. 友元函数**
> - 声明：`friend <返回类型> <函数名>(<参数表>);`
> - 定义：不加 `类名::`，调用同普通函数。
> - 无 `this`，通过对象参数访问成员。
> - 类成员函数作友元：`friend <返回类型> <类名>::<函数名>(<参数表>);`，签名需一致。
>
> **3. 友元类**
> - 声明：`friend class <类名>;`
> - 整个类的所有成员函数都有访问权限。
> - 典型场景：紧密协作的两个类（栈与结点）。
>
> **4. 程序组织规范**
> - 构建流程：编辑 → 编译 → 链接 → 运行。
> - 文件组织：主程序单独 `.cpp`，类声明 `.h` + 实现 `.cpp`。
> - 头文件包含保护：`#ifndef/#define/#endif`。
> - 预编译指令：`#include`、`#define`、条件编译。
> - 内联函数、模板放头文件。
>
> **5. 类名可见性（类型完整性）**
> - 超前声明够用：引用/指针参数、友元声明。
> - 需完整定义（`#include`）：定义对象、访问成员、`sizeof`、继承。
> - 类内不能包含自身完整对象（无限递归），但可含自身指针/静态自身。

> [!tip] 一句话记忆
> **友元是授权、单向不传递；声明加 friend、定义不加类名；头文件放声明、源文件放实现；包含保护防重复、模板内联放头文件；指针引用超前声明、定义对象必须完整。**

> 8. 为什么类内不能定义自身的普通成员对象，但可以定义自身指针和静态自身对象？
> 9. 以下代码有什么错误？
>    ```cpp
>    class A {
>        friend void f();
>    };
>    void A::f() { }   // 错误在哪？
>    ```

> [!example] 参考答案要点（简）
> 10. 成员函数属于类、有 `this`、定义加 `类名::`、调用 `obj.f()`；友元函数不属于类、无 `this`、定义不加 `类名::`、调用 `f(obj)`。
> 11. 友元不是成员，没有隐含的 `this`；通过对象参数（如 `zP.mX`）访问私有成员。
> 12. 不传递：A 友元 B、B 友元 C，A 不是 C 友元；不对称：A 友元 B，B 不自动友元 A；不继承：基类友元不自动成为派生类友元。设计原因：授权应点对点、单向、可控，避免权限扩散破坏封装。
> 13. 类成员函数作友元时，声明友元的类需要知道对方类的完整定义（至少成员函数签名），因此要 `#include`；若只需引用/指针参数，超前声明足够。
> 14. 防止同一 `.cpp` 多次 `#include` 导致类/函数重复定义；不加会编译错误（重定义）。
> 15. 静态成员不属于对象，需单独分配存储；类内定义会导致多个 `.cpp` 包含时重复定义（链接错误）。
> 16. 内联函数需在每个调用点可见函数体才能展开；放 `.cpp` 中其他文件看不到定义，无法内联，甚至链接错误。
> 17. 普通成员对象会嵌入父对象中，若包含自身则大小无限递归；指针大小固定，静态成员不占对象内存，类外定义时类型完整，故均可。
> 18. `f` 是友元函数，不是 `A` 的成员函数，定义时**不能加 `A::`**。应写 `void f() { }`。
