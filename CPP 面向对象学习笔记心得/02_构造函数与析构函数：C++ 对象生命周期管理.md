## 二、缺省参数函数

### 2.1 定义与作用

**缺省参数（默认参数）**：在函数声明中为形参指定默认值，调用时若未提供该实参，则使用默认值。

```cpp
class CComplex {
    double mR, mI;                                   // 实部 mR、虚部 mI，未初始化
public:
    void SetValue(double zR = 0, double zI = 0);     // 双参声明，两个都有缺省值 0
    void ShowValue();                                // 显示复数
};
```

**解读**：缺省值写在**声明**里（通常在头文件），函数定义（`.cpp`）中**不能再写** `= 0`，否则违反“缺省值只写一次”的规则。这一声明让一个函数支持三种调用形式：

```cpp
CComplex zC1, zC2, zC3;
zC1.SetValue(2, 2);        // 两个实参都给：zR=2, zI=2
zC2.SetValue(3.15);        // 只给一个：zR=3.15, zI 取缺省值 0
zC3.SetValue();            // 一个都不给：zR=0, zI=0（括号不能省）
```

编译器在**调用点**把缺省值“填进去”，生成与普通函数调用相同的代码。它**不是**函数重载，而是“一个函数 + 编译器自动补参”。

### 2.2 使用规则（易错点）

> [!warning] 缺省参数的硬性规则
> 1. **缺省值必须从右向左连续指定**。若某参数有缺省值，则其右侧所有参数都必须有缺省值。
>    - ✅ `void f(int a, int b = 0, int c = 0);`
>    - ❌ `void f(int a = 0, int b, int c = 0);`（`b` 没有缺省值，但其左侧 `a` 有，非法）
> 2. **缺省值只能在声明中给出一次**（通常在头文件），定义中不得重复给出。
> 3. 缺省值可以是**常量表达式、全局变量、函数调用**，但不能是局部变量。
> 4. 缺省参数与函数重载同时使用时，**必须避免歧义**。

> [!warning] 歧义示例（重点）
> ```cpp
> void f(int a);              // 版本一：单参
> void f(int a, int b = 0);   // 版本二：双参，b 有缺省值
> f(1);                       // 错误！两个函数都能匹配，编译器无法抉择
> ```
> `f(1)` 可匹配版本一（1 给 a），也可匹配版本二（1 给 a，b 取 0），两者都合法 → **二义性**，编译错误。解决方式：不要设计“调用形式重叠”的重载 + 缺省参数组合。

### 2.3 为什么构造函数特别需要缺省参数

若不用缺省参数，支持“无参 / 单参 / 双参”构造就要写三个重载：

```cpp
class CComplex {
    double mR, mI;
public:
    CComplex(double zR, double zI);   // 双参
    CComplex(double zR);              // 单参（函数体内需写 mI = 0）
    CComplex();                       // 无参（函数体内需写 mR = mI = 0）
};
```

而使用缺省参数，**一个声明覆盖三种调用形式**：

```cpp
class CComplex {
    double mR, mI;
public:
    CComplex(double zR = 0, double zI = 0);   // 一个声明，三种调用
};
```

**解读**：两者在**调用层面等效**，但缺省参数版本代码更简洁、维护成本更低——改初始化逻辑只需改一处，且不会出现“某个重载忘了初始化”的漏洞。

## 三、构造函数

### 3.1 引入动机：不初始化会怎样

```cpp
class CComplex {
    double mR, mI;                         // 成员未初始化
    void SetValue(double zR, double zI);   // 默认 private
    void ShowValue();                      // 默认 private
};

int main() {
    CComplex zC1;          // 缺省构造 CComplex(){}，成员为垃圾值
    zC1.ShowValue();       // 输出不可预测，未定义行为
    return 0;
}
```

**解读**：`CComplex zC1;` 调用编译器生成的**缺省构造函数**（空函数体），`mR`、`mI` 保持栈上残留的垃圾值。`ShowValue()` 读取这些值并打印，输出不可预测。

> [!warning] 为什么“更严重”
> - 若对象是**局部变量**：栈上残留值，通常表现为随机数，问题可见。
> - 若对象是**动态分配**（`new`）或在**多线程/长期运行**环境中：垃圾值可能恰好是合法数值，错误被掩盖，导致**逻辑错误、越界、崩溃难以复现**。
> - 若成员是**指针**，未初始化指针被误用 → **段错误或内存破坏**。
>
> 因此，**对象在创建时必须被初始化**——这就是构造函数的职责。

### 3.2 构造函数的定义与特征

> [!important] 构造函数的定义规范
> - 函数名**与类名相同**；
> - **没有返回类型**（连 `void` 都不写）；
> - 可以被重载（多个构造函数）；
> - 由编译器在**对象定义时自动调用**，不能显式调用（不能取地址、不能被继承）；
> - 通常声明为 `public`，否则对象无法在类外定义。

```cpp
class CComplex {
    double mR, mI;
public:
    CComplex(double zR = 0, double zI = 0);   // 声明，缺省值写在这里
    void SetValue(double zR, double zI);
    void ShowValue();
};

// 定义：注意参数后不再写 = 0
CComplex::CComplex(double zR, double zI) {
    mR = zR;    // 函数体内赋值（先有垃圾值，再覆盖）
    mI = zI;
}
```

**解读**：`类名::函数名` 表明这是 `CComplex` 的构造函数。函数体内赋值发生在成员“默认初始化之后”，属于“先垃圾值再覆盖”，更规范写法见 3.4 初始化列表。

### 3.3 构造函数与对象定义方式的对应

| 对象定义写法 | 调用的构造函数 | 说明 |
| --- | --- | --- |
| `CComplex zC1;` | `CComplex(0, 0)`（借助缺省参数） | 无参形式，两参数取默认值 |
| `CComplex zC2(2, 1);` | `CComplex(2, 1)` | 括号初始化，双参 |
| `CComplex zC3(3.15);` | `CComplex(3.15, 0)` | 单参形式，`zI` 取默认值 |
| `CComplex zC4 = 5;` | `CComplex(5, 0)` | 拷贝初始化，隐式转换 |

> [!note] 常见写法辨析（most vexing parse）
> ```cpp
> CComplex zC1;          // ✅ 定义对象，调用无参构造
> CComplex zC2();        // ❌ 这是函数声明！
> CComplex zC3(2, 1);    // ✅ 括号初始化，调用双参构造
> CComplex zC4 = {2, 1}; // C++11 列表初始化，效果类似双参构造
> ```
> `CComplex zC2();` 被 C++ 语法规则解析为“声明一个名为 `zC2`、返回 `CComplex`、无参数的函数”，**不是**定义对象。想定义对象，写 `CComplex zC2;` 或 `CComplex zC2{};`（C++11）。这个坑称为 **most vexing parse**，初学者务必避免。

### 3.4 构造函数体内赋值 vs 初始化列表

```cpp
// 方式一：函数体内赋值（先默认初始化，再覆盖）
CComplex::CComplex(double zR, double zI) {
    mR = zR;
    mI = zI;
}

// 方式二：初始化列表（推荐）
CComplex::CComplex(double zR, double zI) : mR(zR), mI(zI) {}
```

**解读**：方式一的执行顺序是——① 分配对象内存；② 成员默认初始化（`double` 值不确定）；③ 进入函数体执行赋值。**先垃圾值再覆盖**，多一次写入。方式二在 `:` 后直接用 `zR` 初始化 `mR`，**跳过“默认初始化 + 赋值”**，更高效；且构造顺序按**成员声明顺序**（`mR` 先、`mI` 后），与列表书写顺序无关。

> [!tip] 何时必须用初始化列表
> - 成员是 `const` 或引用类型（只能初始化，不能赋值）；
> - 成员是没有默认构造函数的类类型对象；
> - 成员是基类（派生类构造时）。
>
> 本讲阶段用函数体赋值可以接受，但应尽早建立“优先用初始化列表”的习惯。

> [!warning] 初始化列表顺序陷阱
> ```cpp
> class Bad {
>     int a;
>     int b;
> public:
>     Bad(int x) : b(x), a(b) {}   // ❌ 危险！
> };
> ```
> 实际顺序是 `a` 先构造、`b` 后构造（按声明序）。`a(b)` 执行时 `b` 还没初始化，`a` 拿到垃圾值。列表顺序与声明顺序不一致时，逻辑易错。

### 3.5 构造函数的调用顺序

当一个对象被创建时：① 分配对象内存（栈或堆）；② 按**成员声明顺序**依次构造成员；③ 执行构造函数体；④ 对象构造完成，可以使用。

> [!warning] 易错点
> 初始化列表的书写顺序**不影响**实际构造顺序，实际顺序永远按**成员在类中的声明顺序**。

## 四、析构函数

### 4.1 引入动机：对象消亡时的善后

对象销毁时，其占用的**成员数据空间**会被回收，但如果成员**持有外部资源**（堆内存、文件句柄、锁、网络连接等），这些资源不会自动释放，必须由析构函数完成“善后”。

> [!important] 构造与析构的对称性
> - 构造函数：对象诞生 → **申请资源、初始化状态**
> - 析构函数：对象消亡 → **释放资源、清理状态**
>
> 这种“构造申请、析构释放”的对称设计，是 C++ RAII（Resource Acquisition Is Initialization）思想的基石。

### 4.2 析构函数的定义与特征

> [!important] 析构函数的定义规范
> - 函数名为 `~类名`；
> - **没有返回类型、没有参数**；
> - **不能重载**，一个类**只能有一个**析构函数；
> - 由编译器在**对象生命周期结束时自动调用**；
> - 不能被继承、不能取地址；
> - 若类可能被继承，基类析构函数应声明为 `virtual`（后续讲继承时强调）。

```cpp
class CComplex {
    double mR, mI;
public:
    CComplex(double zR = 0, double zI = 0);
    ~CComplex();                              // 析构函数声明（无参、唯一）
    void SetValue(double zR, double zI);
    void ShowValue();
};

CComplex::~CComplex() {
    // 释放资源、打印调试信息等；复数类无动态资源，函数体通常为空
}
```

**解读**：`~CComplex()` 括号里永远为空（无参数）。析构函数**不负责回收对象本身的内存**（栈/堆内存由作用域或 `delete` 管理），只负责成员持有的外部资源。若成员是指针 `int* p = new int[10];`，析构中必须 `delete[] p;`，否则**内存泄漏**。

### 4.3 析构函数的调用时机

| 对象种类 | 析构时机 |
| --- | --- |
| 局部对象（栈） | 离开作用域时（函数返回、代码块结束） |
| 全局/静态对象 | 程序结束时 |
| `new` 创建的对象 | 显式 `delete` 时 |
| 临时对象 | 所在完整表达式结束时 |
| 对象数组成员 | 数组销毁时，**逆序**逐个析构 |

**解读**：栈对象最常见，离开 `}` 时析构；堆对象只有 `delete` 才析构，不 `delete` 则泄漏；临时对象如 `f(CComplex(1, 2))` 中的 `CComplex(1, 2)`，函数 `f` 返回后析构；数组 `CComplex arr[3];` 析构顺序 `arr[2] → arr[1] → arr[0]`。

### 4.4 析构顺序：与构造相反

> [!important] 析构顺序规则
> - 同一作用域内的多个局部对象：**后定义者先析构**（栈式 LIFO）。
> - 单个对象内部：成员析构顺序与构造顺序**相反**（先构造的后析构）。
> - 派生类对象：先执行派生类析构，再执行基类析构（后续讲继承时展开）。

```cpp
void main() {
    CComplex zC1, zC2, zC3;   // 构造顺序：zC1 → zC2 → zC3
    zC1.ShowValue();
    zC2.ShowValue();
    zC3.ShowValue();
    zC1.SetValue(2, 2);
    zC2.SetValue(3.15, 0);
    zC3.SetValue(0, 0);
    zC1.ShowValue();
    zC2.ShowValue();
    zC3.ShowValue();
}                             // 析构顺序：zC3 → zC2 → zC1
```

**解读**：若构造/析构中打印调试信息，构造时打印 3 次（`zC1, zC2, zC3`），析构时打印 3 次（`zC3, zC2, zC1`）。**先构造的后析构**。

### 4.5 构造函数与析构函数要则

> [!summary] 构造/析构核心要则
> | 项目 | 构造函数 | 析构函数 |
> | --- | --- | --- |
> | 函数名 | 与类名相同 | `~类名` |
> | 返回类型 | 无 | 无 |
> | 参数 | 可有（可重载） | 必须无参 |
> | 数量 | 可多个 | **唯一** |
> | 调用时机 | 对象定义时自动 | 对象销毁时自动 |
> | 能否继承 | 否 | 否 |
> | 能否取地址 | 否 | 否 |
> | 缺省生成 | 未定义时系统生成无参空构造 | 未定义时系统生成空析构 |
> | 主要职责 | 初始化成员、申请资源 | 释放资源、善后 |

## 五、内联函数与有参宏

### 5.1 为什么构造函数/析构函数常是内联的

构造函数、析构函数通常**短小且调用频繁**（每个对象定义/销毁都要调用）。若按普通函数调用，函数调用开销（压栈、跳转、返回）可能超过函数体本身。因此编译器倾向于将它们**内联展开**。

### 5.2 内联函数

> [!important] 内联函数（`inline`）
> - 在函数声明/定义前加 `inline`，建议编译器“把函数体直接展开到调用点”，避免函数调用开销。
> - `inline` 只是**建议**，编译器可拒绝（如函数体过大、含递归、含循环等）。
> - 类内**直接定义**的成员函数，编译器**默认视为内联**。
> - 内联函数的定义必须对每个调用它的编译单元可见，因此**通常放在头文件**中。

```cpp
// 头文件 CComplex.h
class CComplex {
    double mR, mI;
public:
    // 类内直接定义构造函数 → 隐式内联；: 后为初始化列表
    CComplex(double zR = 0, double zI = 0) : mR(zR), mI(zI) {}

    // 类内直接定义普通成员函数 → 隐式内联
    double GetReal() const { return mR; }   // const：不修改成员
};
```

**解读**：类内**直接定义**（有函数体）的成员函数自动带 `inline` 属性，无需显式写 `inline`。若把定义放 `.cpp`、声明放头文件，其他 `.cpp` 调用时看不到函数体，**无法内联**（甚至链接错误）。因此内联函数定义**必须放头文件**。

> [!warning] 内联的常见误区
> - `inline` 不是“一定展开”，只是建议；
> - 内联函数**不能**在多个 `.cpp` 中重复定义（否则链接冲突），因此定义放头文件、加 `inline`；
> - 虚函数、递归函数、含 `switch`/循环的复杂函数通常不会被内联。

### 5.3 有参宏与内联函数的对比

```cpp
// 有参宏（不推荐）
#define MAX(a, b) ((a) > (b) ? (a) : (b))
// 预处理阶段纯文本替换，无类型检查

// 内联函数（推荐）
inline int max(int a, int b) {
    return a > b ? a : b;   // 有类型检查，参数只求值一次
}
```

**解读**：宏在预处理阶段**原样文本替换**，没有类型检查，报错位置指向展开处，难以调试。内联函数有类型检查，参数只求值一次。

| 对比项 | 有参宏 | 内联函数 |
| --- | --- | --- |
| 处理阶段 | 预处理（文本替换） | 编译（语义分析后展开） |
| 类型检查 | 无 | 有 |
| 副作用 | `MAX(i++, j++)` 会自增两次 | 参数只求值一次 |
| 调试 | 难以调试 | 可调试 |
| 作用域 | 无 | 遵循 C++ 作用域规则 |
| 推荐度 | 不推荐（除特殊场景） | 推荐 |

> [!tip] 有参宏的经典陷阱
> ```cpp
> #define SQUARE(x) x * x
> int r = SQUARE(1 + 2);   // 展开为 1 + 2 * 1 + 2 = 5，不是 9
> ```
> 宏展开是**纯文本替换**，`SQUARE(1 + 2)` 变成 `1 + 2 * 1 + 2`，按优先级算得 5。即使修正为 `#define SQUARE(x) ((x) * (x))`，`SQUARE(i++)` 仍会展开为 `((i++) * (i++))`，`i` 自增两次，**未定义行为**。这正是内联函数取代宏的原因。

## 六、系统缺省函数生成机制

### 6.1 编译器会“偷偷”生成什么

> [!important] 缺省生成规则
> 当类中**未显式定义**某些特殊成员函数时，编译器会**自动生成**：
>
> | 特殊成员函数 | 生成条件 | 生成版本的行为 |
> | --- | --- | --- |
> | 缺省构造函数 | 未定义任何构造函数 | 无参、空函数体（成员不初始化） |
> | 缺省析构函数 | 未定义析构函数 | 空函数体 |
> | 缺省拷贝构造函数 | 未定义拷贝构造 | 逐成员拷贝（浅拷贝） |
> | 缺省拷贝赋值运算符 | 未定义拷贝赋值 | 逐成员赋值（浅拷贝） |
>
> **关键点**：一旦用户**自定义了任一构造函数**，编译器**不再生成**缺省构造函数。

```cpp
class CComplex {
    double mR, mI;
    // 未定义任何构造函数 → 编译器生成 CComplex() {} 与 ~CComplex() {}
};

int main() {
    CComplex zC1;    // 调用空构造；mR、mI 仍是垃圾值
    return 0;
}
```

**解读**：编译器生成的缺省构造 `CComplex() {}` **函数体为空**，“空”意味着**不初始化 `mR`、`mI`**。缺省构造函数只是“让对象能构造”，**不是“让成员初始化”**。

### 6.2 缺省生成带来的两个后果

**后果一：自定义构造函数后，无参构造消失**

```cpp
class CComplex {
    double mR, mI;
public:
    CComplex(double zR, double zI);   // 自定义双参构造
    // 编译器不再生成 CComplex() {}
};

int main() {
    // CComplex zC1;        // ❌ 错误：没有可用的无参构造
    CComplex zC2(1, 2);     // ✅ 调用双参构造
    return 0;
}
```

**解读**：用户写了 `CComplex(double, double)` 后，编译器**不再生成** `CComplex()`。`CComplex zC1;` 找不到无参构造 → 编译错误。**补救**：加全缺省参数 `CComplex(double zR = 0, double zI = 0);`，或显式补写 `CComplex();`。

**后果二：缺省构造函数不初始化内置类型成员**

```cpp
class CComplex {
    double mR, mI;
    // 未定义构造 → 生成 CComplex() {}
};

int main() {
    CComplex zC1;   // mR, mI 仍是垃圾值
    return 0;
}
```

> [!warning] 结论
> **不要依赖“系统缺省构造函数会初始化成员”**。缺省构造函数只是“存在”，不是“初始化”。需要初始化就必须**自己写构造函数**，或使用成员初始化列表/类内初始值（C++11）：

```cpp
class CComplex {
    double mR = 0;   // C++11 类内初始值
    double mI = 0;
    // 编译器生成的缺省构造会使用这些初始值
};
```

**解读**：类内初始值让缺省构造**真正初始化**成员，是 C++11 后避免“垃圾值”的简便手段。若自定义构造未在初始化列表中覆盖该成员，则仍用类内初始值。

### 6.3 缺省生成与“空类”

```cpp
class Empty {};              // 空类
int main() {
    Empty e;
    // sizeof(Empty) 通常为 1，不是 0
    return 0;
}
```

**解读**：空类编译后并非真的“空”——编译器生成缺省构造、缺省析构、缺省拷贝构造、缺省拷贝赋值（C++11 后还有移动构造、移动赋值）。`sizeof(Empty)` 通常为 **1**，保证每个对象有唯一地址（`&e1 != &e2`）；若为 0，两个对象地址无法区分。

## 七、类与对象存储机制

### 7.1 成员函数：同类对象共享

> [!important] 核心结论
> - **成员函数代码只有一份**，存放在**类的公用存储区**（代码段），被该类的**所有对象共享**。
> - 成员函数通过隐式的 `this` 指针区分“当前是哪个对象在调用”。
> - 因此 `sizeof(对象)` **不包含成员函数的空间**。

### 7.2 成员数据：每个对象独立

> [!important] 核心结论
> - **每个对象的成员数据各自独立**，存放在**对象存储区**（栈/堆/静态区，取决于对象定义方式）。
> - `sizeof(对象)` = 所有非静态成员数据的大小之和（考虑内存对齐，可能大于简单相加）。

```text
内存
├── 类存储区（代码段，所有对象共享）
│   ├── CComplex 类名信息
│   ├── CComplex(double, double)   构造函数
│   ├── ~CComplex()                析构函数
│   ├── SetValue(double, double)   成员函数
│   └── ShowValue()                成员函数
└── 对象存储区
    ├── zC1: [mR=5] [mI=4]
    └── zC2: [mR=6] [mI=1]
```

### 7.3 用示例验证

```cpp
CComplex zC1, zC2;      // 两个对象，各有独立的 mR、mI
zC1.SetValue(5, 4);     // this = &zC1，修改 zC1 成员
zC2.SetValue(6, 1);     // this = &zC2，修改 zC2 成员
```

**解读**：两次调用 `SetValue` 执行的是**同一份**函数代码，但进入函数时隐式 `this` 分别指向 `zC1`、`zC2`，因此修改的是各自对象的成员。`zC1.mR` 与 `zC2.mR` 是**两块不同内存**，互不影响。

### 7.4 静态成员（简要补充）

```cpp
class CComplex {
    double mR, mI;                  // 非静态：每个对象独立
    static int sCount;              // 静态：所有对象共享一份
public:
    CComplex(double zR = 0, double zI = 0) : mR(zR), mI(zI) {
        ++sCount;                   // 每构造一个对象，共享计数 +1
    }
};

int CComplex::sCount = 0;           // 静态成员必须在类外定义并初始化
```

**解读**：`static int sCount;` 属于类而非对象，**所有对象共享一份**。构造函数中 `++sCount` 无论构造哪个对象，操作的都是同一份。静态成员**必须在类外定义**（分配存储并初始化），否则链接错误。配合析构函数 `--sCount`，可实现对象计数。

> [!note] 共享与独立的边界
> **非静态成员数据独立，成员函数与静态成员共享。** 这是理解对象内存布局的核心。

## 八、典型例程完整分析

### 8.1 复数类：从“无构造”到“有构造”

**版本一：无构造函数（问题版）**

```cpp
#include <iostream>
using namespace std;

class CComplex {
    double mR, mI;                                  // 私有成员：实部、虚部（未初始化）
public:
    void SetValue(double zR, double zI) {           // 类内定义 → 隐式内联
        mR = zR;                                    // 用形参覆盖实部
        mI = zI;                                    // 用形参覆盖虚部
    }
    void ShowValue() {                              // 类内定义
        cout << mR << " + " << mI << " i" << endl;  // 打印复数
    }
};

int main() {
    CComplex zC1, zC2, zC3;   // 缺省构造 CComplex(){}，成员为垃圾值
    zC1.SetValue(2, 2);       // 事后补救：设置 zC1
    zC2.SetValue(3.15, 0);    // 事后补救：设置 zC2
    zC3.SetValue(0, 0);       // 事后补救：设置 zC3
    zC1.ShowValue();          // 输出 2 + 2 i
    zC2.ShowValue();          // 输出 3.15 + 0 i
    zC3.ShowValue();          // 输出 0 + 0 i
    return 0;
}
```

**解读**：`CComplex zC1, zC2, zC3;` 调用编译器生成的空构造，成员是**栈上残留的垃圾值**。三行 `SetValue` 是**事后补救**——若用户忘记调用就 `ShowValue`，输出不可预测。构造函数应保证“创建即正确”，而不是依赖用户事后补救。

**版本二：有构造函数（推荐版）**

```cpp
// ========== CComplex.h ==========
#ifndef CCOMPLEX_H                              // 头文件保护：防止重复包含
#define CCOMPLEX_H

class CComplex {
    double mR, mI;                              // 私有成员：实部、虚部
public:
    // 全缺省参数：支持无参/单参/双参三种定义
    CComplex(double zR = 0, double zI = 0);
    ~CComplex();                                // 析构：无参、唯一
    void SetValue(double zR, double zI);        // 设置复数
    void ShowValue() const;                     // 显示复数（const：不修改成员）
};

#endif
```

```cpp
// ========== CComplex.cpp ==========
#include <iostream>
#include "CComplex.h"
using namespace std;

// 构造函数定义：: 后初始化列表；定义中不再写 = 0
CComplex::CComplex(double zR, double zI) : mR(zR), mI(zI) {
    cout << "构造复数 [" << mR << "," << mI << "]" << endl;   // 调试：观察构造时机
}

CComplex::~CComplex() {
    cout << "析构复数 [" << mR << "," << mI << "]" << endl;   // 调试：观察析构时机
}

void CComplex::SetValue(double zR, double zI) {
    mR = zR;        // 覆盖实部
    mI = zI;        // 覆盖虚部
}

void CComplex::ShowValue() const {
    cout << mR << " + " << mI << " i" << endl;   // 读取成员并打印
}
```

```cpp
// ========== main.cpp ==========
#include "CComplex.h"

int main() {
    CComplex zC1;             // 调用 CComplex(0,0)：构造 zC1
    CComplex zC2(3.15, 2.5);  // 调用 CComplex(3.15,2.5)：构造 zC2
    zC1.SetValue(2, 2);       // 修改 zC1：mR=2, mI=2
    zC1.ShowValue();          // 输出 "2 + 2 i"
    zC2.ShowValue();          // 输出 "3.15 + 2.5 i"
    return 0;
}                             // main 结束：析构 zC2 → 析构 zC1
```

**解读**：

- 头文件保护 `#ifndef/#define/#endif` 防止同一 `.cpp` 重复 `#include` 导致类重复定义。
- 构造函数**声明**中写缺省值 `= 0`，**定义**中不写——缺省值只写一次。
- `: mR(zR), mI(zI)` 是初始化列表，跳过“默认初始化 + 赋值”，直接初始化。
- `ShowValue() const` 中 `const` 表示不修改成员，可被 `const` 对象调用；定义处也要写 `const`，且必须与声明一致。
- `main` 中 `zC1` 用无参形式（两参数取默认 0），`zC2` 用双参形式。
- `return 0;` 后局部对象**逆序析构**：先 `zC2`（打印 `析构复数 [3.15,2.5]`），后 `zC1`（打印 `析构复数 [2,2]`）。

> [!example] 构造/析构顺序分析
> 1. `zC1` 定义 → 调用 `CComplex(0,0)` → 打印 `构造复数 [0,0]`
> 2. `zC2` 定义 → 调用 `CComplex(3.15,2.5)` → 打印 `构造复数 [3.15,2.5]`
> 3. `main` 结束 → `zC2` 先析构 → 打印 `析构复数 [3.15,2.5]`
> 4. `zC1` 后析构 → 打印 `析构复数 [2,2]`
>
> 顺序：**先构造的后析构**。

### 8.2 复数加法中的拷贝构造（预告）

```cpp
// CComplex.h（节选）
class CComplex {
    double mR, mI;
public:
    CComplex(double zR = 0, double zI = 0);
    ~CComplex();
    void SetValue();
    void SetValue(double zR, double zI);
    void ShowValue() const;
    CComplex Add(CComplex zC);                // 参数按值传递 → 拷贝
};
```

```cpp
// CComplex.cpp（节选）
CComplex CComplex::Add(CComplex zC) {         // 形参 zC 按值传递 → 拷贝构造
    CComplex zSum;                            // 局部对象 → 构造 (0,0)
    zSum.mR = mR + zC.mR;                     // 实部相加
    zSum.mI = mI + zC.mI;                     // 虚部相加
    return zSum;                              // 返回值 → 可能拷贝构造（RVO 可省）
}                                             // 函数结束：zSum 析构、zC 析构
```

```cpp
// main.cpp（节选）
int main() {
    CComplex zC1, zC2, zSum;                  // 构造 3 个对象 [0,0]
    zC1.SetValue(3.14, 7.8);                  // 设置 zC1
    zC2.SetValue(2.5, 12.6);                  // 设置 zC2
    zSum = zC1.Add(zC2);                      // 调用 Add：zC2 拷贝给形参 zC
    return 0;
}
```

**解读**：

- 形参 `CComplex zC` 是**按值传递**。调用 `zC1.Add(zC2)` 时，`zC2` 被**拷贝构造**出形参 `zC`，这一步调用**拷贝构造函数**（缺省为逐成员浅拷贝）。
- `CComplex zSum;` 构造局部对象，成员 `(0,0)`。
- `zSum.mR = mR + zC.mR;` 中 `mR` 是当前对象（`zC1`）的实部，`zC.mR` 是形参（`zC2` 拷贝）的实部。
- `return zSum;` 允许**返回值优化（RVO/NRVO）**：编译器可直接在调用者预留空间构造 `zSum`，省一次拷贝。未优化时调用拷贝构造生成返回值临时对象。
- 函数结束：局部 `zSum` 先析构（后定义），形参 `zC` 后析构（先定义）。
- `zSum = zC1.Add(zC2);` 返回的临时对象**拷贝赋值**给 `zSum`（若未重载 `operator=`，用缺省逐成员赋值），临时对象在完整表达式结束后析构。

> [!note] 为什么输出中会出现“多出来的”构造/析构
> 若观察到构造/析构次数多于“对象个数”，通常来自：**按值传参**（`zC` 拷贝一次）、**按值返回**（`zSum` 可能拷贝一次，RVO 可省）、**临时对象**（表达式结束后析构）。这正是下一讲“拷贝构造函数”要解决的问题。本讲只需建立“**拷贝也会构造、临时对象也会析构**”的意识。

## 九、常见错误与易错点汇总

> [!warning] 构造函数相关
> 1. `CComplex zC();` 不是定义对象，而是**声明函数**（most vexing parse）。
> 2. 自定义了任一构造函数后，**无参构造不再自动生成**；若仍需要，必须显式写出（或用全缺省参数）。
> 3. 构造函数**不能有返回类型**，写 `void CComplex()` 是错误。
> 4. 缺省参数**只能在声明中写一次**，定义中重复写会报错。
> 5. 初始化列表顺序应与成员声明顺序一致，否则易产生“用未初始化成员初始化另一成员”的隐蔽错误。

> [!warning] 析构函数相关
> 6. 析构函数**不能有参数**，不能重载，一个类只能有一个。
> 7. 析构函数**不释放对象本身的内存**（栈/堆内存由作用域或 `delete` 管理），只负责**成员资源善后**。
> 8. 若类持有堆资源而析构函数未释放 → **内存泄漏**。
> 9. 若类可能被继承，基类析构应 `virtual`，否则 `delete` 基类指针时**派生类析构不被调用**（后续展开）。

> [!warning] 缺省生成相关
> 10. 缺省构造函数**不会初始化内置类型成员**，不要误以为“有构造就安全”。
> 11. 缺省拷贝构造是**浅拷贝**，成员含指针时会导致**双重释放**（后续拷贝构造专题展开）。
> 12. 空类 `sizeof` 为 1，不是 0。

> [!warning] 存储机制相关
> 13. `sizeof(对象)` **不含成员函数**，只含非静态成员数据（+ 对齐填充）。
> 14. 成员函数共享，但通过 `this` 区分对象；静态成员属于类，非静态成员属于对象。
> 15. 不同对象的成员数据地址不同；同一成员函数地址对同类所有对象相同。

## 十一、总结与速查

> [!summary] 本讲核心速查
>
> **1. 缺省参数**
> - 从右向左连续指定；声明写一次；避免与重载产生歧义。
> - 构造函数用全缺省参数可替代多个重载。
>
> **2. 构造函数**
> - 名同类名、无返回类型、可重载、对象定义时自动调用。
> - 职责：初始化成员、申请资源。
> - 推荐初始化列表；成员构造顺序按声明顺序。
>
> **3. 析构函数**
> - `~类名`、无参、无返回、不可重载、唯一。
> - 职责：释放资源、善后；对象销毁时自动调用。
> - 析构顺序与构造相反（后定义先析构、后构造先析构）。
>
> **4. 内联与宏**
> - 类内定义成员函数隐式内联；`inline` 是建议。
> - 内联函数优于有参宏：类型安全、无副作用、可调试。
>
> **5. 缺省生成**
> - 未定义构造 → 生成无参空构造（**不初始化**内置成员）。
> - 自定义任一构造 → 不再生成缺省构造。
> - 未定义析构 → 生成空析构。
>
> **6. 存储机制**
> - 成员函数：类存储区，同类对象共享，靠 `this` 区分。
> - 成员数据：对象存储区，每个对象独立。
> - `sizeof(对象)` 不含成员函数。

> [!tip] 一句话记忆
> **构造管“生”（初始化、申请），析构管“死”（释放、善后）；生时自动调，死时自动调；生按声明序，死按反序；函数共享、数据独立。**

>    int main() { A x; f(); A y; return 0; } // main：x 构造 → f() → y 构造 → 逆序析构
>    ```

> 8. 输出顺序：`A()`（x）→ `A()`（a）→ `~A()`（a）→ `A()`（y）→ `~A()`（y）→ `~A()`（x）。构造 3 次，析构 3 次。

> 13. `i++`、`j++` 各被求值两次（比较一次、返回一次），产生副作用；内联函数参数只求值一次。
