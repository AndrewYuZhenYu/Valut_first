## 二、new 与 delete 操作

### 2.1 C 与 C++ 内存管理机制对比

| 项目 | C 语言 | C++ |
| --- | --- | --- |
| 申请单个对象 | `malloc(sizeof(T))` | `new T` |
| 申请并初始化 | 需手动赋值 | `new T(初值)` |
| 申请数组 | `malloc(n * sizeof(T))` | `new T[n]` |
| 释放单个对象 | `free(p)` | `delete p` |
| 释放数组 | `free(p)` | `delete[] p` |
| 是否调用构造/析构 | **否** | **是** |
| 返回类型 | `void*`（需强转） | `T*`（类型安全） |
| 失败行为 | 返回 `NULL` | 抛 `std::bad_alloc` 异常 |

> [!important] 核心区别
> `new` 在分配内存后**自动调用构造函数**；`delete` 在释放内存前**自动调用析构函数**。`malloc`/`free` 只负责"分配/释放裸内存"，**不调用构造/析构**。这是 C++ 对象动态管理能正确工作的根本原因。

### 2.2 整数指针示例：地址、内容与数组

```cpp
#include <iostream>
using namespace std;

#define ARRAYSIZE 3

int main() {
    int *pScore = new int[ARRAYSIZE];       // 分配 3 个 int，pScore 指向首元素
    int *pScoreImg = &pScore[1];            // 指向第二个元素（首地址 + sizeof(int)）

    cout << "&pScore = " << &pScore << endl;          // 指针变量自身在栈上的地址
    cout << "pScore  = " << pScore  << endl;          // 指针内容 = 堆上首元素地址
    cout << "&pScoreImg = " << &pScoreImg << endl;    // 第二个指针变量自身地址
    cout << "pScoreImg  = " << pScoreImg  << endl;    // = pScore + sizeof(int)

    for (int i = 0; i < ARRAYSIZE; i++)
        pScore[i] = i;                                // 元素赋值为 0, 1, 2

    for (int i = 0; i < ARRAYSIZE; i++) {
        cout << "pScore[" << i << "]  = " << pScore[i]  << endl;
        cout << "&pScore[" << i << "] = " << &pScore[i] << endl;   // 元素地址连续递增
    }

    for (int i = 0; i < ARRAYSIZE - 1; i++) {
        cout << "pScoreImg[" << i << "]  = " << pScoreImg[i]  << endl;  // 等价 pScore[1]、pScore[2]
        cout << "&pScoreImg[" << i << "] = " << &pScoreImg[i] << endl;
    }

    delete[] pScore;                         // 数组必须用 delete[]
    return 0;
}
```

**解读**：

- 代码刻意把 `pScore` 与 `pScoreImg` **拆成两条声明**，避免原资料"一行声明两个指针、后一个依赖前一个"的阅读负担。
- `&pScore` 与 `pScore` 是两种完全不同的量：前者是**指针变量本身**在栈上的地址（如 `006FF7EC`），后者是它**保存的内容**（堆上数组首地址 `00CA38C0`）。这是初学者最常见的混淆点。
- `pScoreImg = &pScore[1]` 后，`pScoreImg[0]` 等价 `pScore[1]`，`pScoreImg[1]` 等价 `pScore[2]`。所以循环上界是 `ARRAYSIZE - 1`，再往后就越界。
- 输出中 `&pScore[0]`、`&pScore[1]`、`&pScore[2]` 依次相差 `sizeof(int) = 4`，证明**数组元素连续存储**。
- `delete[] pScore;` —— 数组必须用 `delete[]`。

> [!warning] new[] 与 delete[] 必须配对
> - `new T` ↔ `delete p`（单个对象）
> - `new T[n]` ↔ `delete[] p`（数组）
>
> 混用是**未定义行为**。对内置类型（如 `int`）有时"碰巧不崩"，但对有构造/析构的类，会导致**部分析构**或**堆破坏**。

### 2.3 delete 之后：悬空指针与置空

```cpp
delete[] pScore;                                  // 释放数组内存
cout << "这里执行了 delete[] pScore!" << endl;

if (pScore == NULL)                               // ❌ 不成立：delete 不会置空
    cout << "pScore == NULL is true!" << endl;
else {
    cout << "&pScore = " << &pScore << endl;      // 变量自身地址（不变）
    cout << "pScore  = " << pScore  << endl;      // 内容地址（不变，但已失效）
}

for (int i = 0; i < ARRAYSIZE; i++) {
    cout << "pScore[" << i << "]  = " << pScore[i]  << endl;   // 读取已释放内存 → 垃圾值
    cout << "&pScore[" << i << "] = " << &pScore[i] << endl;   // 地址仍可打印
}
```

**解读**：

- `delete[]` 只把堆内存归还给系统，**`pScore` 这个指针变量本身仍在栈上**，内容不变——这就是**悬空指针（dangling pointer）**。
- `if (pScore == NULL)` **不成立**，说明 `delete` 不会自动置空。
- 再访问 `pScore[i]` 读到的是已被回收的内存，属**未定义行为**（示例输出 `-572662307` 之类垃圾值）。
- **正确习惯**：`delete[] pScore; pScore = nullptr;`（C++11 起用 `nullptr`）。

> [!warning] 悬空指针的两种典型误用
> 1. **重复 delete**：`delete p; delete p;` —— 第二次是未定义行为。
> 2. **访问已释放内存**：`delete p; cout << *p;` —— 垃圾值或崩溃。
>
> 解决：`delete` 后立即置空，使用前判空。

### 2.4 复数类指针示例：new/delete 自动调用构造/析构

```cpp
#include <iostream>
using namespace std;

class CComplex {
    double mR, mI;
public:
    CComplex();
    ~CComplex();
};

CComplex::CComplex()  { cout << "构造函数 CComplex() 被调用执行！" << endl; }
CComplex::~CComplex() { cout << "析构函数 ~CComplex() 被调用执行！" << endl; }

int main() {
    CComplex *pComplex = new CComplex[3];   // 分配 3 个对象，调用 3 次构造

    cout << "&pComplex    = " << &pComplex    << endl;   // 指针变量自身地址
    cout << "pComplex     = " << pComplex     << endl;   // 数组首元素地址
    cout << "&pComplex[0] = " << &pComplex[0] << endl;
    cout << "&pComplex[1] = " << &pComplex[1] << endl;
    cout << "&pComplex[2] = " << &pComplex[2] << endl;

    delete[] pComplex;                     // 逆序调用 3 次析构
    cout << "这里执行了 delete[] pComplex!" << endl;

    pComplex = nullptr;                    // 置空，防悬空
    if (pComplex == nullptr)
        cout << "pComplex == nullptr is true!" << endl;

    return 0;
}
```

**解读**：

- `new CComplex[3]` —— 分配 3 个对象的内存，**依次调用 3 次构造函数**（输出 3 行"构造函数被调用"）。
- `&pComplex[0]`、`&pComplex[1]`、`&pComplex[2]` 依次相差 `sizeof(CComplex)`（示例为 `0x10`，即 16 字节，两个 `double`），印证**对象数组连续存储**。
- `delete[] pComplex;` —— **逆序调用 3 次析构**（`[2] → [1] → [0]`），与构造顺序相反——这就是上一讲"析构顺序与构造相反"在对象数组上的体现。
- 置空后 `pComplex == nullptr` 为真；后续再 `delete[] pComplex;` 是安全的（`delete` 空指针无操作）。

> [!warning] 与 malloc/free 的对比
> 若把 `new CComplex[3]` 换成 `(CComplex*)malloc(sizeof(CComplex)*3)`，**不会**打印任何"构造函数被调用"；`free` **不会**调用析构。
> **结论**：C++ 动态管理**对象**必须用 `new`/`delete`，不能用 `malloc`/`free`。后者只管理裸内存，不管理对象生命周期。

## 三、指针型成员

### 3.1 有名复数类：成员指针的构造与析构

```cpp
// NamedComplex.h
class CComplex {
    double mR, mI;
    char *mpName;                              // 指针型成员：名字字符串
public:
    CComplex(double zR = 0, double zI = 0);
    ~CComplex();
    void Show();
    void SetValue(double zR, double zI);
};
```

```cpp
// NamedComplex.cpp
#include <iostream>
#include <cstdio>
#include "NamedComplex.h"
using namespace std;

CComplex::CComplex(double zR, double zI) {
    mpName = new char[25];                                 // ① 构造中申请堆内存
    mR = zR;
    mI = zI;
    sprintf(mpName, "C_%010lf+%010lf", mR, mI);            // ② 格式化名字
    cout << "<=" << endl;
    Show();
}

CComplex::~CComplex() {
    Show();                                                // ③ 析构前先显示
    cout << "=>" << endl;
    delete[] mpName;                                       // ④ 释放堆内存
    mpName = nullptr;                                      // ⑤ 置空，防悬空
}

void CComplex::Show() {
    cout << "[" << mpName << ": " << mR << "+" << mI << "i]" << endl;
}

void CComplex::SetValue(double zR, double zI) {
    mR = zR;
    mI = zI;                                               // 注意：未同步更新 mpName
}
```

**解读**：

- `mpName = new char[25];` —— **指针型成员必须在构造函数中申请资源**，否则 `mpName` 是垃圾指针，`sprintf` 写入非法地址直接崩溃。
- `sprintf(...)` —— 把格式化字符串写入 `mpName` 的 25 字节缓冲区。`%010lf` 是宽度 10、左补零的 `double`。
- `delete[] mpName;` —— **析构中释放资源**，与构造中的 `new[]` 配对。**这就是 RAII 的雏形**：构造申请、析构释放。
- `mpName = nullptr;` —— 释放后置空，防悬空。
- `SetValue` 只改 `mR`、`mI`，**没有更新 `mpName`**，所以 `Show` 显示的名字仍是构造时的"`C_000...`"，值却是新值——这暴露了"指针成员与值不同步"的设计缺陷。更合理做法是 `SetValue` 里重新 `sprintf`，或把 `mpName` 改为 `std::string`。此处保留原样，是为突出**指针型成员需要手动管理生命周期**。

```cpp
// main.cpp
#include "NamedComplex.h"

int main() {
    CComplex zC;                // 构造：mpName 申请、初始化
    zC.SetValue(2, 2);          // 修改实部虚部（mpName 未同步）
    zC.Show();                  // 名字仍为初始串，值为 2+2i
    return 0;
}                               // 析构：先 Show，再 delete[] mpName
```

### 3.2 指针型成员带来的拷贝问题（铺垫）

> [!warning] 缺省拷贝构造的浅拷贝灾难
> ```cpp
> class CStudent {
>     char *mpName;
>     int mScore;
> public:
>     // ... 构造/析构略
> };
>
> CStudent zS1;
> zS1.SetName("Tom");
> CStudent zS2(zS1);   // 缺省拷贝构造：逐成员拷贝
> ```
> 缺省拷贝构造生成的是 `mpName = zS.mpName;` —— **只拷贝指针值，不拷贝所指内容**。`zS2.mpName` 与 `zS1.mpName` 指向**同一块堆内存**。
> - **双重释放**：两个对象析构时同一块内存被 `delete[]` 两次 → 崩溃。
> - **数据共享**：改 `zS2` 的名字，`zS1` 也变——违背值语义。
>
> 解决办法：自定义**拷贝构造函数**做**深拷贝**。详见第六节。

## 四、对象指针与 this 指针

### 4.1 this 指针的本质

> [!important] this 是什么
> 每个**非静态成员函数**都有一个隐含形参 `this`，类型为 `类名* const`（指向当前对象的常量指针）。调用 `obj.f(args)` 时，编译器把 `&obj` 作为 `this` 传入。
>
> ```cpp
> // 源代码
> void CComplex::SetValue(double zR, double zI) {
>     mR = zR;
>     mI = zI;
> }
>
> // 编译器眼中的样子（示意）
> void CComplex::SetValue(CComplex* const this, double zR, double zI) {
>     this->mR = zR;
>     this->mI = zI;
> }
> ```

**解读**：`mR = zR;` 等价于 `this->mR = zR;`。成员函数之所以能"知道操作的是哪个对象"，全靠 `this`。`this` 由编译器**自动传入**，程序员通常不写，但可显式使用。

### 4.2 this 的典型用途

```cpp
class CComplex {
    double mR, mI;
public:
    // ① 区分同名成员与形参
    void SetValue(double mR, double mI) {
        this->mR = mR;      // 左侧 this->mR 是成员；右侧 mR 是形参
        this->mI = mI;
    }

    // ② 链式调用：返回 *this 的引用
    CComplex& SetReal(double zR) {
        this->mR = zR;
        return *this;       // 返回当前对象的引用，支持连续调用
    }

    // ③ 自赋值判断（拷贝赋值运算符中常用）
    CComplex& operator=(const CComplex& other) {
        if (this == &other) return *this;   // 自己给自己赋值，直接返回
        mR = other.mR;
        mI = other.mI;
        return *this;
    }
};
```

**解读**：

- **用途 ①**：形参名与成员名相同时，`this->mR` 明确指向成员，`mR` 指向形参。若写 `mR = mR;`，两边都被解释为形参，成员未变——经典错误。
- **用途 ②**：`return *this;` 返回当前对象的引用（不是拷贝），使 `zC.SetReal(3).SetReal(4);` 合法。
- **用途 ③**：`this == &other` 判断自赋值。成员若持有需释放的资源，自赋值会先释放自己的资源再读取已释放内容——必须先判断。

> [!note] this 是常量指针
> `this` 的类型是 `CComplex* const`，**`this` 本身不能被修改**（不能 `this = ...`），但 `*this`（当前对象）可以被修改。在 `const` 成员函数中，`this` 类型变为 `const CComplex* const`，因此不能修改成员——这正是 `const` 成员函数的实现机制。

## 五、对象引用

### 5.1 引用的概念与意义

> [!important] 引用是什么
> 引用是**变量的别名**，与被引用对象**对应同一块内存**。
> - 必须**初始化**，不能先声明后绑定；
> - **一旦绑定，不能重新绑定**到其他对象；
> - 操作引用就是操作原对象，**没有"空引用"**。

```cpp
int zX = 56;
int &rX = zX;      // rX 是 zX 的别名
int &rRX = rX;     // rRX 是 rX 的别名（即仍是 zX 的别名）

cout << "zX = " << zX << ", rX = " << rX << ", rRX = " << rRX << endl;
// 输出：zX = 56, rX = 56, rRX = 56

cout << "&zX = " << &zX << ", &rX = " << &rX << ", &rRX = " << &rRX << endl;
// 三个地址完全相同：0x0012FF7C

rRX = 25;          // 通过引用修改原对象
cout << "zX = " << zX << endl;   // 输出 25

cout << "&zX = " << &zX << ", &rX = " << &rX << ", &rRX = " << &rRX << endl;
// 地址仍完全相同
```

**解读**：`&zX`、`&rX`、`&rRX` 三个地址**完全相同**——引用不是独立变量，不占额外存储（实现上通常用指针，但语义上是别名）。修改 `rRX` 就是修改 `zX`。

> [!important] 引用 vs 指针
> | 项目 | 引用 | 指针 |
> | --- | --- | --- |
> | 是否必须初始化 | 是 | 否 |
> | 能否重新绑定 | 否 | 是 |
> | 是否可为空 | 否 | 是（`nullptr`） |
> | 是否占额外空间 | 语义上不占 | 占（指针大小） |
> | 访问方式 | 直接（`r`） | 解引用（`*p`） |
> | 安全性 | 较高 | 较低（可悬空、可空） |

### 5.2 引用用法要领

```cpp
CComplex zC1(12, 9), zC2(7, 9);
CComplex &zCA = zC1;        // zCA 是 zC1 的引用，必须初始化
CComplex *pC;               // pC 是指针，可不初始化

zCA.SetValue(5, 4);         // 通过引用修改 zC1
pC = &zC2;                  // pC 指向 zC2
pC->SetValue(12, 20);       // 通过指针修改 zC2

zCA = zC2;                  // ✅ 值赋值：把 zC2 的值赋给 zC1
// zCA = &zC2;              // ❌ 类型不匹配：引用是 CComplex，右侧是 CComplex*
// &zCA = &zC2;             // ❌ 非法：不能给引用重新绑定
```

**解读**：

- 把引用和指针**拆成两条声明**，避免"一行混写、后一个依赖前一个"的阅读障碍。
- `zCA = zC2;` —— **合法**。不是"让 `zCA` 改为引用 `zC2`"，而是"把 `zC2` 的值赋给 `zCA` 所引用的 `zC1`"。引用**不能重新绑定**。
- `zCA = &zC2;` —— **非法**。`zCA` 是 `CComplex` 类型，`&zC2` 是 `CComplex*`，类型不匹配。
- `&zCA = &zC2;` —— **非法**。`&zCA` 是地址值（右值），不能被赋值。引用**一旦绑定，终身不变**。

> [!warning] 引用的"终身绑定"
> 引用像"婚姻"：一旦绑定，不能改嫁。想"改变指向"用指针；想"别名"用引用。混用两者语义会出错。

## 六、引用作为函数参数与返回值

### 6.1 三种 Swap 实现对比

**方式一：传值**

```cpp
void Swap(CComplex zC1, CComplex zC2) {    // 形参是实参的拷贝
    CComplex zTemp;
    zTemp = zC2;
    zC2 = zC1;
    zC1 = zTemp;
}                                           // 函数结束，形参销毁，实参不变

int main() {
    CComplex zCA(7, 1), zCB(12, 9);
    Swap(zCA, zCB);
    zCA.Show(); zCB.Show();                 // 仍是 7+1i, 12+9i
    return 0;
}
```

**解读**：形参 `zC1`、`zC2` 是实参的**拷贝**。函数内交换的是拷贝，函数结束拷贝销毁，**实参完全没变**。经典例证："传值不能改变实参"。

**方式二：传指针**

```cpp
void Swap(CComplex *zC1, CComplex *zC2) {  // 形参是指针，指向实参
    CComplex zTemp;
    zTemp = *zC2;                           // 解引用：取所指对象的值
    *zC2 = *zC1;
    *zC1 = zTemp;
}

int main() {
    CComplex zCA(7, 1), zCB(12, 9);
    Swap(&zCA, &zCB);                       // 传地址
    zCA.Show(); zCB.Show();                 // 12+9i, 7+1i（已交换）
    return 0;
}
```

**解读**：`&zCA`、`&zCB` 是实参地址。形参保存地址。`*zC2 = *zC1;` 解引用后赋值，**修改的是实参对象本身**，交换成功。

**方式三：传引用**

```cpp
void Swap(CComplex &zC1, CComplex &zC2) {  // 形参是实参的别名
    CComplex zTemp;
    zTemp = zC2;
    zC2 = zC1;
    zC1 = zTemp;
}

int main() {
    CComplex zCA(7, 1), zCB(12, 9);
    Swap(zCA, zCB);                         // 语法上与传值相同
    zCA.Show(); zCB.Show();                 // 12+9i, 7+1i（已交换）
    return 0;
}
```

**解读**：形参 `zC1`、`zC2` 分别是 `zCA`、`zCB` 的**别名**，函数内 `zC2 = zC1;` 就是 `zCB = zCA;`。**语法上比指针简洁**（不用 `&`、`*`），效果与指针相同。C++ 推荐方式。

> [!tip] 三种方式选择
> - **传值**：小型对象、不需修改实参、需要独立副本时。
> - **传指针**：需表达"可能为空"、需指针算术、与 C 接口交互时。
> - **传引用**：大型对象（避免拷贝）、需修改实参、语法简洁时。**C++ 首选**。
> - **const 引用**：大型对象且不需修改时，`const CComplex&` 既避免拷贝又防止误改。

### 6.2 引用作为返回值

```cpp
#include <iostream>
using namespace std;

int array[] = {2, 4, 6, 8, 10, 12};

int& index(int i) {          // 返回 int 的引用
    return array[i];         // 返回全局数组元素的引用（函数结束后仍有效）
}

int main() {
    index(3) = 16;           // 函数调用作为左值被赋值：array[3] = 16
    cout << index(3) << endl;   // 输出 16
    return 0;
}
```

**解读**：

- `int& index(int i)` —— 返回类型是 `int&`（引用）。`return array[i];` 返回的是 `array[i]` 的**别名**，不是值的拷贝。
- `index(3) = 16;` —— 函数调用出现在赋值号**左边**。因为返回引用，`index(3)` 是左值，可赋值。若返回 `int`（值），`index(3) = 16;` **编译错误**（不能给右值赋值）。
- `array` 是**全局数组**，函数结束后仍存在，所以返回其元素引用安全。

> [!warning] 引用返回值的致命错误：返回局部变量
> ```cpp
> int& bad() {
>     int x = 10;      // 局部变量
>     return x;        // ❌ 返回局部变量的引用
> }                    // 函数结束，x 销毁，返回的引用悬空
>
> int main() {
>     int& r = bad();  // r 绑定到已销毁的 x
>     cout << r;       // 未定义行为：可能输出 10，也可能崩溃
>     return 0;
> }
> ```
> **规则**：引用返回值**必须**指向主调函数作用域内仍然有效的对象——全局变量、静态变量、传入的引用参数、堆对象等。**绝不能返回局部变量的引用**。
>
> 适用场合：需要对函数调用（即返回值）重新赋值的地方，如 `index(3) = 16;`、`operator[]`、`operator=` 返回 `*this` 等。

## 七、拷贝构造函数

### 7.1 什么是拷贝构造函数

> [!important] 定义
> 拷贝构造函数是**构造函数的一种重载形式**，用于"用一个已存在的同类型对象初始化新对象"。典型签名：
> ```cpp
> CComplex(const CComplex& other);   // 参数是 const 引用
> ```
> - 参数必须是**同类型对象的引用**（不能是值，否则递归调用拷贝构造）。
> - 通常加 `const`，表示不修改源对象。
> - 若未自定义，编译器生成**缺省拷贝构造函数**，行为是**逐成员拷贝（浅拷贝）**。

### 7.2 拷贝构造的触发时机

```cpp
CComplex zC1;
zC1.SetValue(8, 6);

CComplex zC2 = zC1;   // ① 拷贝初始化：调用拷贝构造
CComplex zC3(zC1);    // ② 括号初始化：调用拷贝构造

void f(CComplex zC);  // ③ 按值传参：实参 zC1 拷贝给形参 → 拷贝构造
f(zC1);

CComplex f();         // ④ 按值返回：返回值可能拷贝构造（RVO 可省）
CComplex zC5 = f();
```

**解读**：

- ① `CComplex zC2 = zC1;` —— `=` 在这里**不是赋值**，是**拷贝初始化**，调用拷贝构造。区分：`zC2 = zC1;`（已定义后）才是赋值，调用 `operator=`。
- ② `CComplex zC3(zC1);` —— 括号初始化，同样调用拷贝构造。
- ③ 按值传参 —— 形参由实参拷贝而来，调用拷贝构造。
- ④ 按值返回 —— 可能拷贝构造返回值临时对象；编译器**返回值优化（RVO/NRVO）** 可省略这一次拷贝。

### 7.3 缺省拷贝构造：浅拷贝及其问题

```cpp
class CStudent {
    char *mpName;    // 指针型成员
    int mScore;
public:
    // ... 构造、SetName、SetScore、Show 略
};

// 编译器生成的缺省拷贝构造（示意）：
CStudent::CStudent(const CStudent& zS) {
    mpName = zS.mpName;   // ❌ 只拷贝指针值（浅拷贝）
    mScore = zS.mScore;
}
```

**解读**：

- `mpName = zS.mpName;` —— **只复制指针值**，两个对象的 `mpName` 指向**同一块堆内存**。
- 后果一：**双重释放**。两个对象析构时都 `delete[] mpName;`，同一块内存释放两次 → 崩溃。
- 后果二：**数据共享**。修改 `zS2` 的名字，`zS1` 的名字也变，违背"每个对象独立"的语义。

```cpp
int main() {
    CStudent zS1;
    zS1.SetName("Tom");
    zS1.SetScore(60);

    CStudent zS2(zS1);   // 缺省拷贝构造：mpName 指向同一块内存
    zS2.Show();          // 显示 Tom（看似正常）

    return 0;
}                         // 析构：zS2 先 delete[]，zS1 再 delete[] 同一块 → 崩溃
```

**解读**：运行期可能"看起来正常"（`zS2.Show()` 显示 Tom），但**析构阶段**会因双重释放而崩溃。这是缺省浅拷贝最隐蔽的危害。

### 7.4 自定义深拷贝构造函数

```cpp
class CStudent {
    char *mpName;
    int mScore;
public:
    CStudent(const char* name = "", int score = 0) {
        mpName = new char[strlen(name) + 1];   // 申请足够空间
        strcpy(mpName, name);                  // 复制内容
        mScore = score;
    }

    // 自定义拷贝构造：深拷贝
    CStudent(const CStudent& zS) {
        mpName = new char[strlen(zS.mpName) + 1];   // ① 重新申请内存
        strcpy(mpName, zS.mpName);                  // ② 复制内容
        mScore = zS.mScore;                         // ③ 普通成员直接赋值
    }

    ~CStudent() {
        delete[] mpName;    // 释放本对象的内存
        mpName = nullptr;
    }
};
```

**解读**：

- ① `new char[strlen(zS.mpName) + 1];` —— **为副本单独申请内存**，大小与源对象相同（`+1` 是 `'\0'`）。
- ② `strcpy(...)` —— **复制内容**，不是复制指针。两个对象各有独立内存。
- ③ `mScore` 是 `int`，直接赋值即可。
- 析构时各自 `delete[]` 自己的内存，**无双重释放**。

> [!important] 三法则（Rule of Three）
> 若类需要自定义**析构函数**（因为持有资源），通常也需要自定义**拷贝构造函数**和**拷贝赋值运算符**。三者要么都不写（用缺省），要么都写（深拷贝）。只写析构不写拷贝构造 → 缺省浅拷贝 → 双重释放。本讲只讲拷贝构造，拷贝赋值运算符在后续展开。

### 7.5 复数加法例程：const 引用参数

```cpp
CComplex CComplex::Add(const CComplex& zC) const {
    CComplex zSum;                  // 局部对象
    zSum.mR = mR + zC.mR;           // this->mR + zC.mR
    zSum.mI = mI + zC.mI;
    return zSum;                    // 返回值（可能拷贝构造，RVO 可省）
}

int main() {
    CComplex zC1, zC2;
    zC1.SetValue(3.14, 7.8);
    zC2.SetValue(2.5, 12.6);
    CComplex zSum = zC1.Add(zC2);   // 拷贝初始化：调用拷贝构造（或 RVO 直构）
    zSum.ShowValue();               // 5.64 + 20.4 i
    return 0;
}
```

**解读**：

- `const CComplex& zC` —— **const 引用参数**。既避免拷贝（比传值高效），又保证函数内不修改 `zC`。这是 C++ 传递大型对象的**标准写法**。
- `const` 修饰成员函数 —— 表示 `Add` 不修改当前对象（`this` 是 `const CComplex* const`），因此 `Add` 可被 `const` 对象调用。
- `return zSum;` —— 返回局部对象。RVO/NRVO 可直接在调用者预留空间构造 `zSum`，省去一次拷贝；若未优化，则调用拷贝构造。
- `CComplex zSum = zC1.Add(zC2);` —— 拷贝初始化。若 `Add` 返回临时对象，`zSum` 由该临时对象拷贝构造（或 RVO 直接构造）。

## 八、常见错误与易错点汇总

> [!warning] new/delete 相关
> 1. `new[]` 必须配 `delete[]`，`new` 必须配 `delete`，混用是未定义行为。
> 2. `delete` 后指针不自动置空，必须手动 `p = nullptr;`。
> 3. 重复 `delete` 同一指针是未定义行为。
> 4. 动态管理**对象**必须用 `new`/`delete`，不能用 `malloc`/`free`（后者不调用构造/析构）。

> [!warning] 指针型成员相关
> 1. 指针型成员必须在构造函数中**申请**，在析构函数中**释放**，否则悬空或泄漏。
> 2. 缺省拷贝构造是**浅拷贝**，指针型成员会导致双重释放。必须自定义拷贝构造（深拷贝）。
> 3. 释放后置空，防悬空。

> [!warning] this 相关
> 4. `this` 是常量指针（`CComplex* const`），不能 `this = ...`。
> 5. 形参名与成员名相同时，必须用 `this->成员` 区分。
> 6. `const` 成员函数中 `this` 类型为 `const CComplex* const`，不能修改成员。

> [!warning] 引用相关
> 7. 引用**必须初始化**，**不能重新绑定**。
> 8. 不存在"空引用"，`int& r = NULL;` 是错误。
> 9. `zCA = zC2;` 是值赋值，不是重新绑定。
> 10. 引用返回值**绝不能返回局部变量**的引用。

> [!warning] 拷贝构造相关
> 11. 拷贝构造参数必须是**同类型引用**（通常 `const T&`），传值会导致递归。
> 12. `T a = b;` 是拷贝初始化，调用拷贝构造；`a = b;`（已定义后）是赋值，调用 `operator=`。
> 13. 指针型成员必须深拷贝，否则双重释放。
> 14. 三法则：析构、拷贝构造、拷贝赋值要么都自定义，要么都不写。

## 十、总结与速查

> [!summary] 本讲核心速查
>
> **1. new / delete**
> - `new T` ↔ `delete p`；`new T[n]` ↔ `delete[] p`；必须配对。
> - `new`/`delete` **调用构造/析构**；`malloc`/`free` **不调用**。
> - `delete` 后指针悬空，必须手动置空。
>
> **2. 指针型成员**
> - 构造中 `new` 申请，析构中 `delete` 释放，释放后置空。
> - 缺省拷贝构造是浅拷贝 → 双重释放 → 必须自定义深拷贝。
>
> **3. this 指针**
> - 非静态成员函数的隐含形参，类型 `T* const`（const 成员函数中为 `const T* const`）。
> - 用途：区分同名成员、链式调用（`return *this;`）、自赋值判断（`this == &other`）。
>
> **4. 引用**
> - 别名，必须初始化，不可重新绑定，无空引用。
> - 与指针对比：更安全、更简洁、语义更清晰。
>
> **5. 引用参数 / 返回值**
> - 引用传参：避免拷贝、可修改实参，C++ 首选。
> - `const T&`：大型对象且不修改时的标准写法。
> - 引用返回：返回左值，函数调用可被赋值；**禁止返回局部变量引用**。
>
> **6. 拷贝构造函数**
> - 签名 `T(const T& other)`；触发于拷贝初始化、按值传参、按值返回。
> - 缺省为浅拷贝；指针型成员必须深拷贝。
> - 三法则：析构、拷贝构造、拷贝赋值要么都写，要么都不写。

> [!tip] 一句话记忆
> **new/delete 管生灭，指针成员要深拷，this 区分你我他，引用是别名不搬家。**
