# 数据结构 第3章 栈和队列（修订定稿版）

> [!abstract] 本章定位
> 栈和队列是两种**操作受限的线性表**，它们的插入和删除只能在表的“端点”进行。本章围绕以下主线展开：
> 1. **概念与特性**：栈（LIFO）、队列（FIFO）的定义、抽象数据类型；
> 2. **存储与实现**：顺序栈、链栈、循环队列、链队列的 C 语言描述与基本操作；
> 3. **典型应用**：数制转换、括号匹配、行编辑、迷宫求解、表达式求值、递归实现与 N 皇后问题。
>
> 核心目标：掌握栈和队列的特点，熟练实现其基本操作，理解**循环队列**和**链队列**的基本运算，重点体会递归执行过程中栈状态的变化。

> [!important] 代码约定
> 4. 全部使用标准 `struct` 定义，**不使用 `typedef`**；
> 5. 数据类型默认 `int`；仅括号匹配、行编辑中的栈元素因处理字符而使用 `char`（合理例外）；
> 6. 函数返回值统一 `int`，`OK`（1）成功，`ERROR`（0）失败；
> 7. 所有 `realloc` 使用临时变量接收，防止失败时丢失原指针。

## 3.1 栈

### 3.1.1 栈的定义与特性

**栈（Stack）**是限定仅在**表尾**进行插入或删除操作的线性表。

- 允许插入和删除的一端（表尾）称为**栈顶（top）**；
- 另一端（表头）称为**栈底（bottom）**；
- 表中没有元素时称为**空栈**。

设栈 $S = (a_1, a_2, \dots, a_n)$：

```
       ↑ 进栈
       |
    [aₙ]  ← 栈顶
    [aₙ₋₁]
    [...]
    [a₂]
    [a₁]  ← 栈底
       |
       ↓ 退栈
```

- **进栈次序**：$a_1, a_2, \dots, a_{n-1}, a_n$
- **退栈次序**：$a_n, a_{n-1}, \dots, a_2, a_1$
- 栈按“**后进先出**”原则处理数据元素，简称 **LIFO 表**（Last In First Out）。

> [!important] 栈与线性表的关系
> 栈和队列都是**限定插入和删除只能在表的“端点”进行的线性表**：
>
> | 数据结构 | 插入位置 | 删除位置 |
> | --- | --- | --- |
> | 线性表 | `Insert(L, i, x)`，$1 \le i \le n+1$（任意位置） | `Delete(L, i)`，$1 \le i \le n$（任意位置） |
> | 栈 | `Insert(S, n+1, x)`（表尾，栈顶） | `Delete(S, n)`（表尾，栈顶） |
> | 队列 | `Insert(Q, n+1, x)`（表尾，队尾） | `Delete(Q, 1)`（表头，队头） |

### 3.1.2 栈的抽象数据类型

```
ADT Stack
{
    数据对象:
        D = { aᵢ | aᵢ ∈ ElemSet, i = 1, 2, ..., n, n ≥ 0 }
    数据关系:
        R1 = { <aᵢ₋₁, aᵢ> | aᵢ₋₁, aᵢ ∈ D, i = 2, ..., n }
        约定 aₙ 端为栈顶，a₁ 端为栈底
    基本操作:
        InitStack(&S)            构造一个空栈 S
        DestroyStack(&S)         销毁栈 S
        StackLength(S)           返回 S 的元素个数（栈长）
        StackEmpty(S)            若栈 S 为空返回 TRUE，否则 FALSE
        GetTop(S, &e)            用 e 返回 S 的栈顶元素
        ClearStack(&S)           将 S 清为空栈
        Push(&S, e)              插入 e 为新的栈顶元素
        Pop(&S, &e)              删除栈顶元素并用 e 返回其值
        StackTravers(S, visit()) 从栈底到栈顶依次对每个元素调用 visit()
} ADT Stack
```

**基本操作说明**：

| 操作 | 初始条件 | 操作结果 |
| --- | --- | --- |
| `InitStack(&S)` | 无 | 构造一个空栈 S |
| `DestroyStack(&S)` | 栈 S 已存在 | 栈 S 被销毁 |
| `StackLength(S)` | 栈 S 已存在 | 返回 S 的元素个数 |
| `StackEmpty(S)` | 栈 S 已存在 | 若 S 为空栈返回 TRUE，否则 FALSE |
| `GetTop(S, &e)` | 栈 S 已存在且非空 | 用 e 返回 S 的栈顶元素 |
| `ClearStack(&S)` | 栈 S 已存在 | 将 S 清为空栈 |
| `Push(&S, e)` | 栈 S 已存在 | 插入元素 e 为新的栈顶元素 |
| `Pop(&S, &e)` | 栈 S 已存在且非空 | 删除 S 的栈顶元素，用 e 返回其值 |
| `StackTravers(S, visit())` | 栈 S 已存在且非空 | 从栈底到栈顶对每个元素调用 visit()，一旦 visit() 失败则操作失败 |

> [!example] 例：进栈序列 1, 2, 3 的出栈序列
> 三个元素依次进栈（以 `S` 表示进栈、`X` 表示出栈），可能得到的出栈序列及操作序列：
>
> | 出栈序列 | 操作序列 |
> | --- | --- |
> | 1, 2, 3 | S X S X S X |
> | 1, 3, 2 | S X S S X X |
> | 2, 1, 3 | S S X X S X |
> | 2, 3, 1 | S S X S X X |
> | 3, 2, 1 | S S S X X X |
>
> > [!warning] 注意
> > 序列 **3, 1, 2** 是不可能得到的：若 3 先出栈，则 1、2 均已进栈，它们只能按 LIFO 顺序出栈为 2, 1。

### 3.1.3 栈的表示与实现

栈有两种存储方法：**顺序存储结构（顺序栈）** 和 **链式存储结构（链栈）**。

#### 方法一：顺序栈（`Top` 指向栈顶元素）

用一组**地址连续**的存储单元依次存放从栈底到栈顶的数据元素。**`Top` 指向栈顶元素本身**，空栈时 `Top = -1`。

```c
#define MAXSIZE 100   /* 栈中数据元素个数的最大可能值 */

struct SqStack {
    int Stack[MAXSIZE];   /* 存放栈元素的一维数组 */
    int Top;              /* 栈顶指针（下标），指向栈顶元素 */
};
```

**初始化**：

```c
int InitStack(struct SqStack &S)
/* 构造一个空栈 S */
{
    S.Top = -1;              /* -1 表示栈空 */
    return OK;
} /* InitStack */
```

**进栈**：

```c
int Push(struct SqStack &S, int x)
/* 在栈顶插入新元素 x */
{
    if (S.Top >= MAXSIZE - 1)
        return ERROR;        /* 栈满，上溢 */
    else
    {
        S.Top++;             /* 栈顶指针先上移一位 */
        S.Stack[S.Top] = x;  /* 再在栈顶位置写入新元素 */
        return OK;
    }
} /* Push */
```

**出栈**：

```c
int Pop(struct SqStack &S, int &e)
/* 删除栈顶元素并用 e 返回其值 */
{
    if (S.Top < 0)
        return ERROR;        /* 栈空，下溢 */
    else
    {
        e = S.Stack[S.Top];  /* 先取出栈顶元素的值 */
        S.Top--;             /* 栈顶指针再下移一位 */
        return OK;
    }
} /* Pop */
```

**取栈顶元素**：

```c
int GetTop(struct SqStack S, int &e)
/* 若栈非空，用 e 返回栈顶元素 */
{
    if (S.Top < 0)
        return ERROR;        /* 栈空 */
    else
    {
        e = S.Stack[S.Top];  /* 只取值，不改变 Top */
        return OK;
    }
} /* GetTop */
```

**判栈空**：

```c
int StackEmpty(struct SqStack S)
/* 若栈 S 为空返回 TRUE，否则 FALSE */
{
    if (S.Top < 0)
        return TRUE;
    else
        return FALSE;
} /* StackEmpty */
```

> [!note] 结构体指针写法
> 也可以将栈定义为指向结构体的指针 `struct SqStack *S;`，此时把 `S.Top` 写成 `S->Top`、`S.Stack[]` 写成 `S->Stack[]` 即可。

#### 方法二：顺序栈（`Top` 指向栈顶空位，动态扩容）

```c
#define STACK_INIT_SIZE 100   /* 初始分配量 */
#define STACKINCREMENT 10     /* 分配增量 */

struct SqStack {
    int *Base;      /* 栈底指针，初始指向数组起点 */
    int *Top;       /* 栈顶指针，指向栈顶元素的下一个位置 */
    int Stacksize;  /* 当前已分配的存储容量 */
};
```

> [!warning] 方法二的关键约定
> `Top` **始终指向栈顶元素的下一个位置**（即"栈顶空位"），因此：
> - **空栈**：`Top == Base`；
> - **栈满**：`Top - Base >= Stacksize`；
> - 取栈顶元素要用 `*(Top - 1)`；
> - 入栈：先 `*Top = e`，再 `Top++`；
> - 出栈：先 `Top--`，再取 `*Top`。

**初始化**：

```c
int InitStack(struct SqStack &S)
/* 构造一个空栈 S */
{
    S.Base = (int *)malloc(STACK_INIT_SIZE * sizeof(int));
    if (!S.Base)
        exit(OVERFLOW);           /* 存储分配失败 */
    S.Top = S.Base;               /* 空栈：栈顶指针 = 栈底指针 */
    S.Stacksize = STACK_INIT_SIZE;
    return OK;
} /* InitStack */
```

**取栈顶元素**：

```c
int GetTop(struct SqStack S, int &e)
/* 若栈非空，用 e 返回栈顶元素 */
{
    if (S.Top == S.Base)
        return ERROR;             /* 栈空 */
    e = *(S.Top - 1);             /* Top 指向下一个空位，故取 Top-1 */
    return OK;
} /* GetTop */
```

**入栈（含动态扩容）**：

```c
int Push(struct SqStack &S, int e)
/* 插入元素 e 为新的栈顶元素 */
{
    int *newbase;
    if (S.Top - S.Base >= S.Stacksize)
    {
        /* 栈满，追加存储空间 */
        newbase = (int *)realloc(S.Base,
                    (S.Stacksize + STACKINCREMENT) * sizeof(int));
        if (!newbase)
            exit(OVERFLOW);       /* 存储分配失败，原 S.Base 仍有效 */
        S.Base = newbase;         /* 成功后再更新 Base */
        S.Top = S.Base + S.Stacksize;   /* 重新定位 Top，保持原偏移 */
        S.Stacksize += STACKINCREMENT;
    }
    *S.Top++ = e;                 /* 先赋值，Top 再后加 1 */
    return OK;
} /* Push */
```

> [!tip] `realloc` 安全性解析
> - `realloc` 失败时返回 `NULL`，但**原指针仍然有效**。若直接写 `S.Base = (int *)realloc(S.Base, ...)`，失败时 `S.Base` 会变成 `NULL`，原内存无法再访问 → **内存泄漏**。
> - 正确做法：先用临时变量 `newbase` 接收返回值，判空后再赋给 `S.Base`。
> - 更新 `S.Top` 时，**原有偏移量 `S.Top - S.Base` 必须保持**，故用 `S.Base + S.Stacksize`（旧容量）。

**出栈**：

```c
int Pop(struct SqStack &S, int &e)
/* 删除 S 的栈顶元素，用 e 返回其值 */
{
    if (S.Top == S.Base)
        return ERROR;             /* 栈空 */
    e = *--S.Top;                 /* Top 先减 1，再取值 */
    return OK;
} /* Pop */
```

> [!important] 两种顺序栈约定对比
> | 约定 | 空栈条件 | 栈满条件 | 入栈 | 出栈 |
> | --- | --- | --- | --- | --- |
> | 方法一（`Top` 为下标，指向栈顶元素） | `Top == -1` | `Top == MAXSIZE-1` | `Top++; Stack[Top]=x` | `e = Stack[Top]; Top--` |
> | 方法二（`Top` 为指针，指向栈顶空位） | `Top == Base` | `Top - Base >= Stacksize` | `*Top++ = e` | `e = *--Top` |
>
> **易错点**：使用前必须**先明确当前栈用的是哪一种约定**，否则代码会出现越界或漏取一个元素。本笔记两节**不混用**。

#### 链栈

当最大需要容量事先不能估计时，采用链式存储结构是有效的方法。链栈的操作只能在**栈顶**进行。

```c
struct snode {
    int data;              /* 数据域 */
    struct snode *next;    /* 指针域 */
};
struct snode *LinkStack;   /* 链栈的栈顶指针（即链表头指针） */
```

```
top → [a₅] → [a₄] → [a₃] → [a₂] → [a₁] → NULL
      (栈顶)                          (栈底)
```

**进栈**：

```c
int Push(struct snode *&top, int x)
/* 将元素 x 压入链栈 top 中 */
{
    struct snode *t;
    t = (struct snode *)malloc(sizeof(struct snode));
    if (t == NULL)
        return ERROR;       /* 内存无可用空间，栈上溢 */
    else
    {
        t->data = x;        /* 给新结点赋值 */
        t->next = top;      /* 新结点指向原栈顶 */
        top = t;            /* top 更新为新结点 */
        return OK;
    }
} /* Push */
```

**出栈**：

```c
int Pop(struct snode *&top, int &e)
/* 删除链栈 top 的栈顶元素，用 e 返回其值 */
{
    struct snode *p;
    if (top == NULL)
        return ERROR;       /* 栈空，下溢 */
    else
    {
        p = top;            /* p 暂存被删结点 */
        top = top->next;    /* top 指向下一个结点 */
        e = p->data;        /* 取出被删结点数据 */
        free(p);            /* 释放被删结点 */
        return OK;
    }
} /* Pop */
```

> [!note] 链栈的优势
> - 对于链栈，**不会产生单个栈满而其余栈空的情形**，只有当系统空间全部用完、`malloc` 无法实现时才发生上溢；
> - 因此**多个链栈共享空间是自然的**；
> - 对栈这样元素多变的数据结构，链式存储结构更适宜。

## 3.2 栈的应用举例

> [!note] 应用总览
> 本节通过 7 个典型应用说明栈的作用：数制转换、括号匹配、行编辑、迷宫求解、表达式求值、递归实现、N 皇后求解。**共同思想**：当问题具有**后进先出**的特性时，栈是自然的求解工具。

### 3.2.1 例一：数制转换

算法基于原理：

$$N = (N \ \text{div} \ d) \times d + N \ \text{mod} \ d$$

**例**：$(1348)_{10} = (2504)_8$，计算过程：

| 计算顺序 | $N$ | $N \ \text{div} \ 8$ | $N \ \text{mod} \ 8$ |
| --- | --- | --- | --- |
| 1 | 1348 | 168 | 4 |
| 2 | 168 | 21 | 0 |
| 3 | 21 | 2 | 5 |
| 4 | 2 | 0 | 2 |

**输出顺序**：2 → 5 → 0 → 4（与计算顺序相反），因此需要**栈**暂存余数，再逆序输出。

```c
void conversion(void)
/* 将读入的十进制数 N 转换为 8 进制输出 */
{
    struct SqStack S;
    int N, e;
    InitStack(S);            /* 初始化空栈 */
    scanf("%d", &N);         /* 读入待转换的十进制数 */
    if (N == 0)              /* 特判 N = 0，否则无法输出任何字符 */
    {
        printf("0");
        return;
    }
    while (N)                /* N 不为 0 时循环 */
    {
        Push(S, N % 8);      /* 当前余数入栈 */
        N = N / 8;           /* N 除以 8，为下一轮准备 */
    }
    while (!StackEmpty(S))   /* 栈非空时逐个弹出 */
    {
        Pop(S, e);           /* 取出栈顶余数 */
        printf("%d", e);     /* 按逆序（即转换后的正确顺序）输出 */
    }
} /* conversion */
```

> [!tip] 代码解析
> - **为什么要用栈**：短除法得到的余数是“低位先得”，而输出要求“高位先出”，正好是**后进先出**的顺序；
> - `Push` / `Pop` 使用 3.1.3 方法一的顺序栈约定，`S.Top = -1` 表示空栈；
> - **`N = 0` 特判**：若 `N = 0`，`while (N)` 不进入，栈空，无输出，故需特判；
> - 时间复杂度 $O(\log_8 N)$，空间复杂度 $O(\log_8 N)$。

### 3.2.2 例二：括号匹配的检验（圆括号）

> [!note] 本节范围
> 本节仅讨论**圆括号** `()` 的匹配。方括号、花括号的扩展见 3.6 习题 3.19。

**问题**：假设表达式中只含 `(` 和 `)`，检验括号是否正确匹配。

- **正确格式**：`( [ ] ( ) )`、`( ( ) ( ) )`
- **错误格式**：`( [ ) ]`、`( ( ) ) )`、`( ( )`

**方法**：用“**期待的急迫程度**”来描述 —— 最近出现的左括号，应当是下一个右括号优先匹配的对象（**LIFO**）。

> [!example] 括号序列 `( ( ) ( ) )` 的检验
> 依次扫描：
> 1. `(` 入栈；
> 2. `(` 入栈；
> 3. `)` 与栈顶 `(` 匹配，出栈；
> 4. `(` 入栈；
> 5. `)` 与栈顶 `(` 匹配，出栈；
> 6. `)` 与栈顶 `(` 匹配，出栈。
>
> 最终栈空 → **匹配成功**。

**可能出现的不匹配情况**：

1. **到来的右括号并非所“期待”的**（如 `( ) )`）；
2. **到来的是“不速之客”**（如栈空时来了右括号）；
3. **直到结束也没有到来所“期待”的括号**（如 `( (` 结束时栈非空）。

**算法思想**：

1. 凡出现左括号 → **进栈**；
2. 凡出现右括号 → 先检查栈是否空：
   - 栈空 → 该右括号多余，不匹配；
   - 栈非空 → 与栈顶比较：匹配则左括号出栈，不匹配则失败；
3. 结束时：栈空则匹配正确，否则左括号有余。

```c
int matching(char exp[], int len)
/* 检验仅含圆括号的表达式 exp（长度 len）是否匹配 */
{
    struct SqStack S;              /* 注意：字符栈，使用 char 类型 */
    int i = 0, state = 1;          /* i 从 0 开始遍历整个 exp[] */
    char e;
    InitStack(S);
    while (i < len && state)
    {
        switch (exp[i])
        {
        case '(':
            Push(S, exp[i]);       /* 左括号进栈 */
            i++;
            break;
        case ')':
            /* 栈非空且栈顶为 '(' 才能匹配 */
            if (!StackEmpty(S) && GetTop(S, e) == '(')
            {
                Pop(S, e);         /* 匹配，弹出左括号 */
                i++;
            }
            else
                state = 0;         /* 不匹配 */
            break;
        default:
            state = 0;             /* 出现非法字符 */
            break;
        }
    }
    if (StackEmpty(S) && state)
        return OK;                 /* 匹配成功 */
    else
        return ERROR;
} /* matching */
```

> [!tip] 代码解析
> - **字符栈**：栈元素为 `char`，是合理例外（与“默认 `int`”约定兼容）；
> - **下标从 0 开始**：`i = 0`，遍历 `exp[0..len-1]`；
> - **`state` 变量**：一发现不匹配立即终止，避免无意义扫描；
> - **结束判断**：必须同时满足“栈空”和“未发生错误”；
> - 时间复杂度 $O(n)$，空间复杂度 $O(n)$。

### 3.2.3 例三：行编辑程序问题

**功能**：接收用户从终端输入的程序或数据，并存入用户数据区。

**为什么不能“每接收一个字符即存入存储器”**：用户输入时不能保证不出差错，若直接存入用户数据区，一旦发现错误就难以更正。

**合理做法**：设立**输入缓冲区**（栈），接收用户输入的一行字符，然后逐行存入用户数据区：

- `#` 为**退格符**（前一个字符无效）；
- `@` 为**退行符**（当前行全部无效）。

> [!example] 例：终端输入的两行字符
> ```
> whli##ilr#e ( s#*s)
> outcha@putchar(*s=#++);
> ```
> 实际有效的是：
> ```
> while (*s)
> putchar(*s++);
> ```

**处理规则**：

- 普通字符 → **压入栈顶**；
- `#` 退格符 → 从**栈顶删去一个字符**（`Pop`）；
- `@` 退行符 → 将**字符栈清为空栈**（`ClearStack`）。

```c
void LineEdit(void)
/* 简单的行编辑程序：接收用户输入并存入数据区 */
{
    struct SqStack S;          /* 字符栈，使用 char 类型 */
    char ch, e;
    int i;
    InitStack(S);              /* 构造空栈 */
    ch = getchar();            /* 从终端接收第一个字符 */
    while (ch != EOF)          /* EOF 为全文结束符 */
    {
        while (ch != EOF && ch != '\n')
        {
            switch (ch)
            {
            case '#':
                Pop(S, e);     /* 退格符：删除栈顶字符 */
                break;
            case '@':
                ClearStack(S); /* 退行符：清空当前行缓冲区 */
                break;
            default:
                Push(S, ch);   /* 普通字符：入栈 */
                break;
            }
            ch = getchar();    /* 接收下一个字符 */
        }
        /* 从栈底到栈顶顺序输出，即按输入顺序存入数据区
           方法一顺序栈：直接遍历数组 S.Stack[0..S.Top] */
        for (i = 0; i <= S.Top; i++)
            putchar(S.Stack[i]);
        ClearStack(S);         /* 重置 S 为空栈，准备接收下一行 */
        if (ch != EOF)
            ch = getchar();    /* 跳过换行符 */
    }
    DestroyStack(S);           /* 栈 S 被销毁 */
} /* LineEdit */
```

> [!tip] 代码解析
> - **为什么用栈**：支持**随时回退**，`#` 相当于一个 `Pop`，`@` 相当于清空；
> - **输出顺序修正**：顺序栈的数组 `S.Stack[0..S.Top]` 正是**从栈底到栈顶**的顺序，**直接遍历输出**即可，无需 `Pop`（原 PPT 的 `Pop` 循环会逆序输出）；
> - **字符栈**：`char` 类型是合理例外；
> - 时间复杂度 $O(n)$，空间复杂度 $O(n)$。

### 3.2.4 例四：迷宫求解

**问题**：给定迷宫（`#` 为墙、空格为通道、`$` 为已走过、`→` 等为方向），求从入口到出口的一条路径。

**方法**：**穷举求解**（深度优先搜索 DFS），从入口出发沿东、南、西、北顺时针方向试探。

> [!important] 求迷宫路径的基本思想
> - 若当前位置**可通**，则**纳入路径**，继续前进；
> - 若当前位置**不可通**，则**后退**，换方向继续探索；
> - 若四周**均无通路**，则将当前位置**从路径中删除**。

**算法框架（栈实现）**：

```
设定当前位置的初值为入口位置；
do {
    若当前位置可通，
    则 {
        将当前位置插入栈顶；         /* 纳入路径 */
        若该位置是出口位置，则算法结束；
        否则切换当前位置的东邻方块为新的当前位置；
    }
    否则 {
        若栈不空且栈顶位置尚有其他方向未被探索，
            则设定新的当前位置为沿顺时针方向找到的栈顶位置的下一相邻块；
        若栈不空但栈顶位置的四周均不可通，
        则 {
            删去栈顶位置；          /* 从路径中删去该通道块 */
            若栈不空，
                则重新测试新的栈顶位置，
                直至找到一个可通的相邻块或出栈至栈空；
            若栈空，则表明迷宫没有通路；
        }
    }
} while (栈不空);
```

> [!tip] 解析
> - **栈保存的是当前路径**，栈顶是当前位置；
> - **回溯**就是出栈：当四周无路可走时，弹出栈顶并回到上一个结点；
> - **`$` 标记**：已访问过的通道块不再重复进入，避免死循环；
> - **工程实现细节**：需定义**方向数组** `int dir[4][2] = {{0,1},{1,0},{0,-1},{-1,0}};`（东、南、西、北），并**对每次移动做边界检查**（`0 <= x < m && 0 <= y < n`），伪代码层面已说明算法思想，具体实现依赖方向数组；
> - 本题是**深度优先搜索（DFS）**的经典应用，时间复杂度 $O(m \times n)$（$m, n$ 为迷宫行、列数）。

### 3.2.5 例五：表达式求值

表达式求值是程序设计语言编译中的基本问题，经典解法是**算符优先法**。

> [!example] 例：对算术表达式 `4 + 2 * 3 - 10 / 5` 求值
> 算术四则运算规则：
> 1. 先括号内，后括号外；
> 2. 先乘除，后加减；
> 3. 同级运算从左算到右。

**基本概念**：

- **操作数（operand）**：常数、变量或常量标识符；
- **运算符（operator）**：算术、关系、逻辑运算符等；
- **界限符（delimiter）**：`(`、`)`、表达式结束符 `#` 等；
- 运算符和界限符统称为**算符**，构成集合 `op`。

任意两个相继出现的算符 $O_1$ 和 $O_2$ 之间的优先关系至多三种：

$$O_1 < O_2 \quad\text{（}O_1\text{ 的优先权低于 }O_2\text{）}$$
$$O_1 = O_2 \quad\text{（}O_1\text{ 的优先权等于 }O_2\text{）}$$
$$O_1 > O_2 \quad\text{（}O_1\text{ 的优先权高于 }O_2\text{）}$$

**算符优先关系表**（行表示栈顶算符 $O_1$，列表示当前算符 $O_2$）：

| $O_1 \backslash O_2$ | `+` | `-` | `*` | `/` | `(` | `)` | `#` |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `+` | `>` | `>` | `<` | `<` | `<` | `>` | `>` |
| `-` | `>` | `>` | `<` | `<` | `<` | `>` | `>` |
| `*` | `>` | `>` | `>` | `>` | `<` | `>` | `>` |
| `/` | `>` | `>` | `>` | `>` | `<` | `>` | `>` |
| `(` | `<` | `<` | `<` | `<` | `<` | `=` | 无 |
| `)` | `>` | `>` | `>` | `>` | 无 | `>` | `>` |
| `#` | `<` | `<` | `<` | `<` | `<` | 无 | `=` |

**两个工作栈**：

- **`OPTR`**：寄存运算符；
- **`OPND`**：寄存操作数或运算结果。

**算法基本思想**：

1. 置 `OPND` 为空栈，表达式起始符 `#` 为 `OPTR` 的栈底元素；
2. 依次读入表达式中的每个字符：
   - 若是**操作数**，则进 `OPND` 栈；
   - 若是**运算符**，则与 `OPTR` 栈顶运算符比较优先数后作相应操作；
3. 直至整个表达式求值完毕（`OPTR` 栈顶和当前读入字符均为 `#`）。

```c
/* 判断 c 是否属于算符集合 op（+ - * / ( ) #） */
int In(char c)
{
    return (c == '+' || c == '-' || c == '*' || c == '/'
            || c == '(' || c == ')' || c == '#');
}

/* 返回栈顶算符 c1 与当前算符 c2 的优先关系：
   '<'、'>'、'=' 三种，'?' 表示非法 */
char Precede(char c1, char c2)
{
    /* 按 7×7 优先级矩阵实现查表 */
    switch (c1)
    {
    case '+':
    case '-':
        if (c2 == '+' || c2 == '-' || c2 == ')' || c2 == '#') return '>';
        return '<';
    case '*':
    case '/':
        if (c2 == '(') return '<';
        return '>';
    case '(':
        if (c2 == ')') return '=';
        if (c2 == '#') return '?';   /* 非法 */
        return '<';
    case ')':
        if (c2 == '(') return '?';   /* 非法 */
        return '>';
    case '#':
        if (c2 == '#') return '=';
        if (c2 == ')') return '?';   /* 非法 */
        return '<';
    }
    return '?';
}

/* 对操作数 a、b 执行算符 op 的运算 */
int Operate(int a, char op, int b)
{
    switch (op)
    {
    case '+': return a + b;
    case '-': return a - b;
    case '*': return a * b;
    case '/': return a / b;   /* 假设 b != 0 */
    }
    return 0;
}

int EvaluateExpression(void)
/* 算符优先法求算术表达式值，以 '#' 结束 */
{
    struct SqStack OPTR, OPND;    /* 运算符栈、操作数栈 */
    int a, b, result;
    char theta, c;
    InitStack(OPTR);
    InitStack(OPND);
    Push(OPTR, '#');              /* 运算符栈底放 '#' */
    c = getchar();                /* 读入第一个字符 */
    while (c != '#' || GetTop(OPTR, theta) != '#')
    {
        if (!In(c))               /* c 不是算符，即操作数 */
        {
            int num = 0;
            while (!In(c) && c != EOF)   /* 连续读入多位数字 */
            {
                num = num * 10 + (c - '0');
                c = getchar();
            }
            Push(OPND, num);      /* 操作数入栈 */
        }
        else
        {
            GetTop(OPTR, theta);
            switch (Precede(theta, c))
            {
            case '<':             /* 栈顶运算符优先权低，c 进栈 */
                Push(OPTR, c);
                c = getchar();
                break;
            case '=':             /* 脱括号：弹出 '(' 并接收下一字符 */
                Pop(OPTR, theta);
                c = getchar();
                break;
            case '>':             /* 栈顶运算符优先权高，先运算 */
                Pop(OPTR, theta); /* 弹出运算符 */
                Pop(OPND, b);     /* 弹出右操作数 */
                Pop(OPND, a);     /* 弹出左操作数 */
                Push(OPND, Operate(a, theta, b));  /* 结果入栈 */
                break;            /* c 不变，继续与新的栈顶比较 */
            }
        }
    }
    GetTop(OPND, result);
    return result;
} /* EvaluateExpression */
```

> [!tip] 代码解析
> - **两条关键原则**：
>   - **栈顶优先权低**（`<`）→ 新算符入栈等待；
>   - **栈顶优先权高**（`>`）→ 先弹栈顶算符运算，结果入操作数栈；
> - **脱括号**（`=`）：左括号 `(` 和右括号 `)` 相遇，直接弹出 `(`，表示括号内运算已全部完成；
> - **`c` 不变的情况**：当算符优先级为 `>` 时，新算符 `c` 需**继续**与更新后的栈顶比较，所以**不能重新读入**；
> - **`Precede` 实现**：按 7×7 优先级矩阵分情况讨论，`'?'` 表示非法组合（如 `(` 与 `#`）；
> - 时间复杂度 $O(n)$（$n$ 为表达式长度），空间复杂度 $O(n)$。

#### 表达式的三种标识方法

设 $Exp = S_1 + OP + S_2$：

| 标识法 | 形式 | 例子（$Exp = a * b + (c - d/e) * f$） |
| --- | --- | --- |
| **前缀表示法**（波兰式） | $OP + S_1 + S_2$ | `+ * a b * - c / d e f` |
| **中缀表示法** | $S_1 + OP + S_2$ | `a * b + c - d / e * f` |
| **后缀表示法**（逆波兰式） | $S_1 + S_2 + OP$ | `a b * c d e / - f * +` |

**三种标识法的特点**：

1. **操作数之间的相对次序不变**；
2. **运算符的相对次序不同**；
3. 中缀式丢失了括号信息，致使运算的次序不确定；
4. **前缀式运算规则**：连续出现的两个操作数和在它们之前且紧靠它们的运算符构成一个最小表达式；
5. **后缀式运算规则**：每个运算符和在它之前出现且紧靠它的两个操作数构成一个最小表达式，**运算符在表达式中出现的顺序恰为表达式的运算顺序**。

> [!tip] 从后缀式求值
> 从左到右扫描后缀式：遇操作数入栈；遇运算符则弹出两个操作数（**先弹右操作数、后弹左操作数**）做运算，结果入栈。最终栈顶即为表达式的值。
>
> 例如 `a b * c d e / - f * +`：先找运算符，再找操作数，构造出运算树，最后栈顶为结果。

### 3.2.6 例六：实现递归

> [!important] 函数调用的栈式管理
> **调用前**需完成三项任务：
> 1. 将所有的实在参数、返回地址等信息传递给被调用函数保存；
> 2. 为被调用函数的局部变量分配存储区；
> 3. 将控制转移到被调用函数的入口。
>
> **返回前**需完成三项任务：
> 4. 保存被调函数的计算结果；
> 5. 释放被调函数的数据区；
> 6. 依照被调函数保存的返回地址将控制转移到调用函数。
>
> **嵌套调用规则**：**后调用先返回**！内存管理实行**“栈式管理”**。

```
主函数 main()
  └─ a()
       └─ b()
```
函数 b 的数据区 → 函数 a 的数据区 → main 的数据区（自栈顶向下）。

**系统用栈实现函数调用**：每当调用一个函数时，在栈顶分配一个存储区；每当从一个函数退出时，释放其存储区。因此**当前运行的函数的数据区必在栈顶**。

**递归函数的特点**：运行过程类似多个函数嵌套调用，只是调用函数与被调用函数是**同一个函数**。主函数是第 0 层，从主函数调用递归函数为进入第 1 层。每进入一层递归，产生一个新的**工作记录**（包括上一层的返回地址、实在参数、局部量）**压入栈顶**；每退出一层递归，从**栈顶弹出一个工作记录**。

> [!example] 例 3-2：$n$ 阶 Hanoi 问题
> **问题**：X、Y、Z 三个塔座，X 上插有 $n$ 个直径各不相同、依小到大编号 $1, 2, \dots, n$ 的圆盘。要求将 X 上 $n$ 个圆盘移至 Z，仍按同样顺序叠排。
>
> **移动规则**：
> 1. 每次只能移动一个圆盘；
> 2. 圆盘可插在 X、Y、Z 任一塔座上；
> 3. 任何时刻不能将较大圆盘压在较小圆盘之上。
>
> **递归思路**：
> - $n = 1$：直接从 X 移到 Z；
> - $n > 1$：
>   - 先用 Y 作辅助，将 X 上编号 1 至 $n-1$ 的圆盘移到 Y；
>   - 将编号为 $n$ 的圆盘从 X 移到 Z；
>   - 再将 Y 上的 $n-1$ 个圆盘移到 Z（以 X 作辅助）。

**`move` 函数**：

```c
void move(char from, int n, char to)
/* 将编号为 n 的圆盘从 from 塔座移到 to 塔座，并打印移动信息 */
{
    printf("%d: %c -> %c\n", n, from, to);
} /* move */
```

**`hanoi` 函数**：

```c
void hanoi(int n, char x, char y, char z)
/* 将塔座 x 上按直径由小到大且自上而下编号为 1 至 n 的
   n 个圆盘按规则搬到塔座 z 上，y 可用作辅助塔座 */
{
    if (n == 1)
    {
        move(x, 1, z);             /* 将编号为 1 的圆盘从 x 移到 z */
    }
    else
    {
        hanoi(n - 1, x, z, y);     /* 将 x 上编号 1 至 n-1 的圆盘移到 y */
        move(x, n, z);             /* 将编号为 n 的圆盘从 x 移到 z */
        hanoi(n - 1, y, x, z);     /* 将 y 上编号 1 至 n-1 的圆盘移到 z */
    }
} /* hanoi */
```

> [!tip] 代码解析
> - **递归三要素**：
>   - **出口**：`n == 1` 时直接移动；
>   - **分解**：将规模 $n$ 的问题分解为两个规模 $n-1$ 的子问题夹一个直接移动；
>   - **合并**：子问题的解通过**栈中的工作记录**自然组合成原问题的解；
> - **参数顺序**：`hanoi(n, from, aux, to)` —— $y$ 始终是“辅助塔”，在递归调用中会通过参数轮换角色；
> - **时间复杂度**：$T(n) = 2T(n-1) + 1$，$T(n) = 2^n - 1$，即 $O(2^n)$；
> - **空间复杂度**：递归栈深度为 $n$，$O(n)$。

#### Hanoi 的递归调用栈（结构性示意）

调用 `hanoi(3, a, b, c)` 时，**系统栈**中工作记录的变化（**示意结构，不代表具体返回地址编号**）：

```
初始：调用 hanoi(3, a, b, c)
  ┌─────────────────────────────┐
  │ hanoi(3,a,b,c)              │   ← 第 0 层工作记录
  │ 保存：返回地址、参数 n,x,y,z │
  └─────────────────────────────┘

调用 hanoi(2, a, c, b)（进入第 1 层）
  ┌─────────────────────────────┐
  │ hanoi(2,a,c,b)              │   ← 第 1 层
  │ 保存：返回地址、参数         │
  ├─────────────────────────────┤
  │ hanoi(3,a,b,c)              │
  └─────────────────────────────┘

调用 hanoi(1, a, b, c)（进入第 2 层）
  ┌─────────────────────────────┐
  │ hanoi(1,a,b,c)              │   ← 第 2 层
  ├─────────────────────────────┤
  │ hanoi(2,a,c,b)              │
  ├─────────────────────────────┤
  │ hanoi(3,a,b,c)              │
  └─────────────────────────────┘
```

> [!note] 递归展开结构
> 对于 `hanoi(2, a, c, b)` 的展开：
> ```
> hanoi(2, a, c, b)
>   hanoi(1, a, b, c)   → move(a, 1, c)
>   move(a, 2, b)
>   hanoi(1, c, a, b)   → move(c, 1, b)
> ```
> 对于 `hanoi(2, b, a, c)` 的展开：
> ```
> hanoi(2, b, a, c)
>   hanoi(1, b, c, a)   → move(b, 1, a)
>   move(b, 2, c)
>   hanoi(1, a, b, c)   → move(a, 1, c)
> ```
> 递归的关键在于：**每一层的工作记录都完整保存了本层返回后需要继续执行的语句位置和参数**，因此能正确完成“回退后继续”。

#### 过程的嵌套调用

```
主程序 r → 子过程1 r → 子过程2 s → 子过程3 t
                                       ↓
                                    返回 s
                                ↓
                             返回 r
                         ↓
                      返回 主程序
```

栈状态图（自下而上）：

- 调用子过程1：栈底 r；
- 调用子过程2：栈 [r, s]；
- 调用子过程3：栈 [r, s, t]；
- 依次返回：弹 t、弹 s、弹 r，回到主程序。

### 3.2.7 例七：N 皇后问题求解

**问题**：设 $n$ 皇后问题的解为 $(x_1, x_2, \dots, x_n)$，约束条件为：任意两个 $x_i$ 和 $x_j$ 不能位于棋盘的**同行、同列及同对角线**。

**棋盘的表示**：每行、每列及每条对角线上只能有一个棋子，因此**只需记录每列中棋子所在的行号**，用一维数组即可：

$$a[j] = i \quad\text{表示第 } j \text{ 列第 } i \text{ 行放一个皇后}$$

> [!example] 例：四皇后问题
> 解为 $(x_1, x_2, x_3, x_4)$，$x_i \in \{1, 2, 3, 4\}$，且任意两个 $x_i$、$x_j$ 不能同行、同列、同对角线。
>
> 求解过程：
> 1. 添加 $x_1 = 1$；
> 2. 添加满足条件的 $x_2 = 3$；
> 3. 对所有 $x_3 \in \{1, 2, 3, 4\}$ 都找不到满足约束的部分解 $(x_1, x_2, x_3)$，**回溯**到部分解 $(x_1)$；
> 4. 重新添加满足约束的 $x_2 = 4$，依次类推。

**判断第 `j` 列第 `i` 行放置后是否合法**：

```c
#define N 8      /* 皇后数量，可修改 */
int a[N + 1];    /* a[j] 表示第 j 列皇后所在的行号，a[0] 不用 */
int m = 0;       /* 解的个数计数器 */

int ok(int i, int j)
/* 检查在第 j 列第 i 行放置皇后是否与前面 1..j-1 列已放的皇后冲突 */
{
    int j1, i1, ok1 = 1;

    /* 1) 检查同列：前 j-1 列中是否有行号为 i 的皇后 */
    j1 = j - 1;
    while (j1 >= 1 && ok1)
    {
        ok1 = (a[j1] != i);      /* 注意：!= 而非 !== */
        j1--;
    }

    /* 2) 检查主对角线方向（左上→右下）：
       第 j1 列的行号 a[j1] 应不等于 i - (j - j1) */
    j1 = j - 1;
    i1 = i - 1;
    while (j1 >= 1 && i1 >= 1 && ok1)
    {
        ok1 = (a[j1] != i1);
        j1--;
        i1--;
    }

    /* 3) 检查副对角线方向（左下→右上）：
       第 j1 列的行号 a[j1] 应不等于 i + (j - j1) */
    j1 = j - 1;
    i1 = i + 1;
    while (j1 >= 1 && i1 <= N && ok1)
    {
        ok1 = (a[j1] != i1);
        j1--;
        i1++;
    }

    return ok1;
} /* ok */
```

> [!tip] `ok` 函数解析
> - **三个 while 检查**：
>   - **同列**：`a[j1] == i`；
>   - **左上对角线**：`a[j1] == i - (j - j1)`，即 `a[j1] == i1`；
>   - **左下对角线**：`a[j1] == i + (j - j1)`，即 `a[j1] == i1`；
> - **边界修正**：`j1` 从 `j - 1` 递减到 `1`（`j1 >= 1`），**不漏第 1 列**；
> - **`!==` 笔误修正**：C 语言中"不等于"写作 `!=`。

**完整求解程序**：

```c
void queen(int j)
/* 从第 j 列开始放置皇后，列号 1~N */
{
    int i;
    if (j > N)
    {
        m++;                         /* 找到一个解 */
        printf("m=%d ", m);
        for (i = 1; i <= N; i++)
            printf(" %d", a[i]);     /* 输出解的坐标 */
        printf("\n");
    }
    else
        for (i = 1; i <= N; i++)
            if (ok(i, j))            /* 在第 j 列第 i 行放置皇后合法 */
            {
                a[j] = i;            /* 记录本列皇后行号 */
                queen(j + 1);        /* 递归处理下一列 */
                /* 回溯：a[j] 会被下一轮循环覆盖，相当于撤销放置 */
            }
} /* queen */

int main(void)
{
    queen(1);    /* 从第 1 列开始放置 */
    return 0;
}
```

> [!tip] 代码解析
> - **回溯实现**：递归返回后，`a[j]` 会被下一个 `i` 覆盖，等价于"撤销放置"，无需显式撤销；
> - **时间复杂度**：$O(N!)$（最坏情况），实际因剪枝快很多；**空间复杂度** $O(N)$（递归栈 + 数组 `a`）；
> - **`ok` 只检查左侧列**：因为右侧列还没放皇后，右下、下方、左下都不可能已有棋子，**无需检查**。

## 3.4 队列

### 3.4.1 队列的定义与特性

**队列（Queue）**是只允许在**表的一端插入**、在**另一端删除**的线性表。

- 允许插入的一端称为**队尾（rear）**；
- 允许删除的一端称为**队头（front）**；
- 设队列 $Q = (a_1, a_2, \dots, a_n)$，$a_1$ 是**队头元素**，$a_n$ 是**队尾元素**；
- 队列元素按 $a_1, a_2, \dots, a_n$ 的顺序进入，也只能按这个次序退出；
- 无元素时称为**空队列**；
- 队列是"**先进先出**"的线性表，简称 **FIFO 表**（First In First Out）。

```
出队列 ← [a₁] [a₂] [a₃] ... [aₙ] ← 入队列
        (队头)              (队尾)
```

### 3.4.2 队列的抽象数据类型

```
ADT Queue
{
    数据对象:
        D = { aᵢ | aᵢ ∈ ElemSet, i = 1, 2, ..., n, n ≥ 0 }
    数据关系:
        R1 = { <aᵢ₋₁, aᵢ> | aᵢ₋₁, aᵢ ∈ D, i = 2, ..., n }
        约定 a₁ 端为队列头，aₙ 端为队列尾
    基本操作:
        InitQueue(&Q)            构造空队列 Q
        DestroyQueue(&Q)         销毁队列 Q
        QueueEmpty(Q)            若 Q 为空队列返回 TRUE，否则 FALSE
        QueueLength(Q)           返回 Q 的元素个数
        GetHead(Q, &e)           用 e 返回 Q 的队头元素
        ClearQueue(&Q)           将 Q 清为空队列
        EnQueue(&Q, e)           插入 e 为 Q 的新队尾元素
        DeQueue(&Q, &e)          删除 Q 的队头元素，用 e 返回其值
        QueueTravers(Q, visit()) 从队头到队尾依次对每个元素调用 visit()
} ADT Queue
```

> [!note] `QueueLength` 与 `QueueEmpty` 的区分
> - `QueueLength(Q)` 返回**元素个数**（数值）；
> - `QueueEmpty(Q)` 返回**布尔值**（TRUE/FALSE），语义为"队列是否为空"。

### 3.4.3 队列的顺序存储结构——顺序队列

用一维数组存储队列元素，数组上界表示最大容量。另设两个指针 `front` 和 `rear`：

- **`front` 指示队头元素**在队列中的位置；
- **`rear` 指示队尾元素的下一个位置**（即"队尾空位"）。

> [!note] 约定
> - **空队列**：`front = rear = 0`；
> - **非空队列**：`front` 指向当前队头元素，`rear` 指向队尾元素的**下一个**位置。

```c
#define MAXQSIZE 100   /* 队列最大容量 */

struct SeQueueup {
    char queue[MAXQSIZE];  /* 静态分配的一维数组 */
    int front, rear;       /* 队头、队尾指针 */
};
struct SeQueueup Q;
```

> [!note] 顺序队列状态演示（以 `A B C D E` 入队、`A B C` 出队、`F G H` 入队为例）
> **初始（空队列）**：
> ```
> front
>   ↓
> [0] [1] [2] [3] [4] [5] [6] [7]
>   ↑
> rear
> Q.front = Q.rear = 0
> ```
>
> **入队 A B C D E 后**：
> ```
> front
>   ↓
> [A] [B] [C] [D] [E] [ ] [ ] [ ]
>                       ↑
>                     rear
> Q.front = 0, Q.rear = 5
> ```
>
> **出队 A B C 后**：
> ```
>         front
>           ↓
> [ ] [ ] [ ] [D] [E] [ ] [ ] [ ]
>                       ↑
>                     rear
> Q.front = 3, Q.rear = 5
> ```
>
> **入队 F G H 后**：
> ```
>         front
>           ↓
> [ ] [ ] [ ] [D] [E] [F] [G] [H]
>                               ↑
>                             rear
> Q.front = 3, Q.rear = 8 = MAXQSIZE
> ```
>
> 'I' 无法再入队，因 `rear = MAXQSIZE`，此时队列**看起来"满了"**，但数组前 3 个位置其实空着 —— 这就是**假溢出**。

**顺序队列的入队 / 出队**：

```c
int EnQueue(struct SeQueueup &Q, char x)
/* 将元素 x 入队（非循环队列，不能解决假溢出） */
{
    if (Q.rear == MAXQSIZE)
        return ERROR;        /* 队列已满（可能是假溢出） */
    else
    {
        Q.queue[Q.rear] = x; /* 在队尾处写入 */
        Q.rear++;            /* 队尾指针后移 */
        return OK;
    }
} /* EnQueue */

int DeQueue(struct SeQueueup &Q, char &e)
/* 删除队头元素，用 e 返回其值 */
{
    if (Q.front == Q.rear)
        return ERROR;        /* 队列空 */
    else
    {
        e = Q.queue[Q.front]; /* 取出队头元素 */
        Q.front++;            /* 队头指针后移 */
        return OK;
    }
} /* DeQueue */
```

> [!warning] 非循环队列判断的陷阱
> - `Q.front == Q.rear != 0` → **队列一定空**；
> - `Q.rear == 0` → **队列一定空**；
> - `Q.front == 0` → **不能断定队列空**（可能队头恰好在数组起点）。
>
> 最后一种情况正是**假溢出**的来源。**上述 `EnQueue` 代码只能发现"尾部到底"，不能解决"前面有空位但 rear 到底"的假溢出**，必须用 **3.4.4 循环队列** 解决。

#### 假溢出与解决方案

**假溢出**：`rear = MAXQSIZE` 但队列中实际元素远少于 `MAXQSIZE`，前部空间无法利用。

**两种解决方案**：

1. **整体左移**：将整个队列左移，使第一个元素重新位于 `queue[0]`，并置 `front = 0`。
   - 缺点：**引起大量元素移动**，增加运行时间。
2. **循环队列**：设想 `queue[0]` 接在 `queue[MAXQSIZE-1]` 之后，使数组成为**首尾相接的环**：

$$\text{if } Q.rear + 1 = MAXQSIZE \text{ then } Q.rear = 0$$

即用**取模**操作：

$$Q.rear = (Q.rear + 1) \bmod MAXQSIZE$$

### 3.4.4 循环队列

```
       [0] [1] [2]
    [7]           [3]
    [6]   [5] [4]
```

**循环队列的入队 / 出队**：

```c
int EnQueue(struct SeQueueup &Q, char x)
/* 循环队列入队 */
{
    /* 判断队列是否已满：队尾加 1 等于队头（少用一个元素空间） */
    if ((Q.rear + 1) % MAXQSIZE == Q.front)
        return ERROR;          /* 队列满 */
    else
    {
        Q.queue[Q.rear] = x;   /* 写入队尾位置 */
        Q.rear = (Q.rear + 1) % MAXQSIZE;  /* 队尾指针循环加 1 */
        return OK;
    }
} /* EnQueue */

int DeQueue(struct SeQueueup &Q, char &e)
/* 循环队列出队 */
{
    if (Q.front == Q.rear)
        return ERROR;          /* 队列空 */
    else
    {
        e = Q.queue[Q.front];  /* 取出队头元素 */
        Q.front = (Q.front + 1) % MAXQSIZE;  /* 队头指针循环加 1 */
        return OK;
    }
} /* DeQueue */
```

#### 循环队列的队满与队空判定

> [!important] 循环队列的两难
> 直接使用 `front == rear` 判空或判满会**产生歧义**：队列满时 `front` 与 `rear` 也可能相等。
>
> **两种解决方法**：
>
> **① 设置标志 `flag`**：
> - `flag` 初始化为 `delete`；
> - 每次**插入**后置为 `entry`；每次**删除**后置为 `delete`；
> - 当 `front == rear` 时：`flag == entry` → 队满；`flag == delete` → 队空。
> - 缺点：**增加每次操作的判断开销**，而队列操作极其频繁，故不常用。
>
> **② 少用一个元素空间**（**教材采用的方法**）：
> - 约定队尾指针加 1 等于队头指针即队列满：
> $$\text{队满条件：} (Q.rear + 1) \bmod MAXQSIZE == Q.front$$
> - 队空条件仍为：$Q.front == Q.rear$。
> - 代价：有 $MAXQSIZE$ 个分量的循环空间只能表示长度不超过 $MAXQSIZE - 1$ 的队列。

> [!note] 循环队列的三种典型状态
> | 状态 | 图示特征 | 条件 |
> | --- | --- | --- |
> | 一般情况 | `front` 与 `rear` 不重合 | `front != rear` |
> | 队列满 | `rear` 的下一个就是 `front` | `(rear + 1) % MAXQSIZE == front` |
> | 队列空 | `front == rear` | `front == rear` |

### 3.4.5 队列的链式存储结构——链队列

用链表表示的队列简称**链队列**。需要两个分别指示**队头和队尾**的指针才能唯一确定。为操作方便，添加一个**头结点**，令头指针指向头结点。

> [!important] 链队列的约定
> - **头指针 `front`** 指向**头结点**；
> - **尾指针 `rear`** 指向**队尾结点**；
> - **空链队列**：`front == rear`（均指向头结点）。

```
空链队列：
Q.front → [头结点] ← Q.rear

非空链队列：
Q.front → [头结点] → [a₁] → [a₂] → ... → [aₙ] ← Q.rear
```

```c
struct qnode {             /* 链队列结点 */
    int data;              /* 数据域 */
    struct qnode *next;    /* 指针域 */
};

struct LinkQueue {         /* 链队列结构 */
    struct qnode *front;   /* 队头指针，指向头结点 */
    struct qnode *rear;    /* 队尾指针，指向队尾结点 */
};
```

**初始化**：

```c
int InitQueue(struct LinkQueue &Q)
/* 构造一个空链队列 */
{
    Q.front = (struct qnode *)malloc(sizeof(struct qnode));
    if (!Q.front)
        exit(OVERFLOW);           /* 存储分配失败 */
    Q.rear = Q.front;             /* 头、尾指针均指向头结点 */
    Q.front->next = NULL;         /* 头结点 next 置空 */
    return OK;
} /* InitQueue */
```

**销毁**：

```c
int DestroyQueue(struct LinkQueue &Q)
/* 销毁链队列 Q */
{
    while (Q.front)               /* 从头结点开始往后删结点 */
    {
        Q.rear = Q.front->next;   /* rear 暂存下一个结点 */
        free(Q.front);            /* 释放当前结点 */
        Q.front = Q.rear;         /* front 前移 */
    }
    return OK;
} /* DestroyQueue */
```

**入队**：

```c
int EnQueue(struct LinkQueue &Q, int x)
/* 将元素 x 插入为新的队尾元素 */
{
    struct qnode *p;
    p = (struct qnode *)malloc(sizeof(struct qnode));
    if (!p)
        exit(OVERFLOW);           /* 存储分配失败 */
    p->data = x;                  /* 新结点数据域赋值 */
    p->next = NULL;               /* 新结点作为新队尾，next 为空 */
    Q.rear->next = p;             /* 原队尾结点指向新结点 */
    Q.rear = p;                   /* 更新队尾指针 */
    return OK;
} /* EnQueue */
```

> [!tip] 入队解析
> - 链队列**入队只修改尾指针**，头指针不动（若队列为空，则新结点既是队头也是队尾，此时 `front->next = p` 即 "头结点指向新结点"，同时 `rear = p`）。

**出队**：

> [!important] 出队的两种情况
> - **队列长度 > 1**：只需修改**头结点的 `next`**，队尾指针不变；
> - **队列长度 = 1**：出队后成为空队列，除修改头结点的 `next` 外，**还需修改队尾指针**（因为此时队尾指针也指向被删结点）。

```c
int DeQueue(struct LinkQueue &Q, int &e)
/* 删除队头元素，用 e 返回其值 */
{
    struct qnode *p;
    if (Q.front == Q.rear)
        return ERROR;             /* 队空 */
    p = Q.front->next;            /* p 指向队头元素（头结点的后继） */
    Q.front->next = p->next;      /* 修改头结点指针域，指向新的队头 */
    e = p->data;                  /* 保存被删结点的数据 */
    if (Q.rear == p)              /* 队列中仅有一个元素 */
        Q.rear = Q.front;         /* 队尾指针回退到头结点 */
    free(p);                      /* 释放被删结点 */
    return OK;
} /* DeQueue */
```

> [!tip] 链队列与循环队列对比
> | 对比项 | 循环队列 | 链队列 |
> | --- | --- | --- |
> | 存储方式 | 静态数组（固定容量） | 动态链表 |
> | 容量 | 最大 `MAXQSIZE - 1` | 无固定上限（取决于内存） |
> | 队满条件 | `(rear + 1) % MAXQSIZE == front` | 无（除非内存耗尽） |
> | 队空条件 | `front == rear` | `front == rear` |
> | 适用场景 | 容量可预估、空间效率要求高 | 容量不可预估、元素变动大 |

## 3.5 本章小结与学习要点

> [!summary] 本章知识速查
>
> **一、栈与队列的对比**
>
> | 对比项 | 栈（Stack） | 队列（Queue） |
> | --- | --- | --- |
> | 插入位置 | 表尾（栈顶） | 表尾（队尾） |
> | 删除位置 | 表尾（栈顶） | 表头（队头） |
> | 特性 | **后进先出（LIFO）** | **先进先出（FIFO）** |
> | 典型应用 | 数制转换、括号匹配、表达式求值、递归 | 任务调度、缓冲处理 |
>
> **二、四种存储结构的关键判据**
>
> | 结构 | 空 | 满 |
> | --- | --- | --- |
> | 顺序栈（`Top` 指向栈顶元素） | `Top == -1` | `Top == MAXSIZE - 1` |
> | 顺序栈（`Top` 指向栈顶空位） | `Top == Base` | `Top - Base == Stacksize` |
> | 链栈 | `top == NULL` | 内存耗尽 |
> | 循环队列 | `front == rear` | `(rear + 1) % MAXQSIZE == front` |
> | 链队列 | `front == rear` | 内存耗尽 |
>
> **三、栈的应用要点**
>
> | 应用 | 栈的作用 | 时间复杂度 |
> | --- | --- | --- |
> | 数制转换 | 余数逆序输出 | $O(\log N)$ |
> | 括号匹配 | 最近左括号优先匹配 | $O(n)$ |
> | 行编辑 | 缓冲区支持回退 | $O(n)$ |
> | 迷宫求解 | 保存当前路径、回溯 | $O(mn)$ |
> | 表达式求值 | 算符优先、延迟计算 | $O(n)$ |
> | 递归实现 | 保存工作记录 | 取决于递归深度 |
> | N 皇后 | 回溯搜索 | $O(n!)$ |
>
> **四、上溢与下溢**
>
> | 结构 | 上溢（overflow） | 下溢（underflow） |
> | --- | --- | --- |
> | 栈 | 栈满再入栈 | 栈空再出栈 |
> | 队列 | 队列满再入队 | 队列空再出队 |
>
> **五、易错点**
> - **假溢出**：顺序队列 `rear == MAXQSIZE` 但前面仍有空位，需循环队列解决；
> - **循环队列判满**：`(rear + 1) % MAXQSIZE == front`（**少用一个元素空间**）；
> - **顺序栈的 `Top` 语义**：是指向栈顶元素，还是指向栈顶空位？使用时**必须明确**；
> - **链队列出队**：队列只剩一个元素时，**必须同时修改 `rear`**；
> - **表达式求值**：`c` 不变时（`>` 情况）需**继续与新的栈顶比较**，不能重新读入；
> - **`realloc` 安全性**：必须用临时变量接收，防止失败时丢失原指针。
>
> **六、递归与栈的关系**
> - 函数调用遵循"**后调用先返回**"，内存管理实行**栈式管理**；
> - 递归函数每进入一层，在栈顶压入一个**工作记录**（返回地址、实参、局部变量）；
> - 每退出一层，从栈顶弹出一个工作记录；
> - **递归 = 系统栈 + 分解子问题 + 合并解**。

## 3.6 课后作业解析

> [!question] 习题 3.9：将递推过程改写为递归过程
> **原递推代码**：
> ```c
> void recursion(int n)
> {
>     int i;
>     i = n;
>     while (i > 1)
>         printf(i--);
> }
> ```
>
> **分析**：`i` 从 `n` 递减到 `2`，每次打印 `i`，即打印 $n, n-1, \dots, 2$。
>
> **递归改写**：
> ```c
> void recursion(int n)
> /* 递归打印 n, n-1, ..., 2 */
> {
>     if (n > 1)
>     {
>         printf("%d", n);
>         recursion(n - 1);      /* 递归处理 n-1 */
>     }
> }
> ```
>
> > [!tip] 解析
> > - **递归出口**：`n <= 1` 时停止（与 `while (i > 1)` 对应）；
> > - **递归调用**：`recursion(n - 1)` 对应 `i--`；
> > - **执行顺序**：先打印 `n`，再递归打印 `n-1`，与递推的**自顶向下**一致。

> [!question] 习题 3.10：将递归过程改写为非递归过程
> **原递归代码**：
> ```c
> void test(int &sum)
> {
>     int x;
>     scanf(x);
>     if (x == 0)
>     {
>         sum = 0;
>     }
>     else
>     {
>         test(sum);
>         sum = sum + x;
>     }
>     printf(sum);
> }
> ```
>
> **分析**：`test` 不断读入 `x` 并递归，直到读入 0 时 `sum = 0`，然后在回退时**逆序**执行 `sum = sum + x`，并在每层返回时打印 `sum`。
>
> **非递归实现（用栈模拟）**：
> ```c
> void test(int &sum)
> /* 非递归实现：用栈模拟递归过程 */
> {
>     struct SqStack S;
>     int x;
>     InitStack(S);            /* 初始化栈，保存各层读入的 x */
>     scanf("%d", &x);
>     while (x != 0)
>     {
>         Push(S, x);          /* 非零 x 入栈，相当于进入下一层递归 */
>         scanf("%d", &x);
>     }
>     sum = 0;                 /* 对应递归出口：x == 0 时 sum = 0 */
>     while (!StackEmpty(S))
>     {
>         Pop(S, x);           /* 弹栈，相当于从递归返回 */
>         sum = sum + x;       /* 逆序执行 sum = sum + x */
>         printf("%d", sum);
>     }
> }
> ```
>
> > [!tip] 解析
> > - **递归的展开顺序**：先读入 $x_1, x_2, \dots, x_k$（均非零），然后读到 0，设 `sum = 0`，再**逆序**执行 $\text{sum} \leftarrow \text{sum} + x_k, \dots, \text{sum} \leftarrow \text{sum} + x_1$；
> > - **栈的作用**：非零的 `x` 按进入顺序压栈，返回时按**后进先出**顺序弹出，正好对应递归返回的顺序；
> > - 输出：每层返回时都打印 `sum`，共 $k$ 次输出。

> [!question] 习题 3.19：三种括号的匹配检验
> **题目**：算术表达式可含圆括号 `()`、方括号 `[]`、花括号 `{}`，三种括号可任意次序嵌套。编写判别括号是否正确配对的算法。
>
> **分析**：只需在 3.2.2 的 `matching` 算法中：
> 1. 增加三种左括号的 `case` 分支（全部进栈）；
> 2. 对三种右括号统一判断**是否与栈顶左括号配对**。
>
> ```c
> /* 判断左右括号是否配对 */
> int match_pair(char left, char right)
> {
>     if (left == '(' && right == ')') return 1;
>     if (left == '[' && right == ']') return 1;
>     if (left == '{' && right == '}') return 1;
>     return 0;
> } /* match_pair */
>
> int matching(char exp[], int len)
> /* 检验含三种括号的表达式 exp（长度 len）是否配对 */
> {
>     struct SqStack S;              /* 字符栈 */
>     int i = 0, state = 1;
>     char e;
>     InitStack(S);
>     while (i < len && state)
>     {
>         switch (exp[i])
>         {
>         /* 三种左括号：统一进栈 */
>         case '(':
>         case '[':
>         case '{':
>             Push(S, exp[i]);
>             i++;
>             break;
>
>         /* 三种右括号：统一与栈顶比较 */
>         case ')':
>         case ']':
>         case '}':
>             if (!StackEmpty(S))
>             {
>                 GetTop(S, e);
>                 if (match_pair(e, exp[i]))  /* 括号类型匹配 */
>                 {
>                     Pop(S, e);
>                     i++;
>                 }
>                 else
>                     state = 0;      /* 括号类型不匹配 */
>             }
>             else
>                 state = 0;          /* 右括号多余 */
>             break;
>
>         default:
>             state = 0;              /* 非法字符 */
>             break;
>         }
>     }
>     if (StackEmpty(S) && state)
>         return OK;
>     else
>         return ERROR;
> } /* matching */
> ```
>
> > [!tip] 解析
> > - **为什么能工作**：三种括号的嵌套遵循**严格的 LIFO**——最内层、最近的左括号必须与**最近的右括号**配对，栈顶总是"最迫切期待配对"的左括号；
> > - **时间 / 空间复杂度**：$O(n)$，其中 $n$ 为表达式长度；
> > - **`match_pair` 的设计**：将"配对规则"从主逻辑中分离，使主算法清晰，且便于后续扩展其他括号类型。
