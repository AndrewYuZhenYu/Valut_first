# 第二章 数据的机器级表示与处理

> [!abstract] 本章知识主线
> **现实中的数值或文字 → 二进制编码 → 内存存储 → 指令与运算电路 → 运算结果的解释。**
>
> 1. **数值表示**：进制、原码/反码/补码、无符号数与带符号数、浮点数。
> 2. **数据存储**：位、字节、字、字长；字节顺序、对齐、C 类型宽度。
> 3. **非数值表示**：逻辑数据、ASCII、汉字编码与字形。
> 4. **机器级运算**：位操作、移位、扩展与截断、ALU、条件标志、整数乘除法、浮点计算。
> 5. **程序正确性**：混合类型转换、溢出、舍入误差，以及机器语义与 C 语言语义的区别。

## 一、机器数与数值编码的基本思想

### 1. 计算机为什么采用二进制

计算机内部的各种信息最终都表示为 0 和 1。二进制适合硬件实现，原因包括：两种稳定物理状态较容易实现、逻辑门结构简单、与逻辑真/假直接对应，以及加法器等运算电路容易构造。

数据可分为两类：

| 类别 | 典型数据 | 同一串比特的解释依据 |
| --- | --- | --- |
| 数值数据 | 无符号整数、带符号整数、浮点数 | 位宽、编码方式、数值格式 |
| 非数值数据 | 逻辑值、状态位串、字符 | 指令、数据类型或字符编码标准 |

**真值**是数据实际表示的数学值；**机器数**是计算机中用于编码该值的有限长 0/1 序列。例如，在 8 位补码中，`11111111` 的真值为 $-1$；在 8 位无符号格式中，它的真值为 $255$。

> [!important] 最关键的思想
> **比特本身不携带“正负”“小数点”或“字符”等含义。** 必须结合位宽、编码/数据格式和处理指令才能解释它。
>
> 例如，`01011001` 可按无符号整数解释为 $89$，也可按 ASCII 解释为字母 `Y`；若事先约定为定点小数，含义还可能不同。

### 2. 数值表示的三个要素

1. **进位记数制**：确定每个数位的权，如二进制的权为 $2^i$。
2. **定点或浮点**：确定小数点的位置及是否由指数决定。
3. **二进制编码方式**：解决符号、阶码等如何编码的问题，例如补码、原码、移码。

> [!note] 从 C 程序到硬件
> C 变量提供类型语义；编译器依据目标机器的 ISA（指令集体系结构）将表达式变为指令，指令再控制寄存器、加法器、ALU 等电路。因而理解机器数，可以解释一些表面上看似“计算机算错了”的结果。

### 3. 一个 C 程序为何会因“数的表示”出错

设函数参数 `len` 是 `unsigned`，且循环条件写成 `i <= len - 1`。当 `len=0` 时，表达式 `len-1` 不是数学上的 $-1$，而是无符号取模后的最大值 `UINT_MAX`。循环因而可能错误地尝试读取不存在的元素。

> [!warning] 零长度数组处理中的无符号下溢
> `len - 1` 在 `len == 0` 时发生无符号回绕。因此用索引控制循环，应优先写成 `i < len`，避免把上界先减一。

```c
#include <stddef.h>

int array_sum(const int a[], size_t len) {
    int total = 0;                    // 累加器从0开始
    for (size_t i = 0; i < len; ++i) { // 直接检查i<len，避免len为0时下溢
        total += a[i];                // 累加当前数组元素
    }
    return total;                     // len为0时返回0
}
```

这段代码用于理解**无符号运算如何影响循环条件**；如果数组元素之和有可能超过 `int` 范围，还需要独立考虑累加器溢出问题。函数名与局部变量名也应避免遮蔽造成调用错误。

## 二、进位记数制与进制转换

### 1. R 进制与数位权重

设 $R$ 进制数为

$$
(a_na_{n-1}\cdots a_0.a_{-1}a_{-2}\cdots a_{-m})_R,
$$

则其对应的真值为

$$
V=\sum_{i=-m}^{n}a_iR^i,\qquad 0\le a_i<R.
$$

其中 $R$ 为**基数**，$R^i$ 为第 $i$ 位的**位权**。

| 进制 | 基数 | 可用数码 | 常见表示 |
| --- | ---: | --- | --- |
| 二进制 | 2 | `0,1` | $(1011)_2$、课件中的 `1011B` |
| 八进制 | 8 | `0`～`7` | $(17)_8$、`17O` |
| 十进制 | 10 | `0`～`9` | $(15)_{10}$ |
| 十六进制 | 16 | `0`～`9,A`～`F` | `0xFF`、`FFH` |

十六进制中的 `A,B,C,D,E,F` 分别代表十进制的 $10,11,12,13,14,15$。

> [!example] 按权展开
> $$
> (100101.01)_2=2^5+2^2+2^0+2^{-2}=37.25.
> $$
>
> $$
> (3A.1)_{16}=3\times16+10+\frac1{16}=58.0625.
> $$

### 2. 十进制整数转二进制：除基取余

不断除以 2，记录余数，最后将余数**逆序排列**。

以 $45$ 为例：

| 被除数 | 商 | 余数 |
| ---: | ---: | ---: |
| 45 | 22 | 1 |
| 22 | 11 | 0 |
| 11 | 5 | 1 |
| 5 | 2 | 1 |
| 2 | 1 | 0 |
| 1 | 0 | 1 |

自下而上读余数：$(45)_{10}=(101101)_2$。

也可以利用 $45=32+8+4+1$，直接写为 $101101$。熟记 $2^0$ 到 $2^{16}$ 等常见幂，可快速拆数。

### 3. 十进制小数转二进制：乘基取整

对小数反复乘以 2，将每次所得的**整数部分按正序排列**。

> [!example] 将 $0.6875$ 转为二进制
> $$
> \begin{aligned}
> 0.6875\times2&=1.375 &&\Rightarrow1\\
> 0.375\times2&=0.75 &&\Rightarrow0\\
> 0.75\times2&=1.5 &&\Rightarrow1\\
> 0.5\times2&=1.0 &&\Rightarrow1
> \end{aligned}
> $$
>
> 因此 $(0.6875)_{10}=(0.1011)_2$。结合整数部分，$(835.6875)_{10}=(1101000011.1011)_2$。

**不是所有十进制有限小数都能转换成有限二进制小数。** 例如：

$$
(0.1)_{10}=(0.0001100110011\ldots)_2.
$$

> [!warning] 小数的精确表示
> 一个最简分数的分母只有 $2$ 的因子时，才能用有限位二进制小数精确表示。$0.5$、$0.25$ 可以精确表示，$0.1$ 一般只能近似存储。后续浮点误差正是从这里开始的。

### 4. 二进制与八/十六进制快速互换

二进制自小数点向两侧分组，不足补 0：

- 每 **3 位**对应一个八进制数码；
- 每 **4 位**对应一个十六进制数码。

例如：

$$
(1010\ 1100\ 0101)_2=(\mathrm{AC5})_{16}.
$$

再如：

$$
(110\ 101\ 011)_2=(653)_8.
$$

### 5. C 语言中的字面量表示

```c
int a = 45;          // 十进制常量
int b = 0x2D;        // 十六进制常量，数值仍是45
int c = 055;         // 八进制常量，注意前导0
unsigned d = 45U;    // 后缀U表示无符号整数字面量
```

> [!warning] 注意前导 0
> 在传统 C 整数字面量中，`012` 代表八进制的 12，即十进制的 10，而不是十进制的 12。用于跨版本 C 代码时，二进制整数可以写为 `0x...` 并通过位运算体现，避免依赖特定标准支持的 `0b` 语法。

## 三、定点数、原码、反码与补码

### 1. 定点数与浮点数

- **定点数**：约定小数点固定。例如 8 位整数约定小数点在最低位之后；定点小数则可以约定小数点在符号位之后。
- **浮点数**：用尾数和指数共同决定数值，小数点的位置等效地随指数变化。

浮点数一般写为

$$
X=(-1)^S\times M\times R^E,
$$

其中 $S$ 是符号位，$M$ 是尾数，$R$ 是基数，$E$ 是阶（指数）。

### 2. 原码、反码与补码对比

以 **4 位有符号整数** 为例：

| 真值 | 原码 | 反码 | 补码 |
| ---: | :---: | :---: | :---: |
| $+5$ | `0101` | `0101` | `0101` |
| $-5$ | `1101` | `1010` | `1011` |
| $+0$ | `0000` | `0000` | `0000` |
| $-0$ | `1000` | `1111` | **仍为 `0000`** |

- **原码**：最高位表示符号，其余位表示绝对值；有两个零，加减法处理不统一。
- **反码**：正数不变，负数由对应正数逐位取反得到；同样存在 $+0$ 和 $-0$。
- **补码**：正数不变，负数由对应正数**按位取反再加 1**得到；整数运算更方便，零编码唯一。

> [!important] n 位补码表示范围
> $$
> \boxed{-2^{n-1}\le x\le2^{n-1}-1}
> $$
> 
> 8 位：$-128\sim127$；16 位：$-32768\sim32767$；32 位：$-2^{31}\sim2^{31}-1$。
>
> **最小负数没有对应的同位宽正数**，这是计算 `-INT_MIN`、`INT_MIN/-1` 时必须警惕的原因。

### 3. 补码的本质：模 $2^n$ 运算

把一个 $n$ 位二进制加法器看作一个模为 $2^n$ 的计数器：结果超出 $n$ 位后，高位被舍弃。

$$
\boxed{[x]_{\mathrm{补}}=x\bmod2^n}
$$

若用非负整数 $0\sim2^n-1$ 代表编码：

$$
[x]_{\mathrm{补}}=\begin{cases}
x,&x\ge0,\\
2^n+x,&x<0.
\end{cases}
$$

例如，在 8 位系统中：

$$
[-5]_{\mathrm{补}}=256-5=251=(11111011)_2.
$$

反向解释一个 8 位补码机器数：若最高位为 0，按普通二进制非负整数读取；若最高位为 1，则其真值等于无符号值减去 $256$。

> [!example] 8 位补码中求 $-123$
> $$
> 123=(01111011)_2.
> $$
> 按位取反：`10000100`；加 1：`10000101`，因此
> $$
> [-123]_{\mathrm{补}}=(10000101)_2=\mathrm{0x85}.
> $$

### 4. 补码加减法为什么能统一

在固定 $n$ 位宽下：

$$
\boxed{[a+b]_{\mathrm{补}}=([a]_{\mathrm{补}}+[b]_{\mathrm{补}})\bmod2^n}
$$

$$
\boxed{[a-b]_{\mathrm{补}}=([a]_{\mathrm{补}}+[\,-b\,]_{\mathrm{补}})\bmod2^n}
$$

因为 $[-b]_{\mathrm{补}}=(\sim[b]_{\mathrm{补}})+1$（取反和加一都在固定 $n$ 位中完成），所以**硬件只需要加法器，配合反相与进位输入，就能实现减法**。

8 位示例：

```text
  0111 1111     127
+ 1100 0000     -64 的8位补码
-----------
1 0011 1111     仅保留低8位：0011 1111，即63
```

### 5. 无符号数与补码数的相同和不同

| 项目 | n 位无符号整数 | n 位补码有符号整数 |
| --- | --- | --- |
| 数值范围 | $0\sim2^n-1$ | $-2^{n-1}\sim2^{n-1}-1$ |
| 最高位含义 | 普通数值位 | 带负权的符号位 |
| 相同输入位串的低 n 位加法结果 | 相同 | 相同 |
| 判断结果是否越界 | 无符号进位/借位 | 有符号溢出 |

例如 `10000000` 在无符号 8 位格式下是 $128$，在 8 位补码格式下却是 $-128$。

> [!warning] 不要混淆“数学溢出”和“C 语言行为”
> 在物理上的固定宽度补码加法器中，高位自然丢失；但在 C 语言中，**无符号整数溢出按 $2^n$ 取模，带符号整数溢出属于未定义行为**。不能仅凭常见 CPU 使用补码，就断言任何 `int` 溢出表达式都可以安全获得环绕后的值。

## 四、位宽、数据类型与类型转换

### 1. bit、Byte、word、字长

- **位（bit，b）**：一位二进制信息。
- **字节（Byte，B）**：现代通用机器通常为 8 位，是常见的最小可寻址存储单位；在 C 标准中一个字节有 `CHAR_BIT` 位，标准只保证不少于 8 位。
- **字（word）**：某个体系结构约定的数据处理单位，**不一定等于 CPU 字长**。例如 x86 术语中 `WORD` 为 16 位、`DWORD` 为 32 位、`QWORD` 为 64 位。
- **字长**：与处理器内部通用寄存器、运算部件、数据通路等设计有关的宽度；不能拿 `sizeof(int)` 简单代替。

> [!note] 存储容量和传输速率的单位
> 课件采用传统约定，如 $1\,\mathrm{KB}=1024\,\mathrm B$。更严格的现代区分是：$1\,\mathrm{KiB}=1024\,\mathrm B$，$1\,\mathrm{kB}=1000\,\mathrm B$；网络传输速率中的 $1\,\mathrm{Mb/s}=10^6\,\mathrm{bit/s}$。注意小写 `b`（位）与大写 `B`（字节）不同。

### 2. C 语言的整数、浮点与指针类型

典型 32 位环境中：`char` 1 字节、`short` 2 字节、`int` 4 字节、`long` 4 字节；64 位环境里的 `long` 可能为 4 或 8 字节，指针大小也可能不同。

> [!important] 类型宽度由平台及 ABI 决定
> 不可假定所有机器的 `int`、`long`、指针均有固定字节数。C 对各种整数类型给出最小范围及相对宽度约束，而精确宽度应由目标平台和编译器确定。

可用以下代码查看：

```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    printf("char: %zu byte(s)\n", sizeof(char));       // char固定占1个C字节
    printf("short: %zu byte(s)\n", sizeof(short));     // 输出short占用字节数
    printf("int: %zu byte(s)\n", sizeof(int));         // 输出int占用字节数
    printf("long: %zu byte(s)\n", sizeof(long));       // 输出long占用字节数
    printf("pointer: %zu byte(s)\n", sizeof(void *));  // 输出对象指针的典型存储宽度
    printf("bits per byte: %d\n", CHAR_BIT);           // 一个C字节包含多少位
    return 0;
}
```

`sizeof` 的结果类型为 `size_t`，对应 `printf` 的 `%zu`。

### 3. 整型提升与通常算术转换

- `char`、`short` 等参与大多数算术运算时，通常先**整型提升**为 `int`（若 `int` 容纳不了其所有值，则提升为 `unsigned int`）。
- 两个操作数的类型不一致时，再进行**通常算术转换**，得到共同运算类型。
- 对同等级的 `int` 和 `unsigned int`，前者转换为后者；若不同宽度或等级，还需要综合可表示范围，不能笼统理解为“遇到 unsigned 永远都按 unsigned 算”。

> [!example] 为什么 `-1 < 0U` 为假
> 在通常的 32 位 `int`/`unsigned int` 模型中：
> $$
> -1\ \longrightarrow\ 2^{32}-1=4294967295.
> $$
> 因此比较实际上相当于 `4294967295U < 0U`，结果为假。

```c
int a = -1;                    // a为带符号整数
unsigned b = 0U;              // b为无符号整数
int r1 = (a < 0);             // 真：-1小于0
int r2 = (a < b);             // 常见32位模型中为假：a被转为unsigned
int r3 = (a < (int)b);        // 真：两边按int比较；此处b=0，转换安全
```

以下是在 **32 位 `int`、补码存储** 模型中的典型比较：

| 表达式 | 结果 | 关键原因 |
| --- | :---: | --- |
| `0 == 0U` | 真 | 相同的数值 0 |
| `-1 < 0` | 真 | 带符号比较 |
| `-1 < 0U` | 假 | `-1` 转换为无符号最大值 |
| `2147483647 > -2147483647 - 1` | 真 | 都能按 `int` 解释 |
| `2147483647U > -2147483647 - 1` | 假 | 右边被转成无符号数 $2^{31}$ |
| `(unsigned)-1 > -2` | 真 | 两边转换为无符号值后比较 |

### 4. 整型常量与极值的表达方式

在 C 中，负号 `-` 是**一元运算符**，并非整数字面量本身的一部分。因此 `-2147483648` 不是一个独立的“负数字面量”，编译器先确定 `2147483648` 的类型，再执行取负运算。

```c
#include <limits.h>

int minimum = INT_MIN;       // 推荐：使用标准极值宏
int maximum = INT_MAX;       // 推荐：使用标准极值宏
int same_min = -2147483647 - 1; // 假定int为32位时，结果为-2147483648
```

> [!warning] 版本与 ABI 会影响常量类型
> 课件通过 C90、C99 讨论整数常量类型变化。实际规则还涉及数字是否为十进制、是否带 `U/L/LL` 后缀、目标环境中 `long` 的宽度等。不要将某一张“32 位机器默认类型表”当成对全部 C 编译器普遍成立的规则。

### 5. 数值转换与机器位模式的区别

```c
unsigned int u = (unsigned int)-1; // 数学上按无符号模数转换：得到UINT_MAX
int x = -1;                       // x仍然是带符号值-1
```

`(unsigned int)-1` 的数值结果由 C 标准定义，与处理器是否恰好采用补码无关。相反，**超出目标有符号整数类型范围的转换**，在较常用的 C17 及更早标准中，结果由实现定义，或者产生实现定义的信号；不能直接写成“一定按高位截断”，也不能笼统称为必然未定义行为。

> [!example] 扩展与截断带来的变化
> 假定 16 位 `short`、32 位 `int`、补码机器：
>
> `int i = 32768;` 的位模式为 `00008000`（十六进制）。
>
> `(short)i` 常见地截取低 16 位 `8000`，解释为 $-32768$；再转换回 `int` 通常得到 `FFFF8000`，真值仍为 $-32768$，因而与原来的 $32768$ 不相等。
>
> **注意**：这里具体的超范围转换结果依赖实现，表述的是教学机器的常见行为。

## 五、内存中的存储顺序与边界对齐

### 1. 数据地址与字节排列

内存按字节编址。一个多字节对象占用连续的字节位置，其地址通常指向**最低地址处的字节**。

以 32 位数据 `0x12345678` 存放在地址 `0x1000` 起的四个字节中为例：

| 字节地址 | 大端（Big Endian） | 小端（Little Endian） |
| --- | :---: | :---: |
| `0x1000` | `12` | `78` |
| `0x1001` | `34` | `56` |
| `0x1002` | `56` | `34` |
| `0x1003` | `78` | `12` |

- **大端**：最高有效字节放在最低地址处。
- **小端**：最低有效字节放在最低地址处。
- **MSB / LSB** 可以分别指最高/最低有效位；讨论整个字节时可使用 **most/least significant byte** 避免歧义。

> [!important] 一个关键区别
> **大小端描述的是多字节数据在内存中的字节排列，不是数字的正负，也不是数学上从左往右写的二进制顺序。** 同一个数在大小端机器上具有相同数值，只是各地址处的内容不同。

> [!example] 负数在不同字节顺序下存储
> 假定 `int` 为 32 位，$-65535$ 的补码是 `0xFFFF0001`。
>
> - 小端、从低地址到高地址：`01 00 FF FF`。
> - 大端、从低地址到高地址：`FF FF 00 01`。

### 2. 查看本机字节序：使用对象表示

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    uint32_t x = 0x12345678U;                  // 32位无符号整数
    const unsigned char *p = (const unsigned char *)&x; // 按字节查看其对象表示

    for (size_t i = 0; i < sizeof x; ++i) {     // 从低地址开始依次读取
        printf("%02X ", (unsigned)p[i]);        // 打印当前字节的十六进制值
    }
    putchar('\n');                              // 输出换行
    return 0;
}
```

在每个字节 8 位的典型平台上，小端输出 `78 56 34 12`，大端输出 `12 34 56 78`。`unsigned char` 可合法观察对象的字节表示，比依赖 `char` 默认有符号性来测试更可靠。

> [!warning] `char` 的符号会干扰字节比较
> 如果 `char` 为带符号类型，则存储字节 `0xFF` 的 `char` 可能提升为数值 `-1`，与整数字面量 `0xFF`（255）比较时并不相等。读取原始二进制字节时应优先选用 `unsigned char`。

### 3. 字节交换与跨机器通信

当文件、通信协议、内存映射寄存器指定一种字节序，而本机采用另一种字节序时，需要交换字节顺序。例如：

```c
#include <stdint.h>

uint32_t swap32(uint32_t x) {
    return ((x & 0x000000FFU) << 24) | // 最低字节移到最高字节位置
           ((x & 0x0000FF00U) <<  8) | // 次低字节左移8位
           ((x & 0x00FF0000U) >>  8) | // 次高字节右移8位
           ((x & 0xFF000000U) >> 24);  // 最高字节移到最低字节位置
}
```

例如 `swap32(0x12345678U)` 的结果是 `0x78563412U`。注意：该函数是**数值的字节逆序变换**，不是在任意情形下自动完成网络序/主机序转换，后者应遵循协议规定。

### 4. 为什么需要边界对齐

对象通常按类型对齐要求放在某些地址上。若一个 4 字节整数按 4 字节对齐，则起始地址通常满足

$$
\mathrm{address}\bmod4=0.
$$

按边界对齐可能减少访存次数，简化或加快硬件访问；某些体系结构还限制非对齐访问。结构体成员之间可能存在填充字节，因此 `sizeof(struct ...)` 不一定等于成员 `sizeof` 的简单相加。

> [!note] 对齐不是字节序
> 大端或小端决定字节如何排列；对齐决定对象允许从哪些地址开始存放。二者是不同问题。

## 六、逻辑值、字符与汉字编码

### 1. 逻辑数据和位串

一个逻辑量可用一位表示（0/1），多个逻辑状态可组合成位串，如设备状态寄存器、权限标志或 CPU 的条件标志。不同位由不同位置的 0/1 表示，不一定整体解释为一个整数。

在 C 中可用 `&`、`|`、`^`、`~`、移位等操作测试或修改特定位。

### 2. ASCII 编码

ASCII 的基本编码使用 7 位，共有 128 个代码位置，包括可显示字符和控制字符。

| 字符或字符段 | ASCII 编码 |
| --- | --- |
| `'0'`～`'9'` | `0x30`～`0x39`（48～57） |
| `'A'`～`'Z'` | `0x41`～`0x5A`（65～90） |
| `'a'`～`'z'` | `0x61`～`0x7A`（97～122） |
| 空格 | `0x20`（32） |
| 换行 LF | `0x0A`（10） |

> [!example] 字符 `'7'` 与整数 7
> `'7'` 的 ASCII 编码是十进制 $55$，而整数 7 的值就是 7。要把 ASCII 数字字符转换为对应数字，可减去 `'0'`：

```c
char ch = '7';        // ch保存数字字符的编码
int value = ch - '0'; // 在ASCII兼容执行字符集上得到整数7
```

C 标准保证十进制数字字符 `'0'`～`'9'` 的编码连续，因此这种写法也是常见的可移植转换方式。

### 3. 汉字的不同编码层次

| 名称 | 用途 | 例子或说明 |
| --- | --- | --- |
| 输入码 | 通过键盘等输入汉字 | 拼音输入、笔画输入 |
| 内码 | 存储、检索、传输字符 | GB2312、GBK、UTF-8 等编码方案 |
| 字形码（字模/轮廓） | 显示与打印 | 点阵字体、矢量轮廓字体 |

GB2312 时代的一种汉字内码方法，是在国标交换码两个字节的最高位都置 1，以区别于单字节 ASCII 字符。例如课程中的“大”：国标交换码为 `0x3473`，对应的 GB2312/EUC-CN 存储字节是 `B4 F3`。

现代软件还大量使用 **Unicode** 与 **UTF-8**：Unicode 为字符分配码点，UTF-8 将码点编码成可变长度的字节序列。不能将“汉字固定占两个字节”看作对所有现代字符编码成立的规律。

> [!warning] 文字编码与字体字形不能混为一谈
> 同一个汉字在不同字体中可能呈现不同形状；字符编码负责“表示哪个字符”，字体负责“如何画这个字符”。GB2312、GBK、UTF-8 的编码也不能直接当成字符图形。

## 七、浮点数的机器级表示：IEEE 754

### 1. 从科学计数法到规格化二进制数

十进制科学计数法如 $6.02\times10^{21}$。二进制浮点数也使用**尾数 × 基数的指数次方**：

$$
X=(-1)^S\times M\times2^E.
$$

在 IEEE 754 的二进制规格化格式中，非零有效数字以 `1.xxxxx` 开头，这个最前面的 `1` 不必存入尾数字段，称为**隐藏位（隐含的 1）**。

> [!note] 区分“自定义浮点格式”和 IEEE 754
> 一种早期教学用浮点格式可能把规格化尾数约定成 `0.1xxxx`、阶码偏置约定为 128。它可以用来理解浮点数范围，但**不能直接套用 IEEE 754 的位布局和 bias**。以下以常用 IEEE 754 二进制格式为主。

> [!example] 非 IEEE 教学浮点格式的范围计算
> 若某 32 位格式规定：1 位符号、8 位移码指数（偏置 128）、24 位规格化二进制小数尾数（最高位 `1` 隐含，后面显式保存 23 位），那么真实指数范围是 $-128$ 到 $127$。
>
> 最小正规格化正数：
>
> $$
> 0.100\ldots0_2\times2^{-128}=2^{-129}.
> $$
>
> 最大有限正数：
>
> $$
> 0.111\ldots1_2\times2^{127}=(1-2^{-24})\times2^{127}.
> $$
>
> **注意**：这是该题自行约定格式的答案，并不是 IEEE 754 binary32 的最小/最大规格化数。

### 2. 单精度与双精度的字段结构

| 格式 | 总位宽 | 符号位 $S$ | 指数字段 $e$ | 尾数字段 $f$ | 规格化指数偏置 bias |
| --- | ---: | ---: | ---: | ---: | ---: |
| binary32（通常对应 `float`） | 32 | 1 | 8 | 23 | 127 |
| binary64（通常对应 `double`） | 64 | 1 | 11 | 52 | 1023 |

规格化有限数的值为：

$$
\boxed{X=(-1)^S\times(1+f)\times2^{e-\mathrm{bias}}}
$$

其中 $f$ 是尾数字段形成的**二进制小数**，例如尾数字段以 `101` 开头时，$f=2^{-1}+2^{-3}+\cdots$；$e$ 是指数**字段的无符号整数值**。

单精度的有限规格化数满足 $1\le e\le254$，其真实指数为 $-126\sim127$；双精度正常数的真实指数为 $-1022\sim1023$。

> [!important] 为什么尾数字段只有23位，有效精度却是24位？
> 因为规格化 binary32 的最高有效位 `1` 由格式约定而隐含，实际有效精度为 **1 位隐藏位 + 23 位显式尾数 = 24 位二进制有效位**。binary64 类似，具有 53 位有效精度。

### 3. 特殊指数编码与五类数据

单精度可按下表判定：

| 指数字段 $e$ | 尾数字段 | 类别 | 实际取值 |
| --- | --- | --- | --- |
| `00000000` | 全 0 | $+0/-0$ | 带符号的零 |
| `00000000` | 非零 | 非规格化数 | $(-1)^S\times f\times2^{-126}$ |
| `00000001`～`11111110` | 任意 | 规格化数 | $(-1)^S(1+f)2^{e-127}$ |
| `11111111` | 全 0 | $+\infty/-\infty$ | 正/负无穷大 |
| `11111111` | 非零 | NaN | 非数（Not a Number） |

#### （1）正零与负零

`+0` 与 `-0` 的指数字段、尾数字段均为全 0，区别只在符号位。二者进行普通数值相等比较时相等，但在某些运算中可能表现不同，例如符合 IEEE 754 非陷阱规则时 `1.0/+0.0` 和 `1.0/-0.0` 分别产生正负无穷大。

#### （2）无穷大 Infinity

指数全 1、尾数全 0。可以作为有限值超出范围、非零有限数除以零等情况的结果，具体是否产生异常标志或陷阱取决于浮点环境。

#### （3）NaN（非数）

指数全 1、尾数非零，用于表示某些没有有效实数结果的运算，如 $0.0/0.0$、$\sqrt{-4.0}$（常见 IEEE 浮点环境）。NaN 一般具有**不等于自身**的性质：

```c
#include <math.h>

double x = NAN;       // NAN表示一个非数值浮点值（宏在math.h中）
int same = (x == x);  // 对NaN而言，通常结果为0（假）
int is_nan = isnan(x); // 推荐使用标准宏判断NaN
```

> [!warning] 浮点除零与整数除零不同
> 在通常的 IEEE 754 非陷阱环境中，非零浮点数除以零可得到无穷大；但 C 语言对浮点环境、异常处理有平台差异。**整数除以 0 在 C 中是未定义行为**；不能把二者概括为“除零永远不会引发程序异常”。

#### （4）非规格化数（次正规数，subnormal）

若指数字段全 0 且尾数非零，隐藏位改为 `0`，并按真实指数 $-126$ 解释：

$$
X=(-1)^S\times(0.f)_2\times2^{-126}.
$$

这使表示范围从最小正规格化数 $2^{-126}$ 继续向零延伸：

$$
\boxed{\text{最小正非规格化 binary32}=2^{-149}}
$$

最大的正非规格化数为 $(1-2^{-23})2^{-126}$，其与最小正规格化数之间恰好相差 $2^{-149}$。

> [!important] 渐进下溢
> 非规格化数使很小的非零结果**不必立即变成0**，而是可以牺牲有效位数表示接近零的数。这称为渐进下溢（gradual underflow）。

### 4. IEEE 754 编码实例：十六进制转浮点数

给定单精度机器数 `0xBEE00000`：

```text
1 | 01111101 | 11000000000000000000000
S      e                   尾数
```

- 符号位 $S=1$，因此为负数。
- 指数字段 $(01111101)_2=125$，真实指数 $E=125-127=-2$。
- 有效数字 $M=(1.11)_2=1+1/2+1/4=1.75$。

所以

$$
\boxed{X=-1.75\times2^{-2}=-0.4375}.
$$

### 5. 十进制数转 IEEE 754：以 -12.75 为例

第一步，整数部分 $12=(1100)_2$；小数部分 $0.75=(0.11)_2$。

第二步，合并并规格化：

$$
-12.75=-(1100.11)_2=-(1.10011)_2\times2^3.
$$

第三步，编码：符号位为 `1`；阶码为 $3+127=130=(10000010)_2$；尾数记录隐含 `1` 后面的 `10011` 并补 0。

```text
1 | 10000010 | 10011000000000000000000
```

最终：

$$
\boxed{\mathrm{0xC14C0000}}.
$$

### 6. 浮点数的范围与精度

| 指标 | binary32 | binary64 |
| --- | --- | --- |
| 最大有限正数（约） | $3.4\times10^{38}$ | $1.8\times10^{308}$ |
| 最小正规格化数 | $2^{-126}$ | $2^{-1022}$ |
| 最小正非规格化数 | $2^{-149}$ | $2^{-1074}$ |
| 有效二进制位 | 24 | 53 |
| 常见十进制有效精度（约） | 7 位 | 15～16 位 |

最大有限 binary32 的精确表达式是

$$
(2-2^{-23})\times2^{127}.
$$

浮点数虽能覆盖很大的数值范围，但**并不是每个实数都存在一个精确的机器编码**；相邻可表示数间的间隔随量级增大而变大。

> [!example] 为什么 $61.42$ 存成 `float` 可能不是精确的 61.42？
> 它在二进制中通常不能有限展开，只能取邻近的可表示数。对于 32 位单精度，在 $[32,64)$ 这一量级附近，相邻可表示数的间隔为 $2^{5-23}=2^{-18}\approx0.0000038147$。因此显示多位小数时，可能发现与输入的十进制数存在微小偏差。

### 7. 什么是 ULP（补充理解）

ULP 可以理解为指定量级附近“相邻可表示浮点数的间隔”。对 binary32 正规格化数、位于 $[2^E,2^{E+1})$ 的普通区间内，间隔为

$$
\mathrm{ULP}=2^{E-23}.
$$

因此同样是相差 $0.01$，相对于一个很小的数可能很显著，而相对于非常大的数可能小到被舍入直接吞掉。

### 8. C 中观察浮点数的位编码

浮点数的数值转换与“把其位模式解释为整数”是两回事。用 `memcpy` 读取对象字节比不安全的指针强制类型转换更合适：

```c
#include <stdint.h>
#include <string.h>

float value = 0.1f;                 // 单精度浮点数；多数IEEE平台上为近似0.1
uint32_t bits = 0U;                // 用32位无符号数接收原始位模式
memcpy(&bits, &value, sizeof bits); // 按对象表示复制字节，不做数值转换
```

这个示例假定 `float` 恰好为 32 位且使用 IEEE 754 binary32。在通常平台上，`bits` 为 `0x3DCCCCCD`。

> [!warning] `float a = 0x3DCCCCCD;` 并不是按位构造浮点数
> 这种赋值会把十六进制整数的**数值**转换成浮点数，而非解释整数位模式。若要观察或复制原始位模式，应区分对象表示与数值转换，避免依赖违反类型别名规则的写法。

## 八、位运算、逻辑运算、移位、扩展与截断

### 1. 按位运算与逻辑运算的区别

| 运算 | C 运算符 | 工作对象 | 典型用途 |
| --- | --- | --- | --- |
| 按位与 | `&` | 两个整数的对应位 | 清零、位掩码 |
| 按位或 | `\|` | 两个整数的对应位 | 指定位设置为 1 |
| 按位异或 | `^` | 两个整数的对应位 | 位翻转、差异检测 |
| 按位取反 | `~` | 单个整数的每一位 | 位翻转 |
| 逻辑与 | `&&` | 两个条件的真值 | 两条件均满足 |
| 逻辑或 | `\|\|` | 两个条件的真值 | 至少一个条件满足 |
| 逻辑非 | `!` | 一个条件的真值 | 真值取反 |

按位与的基本规律是 `1&1=1`，其他结果为 0；按位或只要至少一位为 1 就得到 1；异或两位不同得 1；按位取反让 0、1 互换。

> [!example] 位掩码提取高字节
> 设 16 位数 $y=\mathrm{0x2C0B}$，那么
> $$
> y\ \&\ \mathrm{0xFF00}=\mathrm{0x2C00}.
> $$
> 掩码 `FF00` 的高 8 位为 1、低 8 位为 0，因此高字节保留，低字节清零。

```c
unsigned y = 0x2C0BU;             // 待处理的16位范围内数据
unsigned high_part = y & 0xFF00U; // 保留高字节位置：0x2C00
unsigned high_byte = (y >> 8) & 0xFFU; // 将高字节移到低位：0x2C
```

### 2. 逻辑运算的短路特性

`&&` 和 `||` 不仅对**整体真值**运算，而且具有短路求值：

```c
int b = 0;                       // 除数为0
if (b != 0 && 100 / b > 5) {    // 左侧为假，右侧不求值，避免整数除0
    // 此分支不会执行
}
```

`&` 不是 `&&` 的简写。`a & b` 是按位运算，而 `a && b` 将两边转换为真假判断，结果为 0 或 1；逻辑或与按位或也同理。

> [!warning] 位运算与逻辑运算不能互换
> `2 & 4` 的结果是 `0`，但 `2 && 4` 的结果是 `1`，因为两个整数均非零，逻辑上都为真。

### 3. 左移与右移

- `x << k`：各位向左移动 $k$ 位，低位补 0；可能丢失高位。
- `x >> k`：各位向右移动 $k$ 位，丢失低位；高位填充取决于操作数类型与相应语言/硬件规则。

在固定 **n 位机器数** 的模型中：

| 数据类型 | 左移 | 右移 |
| --- | --- | --- |
| 无符号数 | 高位移出、低位补 0；相当于模 $2^n$ 的乘 $2^k$ | 高位补 0；相当于向下取整的除 $2^k$ |
| 补码有符号数 | 硬件上通常也是高位移出、低位补 0 | 典型算术右移：高位补符号位 |

> [!important] 机器移位与 C 表达式的边界
> 固定位宽硬件左移的“高位丢失”，不等于任何 C 整型表达式均可安全照搬。C 中负的有符号数左移以及无法表示的有符号左移结果，在常见课程采用的 C11/C17 规则下可能出现未定义行为；负数的带符号右移也有实现差异。教学中若要稳定观察位模式，优先使用无符号类型。

**移位位数限制**：在 C 中，右操作数不得为负数，也不得大于等于经过整数提升后左操作数的位宽，否则行为未定义。

```c
unsigned x = 0xA5U;     // x的低8位是10100101
unsigned left = x << 2; // 在足够宽的unsigned类型中得到0x294
unsigned right = x >> 2;// 右移两位：得到0x29
```

> [!warning] 小整数类型会先提升
> 如果 `unsigned char x=0x80;`，表达式 `x << 1` 通常先把 `x` 提升为 `int`，所以结果不一定是“8 位左移后归零”。必须分别明确**C 表达式宽度**和**将结果送入窄寄存器/窄变量后的结果**。

### 4. 零扩展与符号扩展

**扩展**把较小位宽的数据转换为更大位宽：

- 无符号数：在高位补 0，称为**零扩展**。
- 补码带符号数：高位补原符号位，称为**符号扩展**。

> [!example] 16 位到 32 位
> 16 位位模式 `8000`：
>
> - 当作 `unsigned short` 的数值 $32768$，零扩展后为 `00008000`。
> - 当作 `short` 的数值 $-32768$，符号扩展后为 `FFFF8000`。
>
> 两种转换都保持各自的真值不变，但得到的 32 位编码不同。

### 5. 位截断

截断指只保留低 $n$ 位。对于无符号整数目标类型，转换结果按对应模数计算。例如：

```c
#include <stdint.h>

uint32_t wide = 0x12345678U;          // 原始32位值
uint16_t narrow = (uint16_t)wide;    // 转为16位无符号整数，结果为0x5678
uint32_t again = (uint32_t)narrow;   // 再次扩展，结果为0x00005678
```

**信息丢失不可逆**：从 `0x12345678` 截断为 `0x5678` 后，再零扩展也无法恢复原来的高 16 位。

## 九、整数加减法、ALU 与条件标志

### 1. 加法器怎样实现减法

在固定 $n$ 位宽的补码加减法器里，一般设置控制信号 `Sub`：

$$
F=A+(B\oplus \mathrm{Sub})+\mathrm{Sub}\pmod{2^n}.
$$

这里 `Sub` 作为单比特信号扩展到整个 $B$ 的各位：

- `Sub = 0`：$B$ 保持不变，进位输入为 0，实现 $A+B$。
- `Sub = 1`：$B$ 全部取反，进位输入为 1，实现 $A+\overline B+1=A-B$。

ALU（算术逻辑部件）以加/减法器为核心，还能执行按位与、或、非、异或等操作，所执行功能由控制信号 `ALUop` 决定。

### 2. n 位加法器除了结果，还要输出标志

| 条件标志 | 英文名 | 核心含义 |
| --- | --- | --- |
| `ZF` | Zero Flag | 结果的 n 位全部为 0 则为 1 |
| `SF` | Sign Flag | 结果最高位，用于补码结果的符号解释 |
| `CF` | Carry Flag | 加法时的最高位进位；在课程所述加/减单元中，减法时表示借位 |
| `OF` | Overflow Flag | **有符号运算结果超出可表示范围** |

对于课程中的加减运算器，设 `Cout` 为最高位进位输出，`Cin` 为加减控制输入，则：

$$
\boxed{\mathrm{CF}=C_{out}\oplus\mathrm{Sub}}.
$$

对 n 位带标志加法器：

$$
\boxed{\mathrm{OF}=C_n\oplus C_{n-1}},\qquad
\boxed{\mathrm{SF}=F_{n-1}}.
$$

如果结果每一位都为 0，则 `ZF=1`；否则 `ZF=0`。其中 $C_{n-1}$ 是进入符号位的进位，$C_n$ 是离开符号位的进位。

> [!important] CF 与 OF 绝不是同一个标志
> **CF 判断无符号加法越界或无符号减法借位；OF 判断补码带符号加减是否越界。** 同一组输入位模式下，CF 和 OF 可能不一致，这是正常现象。

### 3. 有符号加法的溢出规则

**两个同号整数相加，结果却变成异号，表示溢出。**

$$
\boxed{\mathrm{OF}_{add}=(s_A=s_B)\land(s_F\ne s_A)}.
$$

> [!example] 8 位加法 $107+46$
> $$
> \begin{aligned}
> 107&=(01101011)_2,\\
> 46&=(00101110)_2,\\
> \text{低8位和}&=(10011001)_2.
> \end{aligned}
> $$
>
> - 作为**无符号整数**：结果 $153$ 在 $0\sim255$ 内，`CF=0`，结果正确。
> - 作为**补码整数**：位模式 `10011001` 表示 $-103$，但真实和为 $153>127$，所以 `OF=1`。
> - 其他标志：`SF=1`、`ZF=0`。

### 4. 有符号减法的溢出规则

减法中，**两个异号整数相减，结果的符号却与被减数不同，表示溢出**。

$$
\boxed{\mathrm{OF}_{sub}=(s_A\ne s_B)\land(s_F\ne s_A)}.
$$

例如在 4 位模型中：$-7-6=-13$ 超出 $[-8,7]$，低四位被解释为 $+3$，发生负向溢出。而 $-3-5=-8$ 刚好在范围内，没有溢出。

### 5. 借助标志位完成比较

比较 `a` 与 `b` 时，可通过执行机器级减法 `a-b` 并检查条件标志：

| 比较（减法后） | 条件 |
| --- | --- |
| 无符号 `a < b` | `CF=1` |
| 无符号 `a == b` | `ZF=1` |
| 无符号 `a > b` | `CF=0` 且 `ZF=0` |
| 有符号 `a < b` | `SF != OF` |
| 有符号 `a == b` | `ZF=1` |
| 有符号 `a > b` | `SF == OF` 且 `ZF=0` |

> [!warning] 为什么有符号比较不能只看 SF？
> 因为减法可能溢出。例如 4 位补码中，$-7-6$ 的低 4 位是 `0011`，`SF=0`，若只看结果为正，就会误认为 $-7>6$；结合 `OF=1`，可得到 `SF != OF`，正确判断 $-7<6$。

### 6. 在 C 中安全检查加法溢出

可以用 `unsigned` 的取模性质检测**无符号溢出**：

```c
int uadd_ok(unsigned x, unsigned y) {
    unsigned sum = x + y; // 无符号加法即使越界也有定义，按模数回绕
    return sum >= x;      // 回绕后sum变小，则说明数学和已超出范围
}
```

对于 `int`，必须**在相加之前**检查，否则先执行 `x+y` 可能已经触发有符号溢出的未定义行为：

```c
#include <limits.h>

int sadd_ok(int x, int y) {
    if (y > 0 && x > INT_MAX - y) return 0; // y为正时防正向溢出
    if (y < 0 && x < INT_MIN - y) return 0; // y为负时防负向溢出
    return 1;                              // 其余情况可以安全相加
}
```

检查后才执行 `x+y`：

```c
if (sadd_ok(x, y)) {    // 先验证结果可表示
    int sum = x + y;    // 只有在安全时才计算
}
```

> [!warning] 一个常见但不安全的教学写法
> `int sum=x+y;` 然后用“两个正数相加却变成负数”等条件检查溢出，是硬件标志位层面的直观描述，**不能直接当作标准 C 的通用无溢出检测方法**，因为计算 `sum` 时可能已发生未定义行为。

### 7. 在 C 中安全检查减法溢出

不建议把减法问题简单改写成 `x + (-y)`，因为当 `y == INT_MIN` 时，`-y` 本身就可能溢出。

```c
#include <limits.h>

int ssub_ok(int x, int y) {
    if (y < 0 && x > INT_MAX + y) return 0; // 减负数可能正向溢出
    if (y > 0 && x < INT_MIN + y) return 0; // 减正数可能负向溢出
    return 1;                              // 可以安全计算x-y
}
```

验证可见：`ssub_ok(INT_MIN, INT_MIN)` 返回 1，因为差为 0；`ssub_ok(INT_MIN, 1)` 返回 0，因为差超出范围。

### 8. 从 C 表达式到机器指令

例如：

```c
int result = (g + h) - (i + j); // 两次求和，再计算两者之差
```

编译器通常会安排寄存器和若干条算术指令，完成 `g+h`、`i+j` 以及相减。若采用 MIPS 这样的 RISC 架构，可能形成类似 `add`、`add`、`sub` 的指令序列。

> [!note] 指令级与源代码级语义
> 不同 ISA 对溢出的指令行为可能不同，有的提供“陷阱”指令，有的只给出低位结果与标志，有的使用不同指令处理带符号和无符号操作。源代码与汇编代码的对应关系还受优化选项和编译器影响，不能保证每个 C 表达式都固定变成某一种指令序列。

## 十、整数乘法：高位、溢出与常数优化

### 1. n 位相乘为何会得到 2n 位结果

两个 n 位无符号整数的最大值均为 $2^n-1$，乘积接近 $2^{2n}$，通常需要多达 $2n$ 位才能完整保存。

硬件可能先形成较宽乘积，再由指令或程序保留低 n 位；一些指令还能分别访问乘积的高 n 位和低 n 位。

> [!example] 4 位补码中的 $5\times5$
> 数学结果是 $25=(00011001)_2$，需要 8 位才能完整表示。
>
> 若只保留低 4 位，得到 `1001`，按 4 位补码解释为 $-7$。这说明低位截断可能让两个正数的乘积变成负数。

### 2. 无符号与有符号乘法的低位相同

如果两个乘数有**相同的 n 位原始位串**，分别把它们当作 n 位无符号整数或 n 位补码有符号整数，所得乘积的**低 n 位总是相同**，因为两者都在模 $2^n$ 的意义下运算。

区别在于：

- 完整的 $2n$ 位乘积可能不同；
- 相同的低 n 位可能代表不同真值；
- 带符号和无符号乘法的溢出判断标准不同。

> [!important] 乘法是否溢出的硬件判据
> 已得到完整的 $2n$ 位乘积：
>
> - **无符号乘法**：高 n 位全为 0，才说明结果能放进 n 位。
> - **补码乘法**：高 n 位必须全部等于低 n 位的最高位，才说明完整乘积是低 n 位的正确符号扩展。

### 3. 乘法器为什么可以由加法器构造

手算二进制乘法的每一行部分积，是根据乘数对应位是否为 1，决定是否加入被乘数的某个移位形式。

例如：

$$
13\times11=13\times(8+2+1)=13\times8+13\times2+13.
$$

因此可以用**判断乘数位 → 形成部分积 → 加法累加 → 移位**的方式构造无符号乘法器。补码乘法还要处理符号，可以使用 Booth 等算法；阵列乘法器则安排大量部分积单元和加法单元并行运算。

> [!note] Booth 算法的思路
> Booth 方法利用乘数相邻位的变化，把连续的一串 1 转换成更简洁的加/减部分积操作。其目标是让补码正负乘数都能统一处理。该算法在这里作为理解“带符号乘法也可归结为移位与加减”的补充，不需要把每一步电路细节与普通 C 乘法混在一起。

### 4. 变量乘常数：移位与加减

例如

$$
20x=(16+4)x=2^4x+2^2x.
$$

对应的无符号 C 表达式：

```c
unsigned mul20(unsigned x) {
    return (x << 4) + (x << 2); // 16x + 4x；无符号结果按模数计算
}
```

编译器有时会采用移位与加减组合，代替整数乘法指令。但现代处理器的乘法指令性能已很强，**是否真的更快应由目标 CPU 与编译器决定**，不宜手工替换所有乘法。

> [!warning] 对有符号整数不可随便替换
> `x * 20` 与 `(x << 4) + (x << 2)` 在数学上等价，但 C 语言中若 `x` 为负数，或中间运算溢出，后者可能引入未定义行为。教学中的位模式等价不能直接升级为“对所有 int 输入都可安全替换”。

### 5. 乘法溢出为何可能变成安全漏洞

设要申请能存放 `count` 个整数的内存，字节数为

$$
\mathrm{bytes}=\mathrm{count}\times\mathrm{sizeof(int)}.
$$

如果 `count` 很大，乘积在无符号 `size_t` 中可能回绕成一个很小的值，从而导致程序申请的内存比实际所需少。随后按 `count` 个元素写入，就可能产生**堆缓冲区越界**。

```c
#include <stdint.h>
#include <stdlib.h>

int *allocate_ints(size_t count) {
    if (count > SIZE_MAX / sizeof(int)) { // 先检验乘法是否会超出size_t范围
        return NULL;                      // 会溢出时拒绝申请
    }
    return malloc(count * sizeof(int));  // 通过检查后再计算所需字节数
}
```

对申请成功后的内存，还必须保证输入数组合法、循环索引与元素数量匹配，并适时释放内存。

> [!important] 防止溢出的通用技巧
> **先除法检查边界，再做乘法**。无符号数中，若 $b\ne0$，条件 $a>\mathrm{MAX}/b$ 意味着 $a\times b$ 将超出最大可表示值。

### 6. 为什么不能先算 `x*y` 再除回去判断

有一种直观想法：求 `z=x*y`，再检查 `z/x==y`。它的问题是：**带符号乘法可能已发生未定义行为**；并且还需处理 `x=0`。安全检查不能依赖一个可能已越界的中间结果。

## 十一、整数除法与右移优化

### 1. 商与余数

对两个整数 $a,b$（$b\ne0$），有

$$
a=bq+r.
$$

在 C99 及后续主流 C 标准中，整数除法的商**向零截断**：

$$
7/2=3,\qquad -7/2=-3.
$$

余数满足 $a=(a/b)\times b+a\%b$，且非零余数的符号与被除数相同。

```c
int a = -7;          // 被除数是负数
int q = a / 2;       // 向零截断，q=-3
int r = a % 2;       // 余数r=-1，满足-7=(-3)*2+(-1)
```

### 2. 整数除法的两类特殊错误

1. **除数为 0**：整数除法无数学意义，C 表达式的行为未定义，某些 CPU/操作系统组合可能报告除法异常。
2. **最小负整数除以 -1**：对 n 位补码整数，$-2^{n-1}/(-1)=2^{n-1}$，无法用同宽带符号整数表示。

```c
#include <limits.h>

int divide_ok(int a, int b) {
    if (b == 0) return 0;                  // 禁止整数除0
    if (a == INT_MIN && b == -1) return 0; // 防止最小负数除以-1溢出
    return 1;                              // 其余组合可以计算int商
}
```

> [!warning] 常量优化也可能改变表面上的异常表现
> 编译器可以对常量除法做优化；如果源程序本来就有未定义行为，不能据此要求编译器一定生成一条会报错的除法指令。源代码的可移植正确性与某次反汇编、某次运行结果必须区分。

### 3. 用右移处理除以 $2^k$

对非负整数，右移 $k$ 位直接对应整数除以 $2^k$ 并向下取整。对**负的补码整数**，如果硬件采用算术右移，简单右移通常相当于向负无穷取整，与 C 的**向零截断**不同。

> [!example] 负数不能直接右移代替整数除法
> $$
> -14/4=-3.
> $$
>
> 但典型的算术右移 `-14 >> 2` 得到 $-4$。为了获得向零截断的商，可先加偏置 $2^2-1=3$：
>
> $$
> \left\lfloor\frac{-14+3}{4}\right\rfloor=-3.
> $$

在假定 32 位补码、负数右移为算术右移的教学模型中：

$$
\boxed{\operatorname{trunc}(x/2^k)=\big(x+[x<0](2^k-1)\big)\gg k}
$$

式中 $[x<0]$ 为条件成立时取 1、否则取 0 的指示值。

### 4. 使用 32 位算术右移完成除以 32

下面的实现仅适用于**假定 `int` 为 32 位，且负数右移执行算术右移**的目标环境：

```c
int div32_machine(int x) {
    int bias = (x >> 31) & 31; // x为负时得到31，非负时得到0
    return (x + bias) >> 5;    // 先纠偏，再算术右移5位
}
```

> [!note] 为什么先加偏置不会溢出？
> 若 $x<0$，则 $x+31\le30$ 且不会超过 `INT_MAX`；若 $x\ge0$，偏置为 0。因此这个公式在假设的补码宽度下不会因纠偏产生带符号溢出。

但这**不是不依赖平台的标准 C 写法**。如果只想正确求商，直接使用 `x / 32` 最清楚，由编译器决定怎样优化：

```c
int div32(int x) {
    return x / 32; // C99及以后按向零截断，编译器可优化为适当的移位序列
}
```

### 5. 移位优化的适用边界

- 无符号数除以 $2^k$，通常可直接逻辑右移。
- 有符号非负整数除以 $2^k$，可直接右移。
- 有符号负数除以 $2^k$，要考虑舍入方向。
- 对非 $2^k$ 的常量除数，编译器还可能采用常量乘法、额外移位与纠偏来实现。

> [!tip] 判断题速记
> **乘 $2^k$ 要先考虑溢出；除 $2^k$ 要先考虑舍入。** 这两句话分别抓住了整数乘除法被移位优化时最容易忽略的正确性条件。

## 十二、浮点数的运算、舍入与精度问题

### 1. 为什么浮点加减法需要“对阶”

设两数为

$$
A=M_A2^{E_A},\qquad B=M_B2^{E_B}.
$$

假定 $E_A\ge E_B$，则

$$
A+B=\left(M_A+M_B2^{E_B-E_A}\right)2^{E_A}.
$$

这意味着先让两个数的指数相同，**小指数对应的尾数要向右移**。若直接加尾数而不处理指数，计算结果就没有正确的数值意义。

> [!important] 浮点加减运算的标准流程
> **求阶差 → 对阶 → 尾数加减 → 规格化 → 舍入 → 检查结果类别与异常。**

#### 第一步：求阶差

比较两个指数，得到 $\Delta E=|E_A-E_B|$。

#### 第二步：对阶

将指数较小者的尾数右移 $\Delta E$ 位，使两数的指数相同。被移出的有效低位不能简单全部遗忘，否则可能影响最后的正确舍入。

#### 第三步：尾数加减

根据两个数的符号，进行有效数字的加法或减法。

#### 第四步：规格化

- **左规**：若有效数字的最高有效位置未出现期望的 `1`，则左移尾数、减小指数。
- **右规**：若尾数加法产生最高位进位，则右移尾数、增大指数。两个小于 2 的规格化正尾数相加，结果小于 4，因此这种直接加法后通常只需右规一次。
- 指数不能无限增减：必要时形成非规格化数、无穷大或其他特殊结果。

#### 第五步：舍入

将中间结果按目标浮点格式能保存的有限有效位数舍入。

### 2. 完整演示：$0.5+(-0.4375)$

先转换成二进制规格化形式：

$$
0.5=(1.000)_2\times2^{-1},
$$

$$
-0.4375=-(1.110)_2\times2^{-2}.
$$

**对阶**：把第二个数转换为指数 $-1$：

$$
-(1.110)_2\times2^{-2}=-(0.111)_2\times2^{-1}.
$$

**尾数相减**：

$$
(1.000-0.111)_2\times2^{-1}=(0.001)_2\times2^{-1}.
$$

**左规**：

$$
(0.001)_2\times2^{-1}=(1.000)_2\times2^{-4}.
$$

所以

$$
\boxed{0.5-0.4375=2^{-4}=0.0625}.
$$

> [!example] “大数吃小数”
> 对精度固定的浮点数，如果两个数的指数差距很大，较小数对阶后可能完全落入可保存有效位之外。这样即使较小数不为 0，浮点计算也可能得到 `大数 + 小数 == 大数`。
>
> 是否完全被“吃掉”由指数差、尾数以及舍入模式共同决定，不能只机械记住一个指数差阈值。

### 3. 保护位、舍入位与粘滞位

为避免对阶和中间运算过早丢失信息，通常使用附加信息位：

- **G（Guard，保护位）**：目标保留尾数之后的第一位。
- **R（Round，舍入位）**：G 后的第二位。
- **S（Sticky，粘滞位）**：再往后所有被移出位的逻辑或；只要其中有一位为 1，S 就为 1。

例如只保留若干位有效数字时，若被舍弃的二进制部分是 `100100...`，G=1、R=0、S=1，这表示被舍弃部分**严格大于半个最小保留单位**。

> [!note] 为什么 S 位重要
> 仅保存 G、R 而不跟踪更低位，有时无法区分“刚好一半”和“比一半稍大”。学习 IEEE 754 正确舍入时，使用 **G、R、S** 更容易避免误判。

### 4. IEEE 754 的四种常用舍入方向

| 舍入方式 | 规则 |
| --- | --- |
| 就近舍入，遇正中间值取偶数 | 选择最接近的可表示数；若恰好居中，选末位为偶的结果 |
| 朝 $+\infty$ 舍入 | 选择不小于精确结果的最小可表示数 |
| 朝 $-\infty$ 舍入 | 选择不大于精确结果的最大可表示数 |
| 朝 0 舍入 | 舍去多余有效位，结果向 0 靠近 |

IEEE 754 中最常使用的是**就近舍入，正中间值取偶数**（round to nearest, ties to even）。

> [!example] 十进制舍入到两位小数
> - `2.344` → `2.34`：距离 2.34 更近。
> - `2.346` → `2.35`：距离 2.35 更近。
> - `2.345` → `2.34`：恰好位于中间，保留数位 `4` 为偶数。
> - `2.355` → `2.36`：恰好位于中间，保留数位 `6` 为偶数。
>
> 这里讨论的是**十进制的概念演示**；实际二进制浮点数应判断它对应的准确二进制位置，而不能只看十进制打印出来的小数尾数。

### 5. 浮点乘法与除法

若 $A=M_A2^{E_A}$、$B=M_B2^{E_B}$，则

$$
\boxed{A\times B=(M_A\times M_B)\times2^{E_A+E_B}}
$$

$$
\boxed{A/B=(M_A/M_B)\times2^{E_A-E_B}}
$$

运算后还需要规格化、舍入，并处理零、无穷大、NaN、指数上下溢等情况。

与加减不同，乘除通常无需像相加那样“对阶”。但如果直接对**存储的偏置阶码**做加减，必须正确处理 bias。例如规格化数相乘时，存储阶码相加之后还要减去一次 bias 才是目标存储阶码。

### 6. 上溢、下溢与尾数溢出的区别

| 情况 | 含义 | 可能处理结果 |
| --- | --- | --- |
| 指数上溢 | 精确结果过大，超出格式有限范围 | 无穷大或按舍入模式得到最大有限数等 |
| 指数下溢 | 结果非常接近零 | 非规格化结果或零，并可能置异常标志 |
| 尾数产生进位 | 计算中有效数字超出当前规格化形式 | 右规后调整指数，不一定是真正的数值上溢 |
| 规格化需左移 | 计算结果最高有效位发生变化 | 左规并减小指数，直到符合目标格式 |

> [!warning] “尾数进位”不等于“浮点数超出表示范围”
> 两个 1.x 形式的有效数字相加产生 10.x，首先只需要右移尾数并增大指数；只有新指数超过允许范围，才可能形成指数上溢。

### 7. 有效位数变化与数值转换

在常见 IEEE binary32/binary64 的环境中：

- **`int` → `float`**：如果整数有效二进制位数多于 24 位，可能舍入；并非全部 32 位整数都能被 float 精确表示。
- **`int` → `double`**：典型 32 位整数都能被 53 位有效精度的 binary64 精确表示。
- **`float` → `double`**：所有有限 binary32 数值通常可精确保留（转换精度足够）。
- **`double` → `float`**：可能舍入、溢出或下溢。
- **`float/double` → 整数**：舍弃小数部分，向 0 截断；如果整数目标类型无法表示截断后的值，在 C 中结果可能为未定义行为。

```c
int x = 16777217;       // 超过单精度连续精确表示整数的范围
float f = (float)x;     // 常见binary32就近舍入为16777216
int y = (int)f;        // y=16777216，不等于原来的x
```

这是因为 binary32 有 24 位有效精度，可以精确表示 $2^{24}$，但无法保证精确表示 $2^{24}$ 之后的**每个**整数。

### 8. 浮点算术的结合律不一定成立

数学上的加法满足 $(x+y)+z=x+(y+z)$；浮点运算每步可能舍入，因此结果不一定相同。

> [!example] 结合律失效
> 以单精度量级为例：
>
> $$
> x=-1.5\times10^{38},\quad y=1.5\times10^{38},\quad z=1.
> $$
>
> $(x+y)+z$：先将大数正负相消，得到接近 $1$ 的结果。
>
> $x+(y+z)$：`y+z` 中的 1 因精度不足可能被舍掉，最终得到 0。
>
> 因此两种结合顺序会给出不同结果。

### 9. 常见浮点比较陷阱

- `0.1 + 0.2 == 0.3` 在典型 binary64 环境下通常为假，因为各操作数及结果的近似舍入不同。
- 对 NaN 而言，`NaN == NaN` 为假，常规大小比较也无法按普通实数全序理解。
- 负的非零有限数乘以 2 可能变得更负，也可能因舍入/下溢产生需要特别处理的边界结果。
- `d*d >= 0.0` 在 IEEE 非陷阱浮点模型中，若 `d` 为普通有限数则成立，但若 `d` 是 NaN 则比较为假。
- `(d+f)-d == f` **不一定**成立，因为 `d+f` 可能先舍掉了 `f` 的有效部分。

> [!tip] 浮点比较的一般处理原则
> 在需要比较计算得到的近似浮点数时，应依据业务含义选择绝对误差、相对误差或 ULP 容差；不要机械地使用一个固定 `1e-6` 处理全部量级，也不要对本应精确的整数计数滥用浮点容差。

### 10. `printf` 显示精度不等于实际保存精度

```c
#include <stdio.h>

int main(void) {
    float a = 123456.789e4f;         // 单精度需将原始数值舍入到可表示数
    double b = 123456.789e4;        // 双精度通常可保留这一整数的精确值
    printf("float  = %.0f\n", (double)a); // float经默认实参提升后打印
    printf("double = %.0f\n", b);        // 打印double
    return 0;
}
```

在典型 IEEE binary32/binary64 环境下，分别输出约 `1234567936` 和 `1234567890`。区别来自**浮点数可表示精度**，不是 `printf` 无故修改了变量值。

## 十三、精度与类型转换的实际案例

### 1. Ariane 5 火箭：浮点数转整数的范围风险

课件介绍的阿丽亚娜 5（Ariane 5）火箭事故发生在 1996 年 6 月 4 日。案例所强调的问题是：系统把某个 64 位浮点数转换为 16 位有符号整数时，数值超出后者可表示范围，由此引发异常以及后续控制问题。

16 位补码有符号整数的取值范围只有

$$
-32768\le x\le32767.
$$

如果浮点数超过这个范围，不能认为“转换后只损失几个小数位”；可能是**量级和表示范围完全不匹配**。

> [!warning] 核心教训：复用程序不等于复用数值范围假设
> 旧系统中对变量最大值作出的合理假设，换成更高性能的新设备后可能失效。应在类型转换前验证范围，并明确异常处理，而不是让溢出后果取决于偶然的机器行为。

```c
#include <limits.h>
#include <math.h>

int double_to_int_ok(double x) {
    if (!isfinite(x)) return 0;          // 排除NaN和正负无穷大
    if (x < (double)INT_MIN) return 0;   // 低于int表示下界，拒绝转换
    if (x >= (double)INT_MAX + 1.0) return 0; // 超过最大可截断到int的范围
    return 1;                            // 可安全地向0截断并转换为int
}
```

这段代码以常见 32 位 `int` 与 IEEE binary64 模型为直观背景；跨平台代码还应根据具体整数范围、浮点范围与转换规范核实边界。

### 2. 爱国者导弹案例：小误差乘以长时间

课件介绍：爱国者系统用时钟计数器记录时间，每隔 $0.1$ 秒计数一次；若把 0.1 近似编码为二进制定点小数，每次转换时间就存在微小误差。运行时间越长，误差可能越明显。

课件给出的某个**截断定点表示**满足每个计数周期的误差约为

$$
\varepsilon\approx9.54\times10^{-8}\ \mathrm s.
$$

连续运行 100 小时，计数次数为

$$
N=100\times60\times60\times10=3.6\times10^6.
$$

累计计时偏差约为

$$
\Delta t=N\varepsilon\approx0.343\ \mathrm s.
$$

若目标以 $2000\ \mathrm{m/s}$ 运动，则距离偏差估算为

$$
\boxed{\Delta s\approx2000\times0.343\approx686\ \mathrm m.}
$$

以上是课件使用的简化误差模型，强调固定小误差随大量重复计数而积累的危险。

### 3. 比较不同编码方式的误差

对于二进制无限循环数 $0.1$，**保留多少位、采用截断还是舍入到最近数**都会影响误差。

- 课件中使用的截断式定点小数近似会产生累计计时偏差。
- 若采用不同位数的定点数，并适当舍入，误差可能变小。
- 使用 IEEE 754 binary32 并不意味着 $0.1$ 可以被精确保存，其常见实际存储值为

$$
0.1_f=0.100000001490116119384765625.
$$

因此实际单精度中，单次 `0.1f` 表示误差的绝对值约为

$$
|0.1_f-0.1|\approx1.4901161\times10^{-9}.
$$

> [!warning] 注意舍入方式的差别
> 课件中也演示了“截去尾数低位”的 `float` 近似计算；其误差估算不应直接当成 IEEE 754 默认**就近舍入**对 `0.1f` 的实际误差。计算机保存 `0.1f` 通常得到 `0x3DCCCCCD`，而不是仅凭截断得到的相邻较小值。

如果仅沿用上一节的“单次固定误差 × 计数次数”模型，而不模拟实际系统其他误差，`0.1f` 这一舍入误差对应的 100 小时累计量级约为 $0.00536$ 秒。这个数只是帮助比较表示误差的**理想化量级估算**，不等于某次真实系统失误的完整重现。

### 4. 什么时候应该考虑定点数

当业务中的数据具有固定的比例系数时，采用整数保存放大后的值，再通过约定缩放比例进行计算，有时比浮点数更适合。

例如用“分”而不是“元的小数”记录货币金额；测量值也可依据允许精度保存为整数量化值。

> [!tip] 选择数据表示方式的三个问题
> **范围是否足够？精度是否足够？误差是否会累积？** 这是选择 `int`、`float`、`double` 或定点比例编码时最应先回答的问题。

## 十四、典型练习与参考解答

### 练习 1：进制与小数

**题目**：将 $(101101.101)_2$ 转为十进制；将 $(0.625)_{10}$ 转为二进制。

> [!example] 参考解答
> $$
> (101101.101)_2=32+8+4+1+\frac12+\frac18=45.625.
> $$
>
> $$
> (0.625)_{10}=\frac12+\frac18=(0.101)_2.
> $$

### 练习 2：8 位补码求值

**题目**：`11101101` 作为 8 位无符号数和 8 位补码有符号数分别表示什么？

> [!example] 参考解答
> 无符号值为 $128+64+32+8+4+1=237$；补码值为 $237-256=-19$。
>
> **一个位串，两个真值**，区别只在解释规则。

### 练习 3：符号扩展与零扩展

**题目**：16 位机器数 `0xFF80` 被扩展成 32 位时，零扩展和符号扩展得到什么？

> [!example] 参考解答
> 零扩展为 `0x0000FF80`；符号扩展为 `0xFFFFFF80`。
>
> 前者保持无符号真值 $65408$，后者保持有符号真值 $-128$。

### 练习 4：大小端存储

**题目**：将 `0xABCDEF12` 存在地址 `0x2000` 起，分别写出小端与大端的四个字节。

> [!example] 参考解答
> - 小端、低地址到高地址：`12 EF CD AB`。
> - 大端、低地址到高地址：`AB CD EF 12`。

### 练习 5：带符号与无符号溢出

**题目**：8 位机器中计算 `127 + 1`，分析两个解释下的结果，以及 `OF`、`CF`。

> [!example] 参考解答
> 机器位计算为 `01111111 + 00000001 = 10000000`。
>
> - 作为无符号数：$127+1=128$，仍在范围内，因此 `CF=0`。
> - 作为补码有符号数：$128$ 超出上界 $127$，结果位模式解释为 $-128$，因此 `OF=1`。
> - `SF=1`、`ZF=0`。

### 练习 6：位掩码与逻辑表达式

**题目**：若 `x=0x9AC7`，求 `x & 0x00FF`、`x >> 8`，并解释 `2 & 4` 与 `2 && 4` 的结果。

> [!example] 参考解答
> - `x & 0x00FF` 为 `0x00C7`，提取低字节。
> - `x >> 8` 为 `0x9A`（按无符号数据解释）。
> - `2 & 4` 为 0，因为位模式没有共同的 1。
> - `2 && 4` 为 1，因为两操作数都非零。

### 练习 7：浮点编码拆解

**题目**：解释 binary32 位串 `0 | 01111111 | 10000000000000000000000`。

> [!example] 参考解答
> $S=0$；阶码为 $127$，真实指数 $E=0$；尾数有效数字为 $(1.1)_2=1.5$。
>
> 结果为 $\boxed{1.5}$，对应十六进制 `0x3FC00000`。

### 练习 8：最小负整数除以 -1

**题目**：在 8 位补码模型中，为什么 $-128/(-1)$ 会溢出？

> [!example] 参考解答
> 数学商为 $128$，但 8 位补码表示范围是 $[-128,127]$，因此 $128$ 无法表示。这与除数为 0 是两种不同错误。

### 练习 9：浮点加法对阶

**题目**：按二进制浮点形式计算 $1.0+0.25$。

> [!example] 参考解答
> $$
> 1.0=(1.0)_2\times2^0,\quad0.25=(1.0)_2\times2^{-2}.
> $$
>
> 对阶：$0.25=(0.01)_2\times2^0$。
>
> 尾数相加：$(1.00+0.01)_2\times2^0=(1.01)_2=1.25$。

### 练习 10：负数除以 4

**题目**：在 32 位补码、算术右移模型中求 $-15/4$，比较直接右移与纠偏右移。

> [!example] 参考解答
> C 整数除法为 $-15/4=-3$。
>
> 直接算术右移两位通常得到 $-4$；先加 $2^2-1=3$，再右移：$(-15+3)\gg2=(-12)\gg2=-3$。

## 十五、核心知识速查与易错点索引

### 1. 核心公式

| 知识点 | 速查公式/条件 |
| --- | --- |
| R 进制数值 | $V=\sum a_iR^i$ |
| n 位无符号范围 | $0\le x\le2^n-1$ |
| n 位补码范围 | $-2^{n-1}\le x\le2^{n-1}-1$ |
| n 位补码编码 | $[x]_{\rm 补}=x\bmod2^n$ |
| 补码减法 | $A-B=A+\overline B+1\pmod{2^n}$ |
| 有符号加法溢出 | 两个同号加数产生异号结果 |
| 有符号减法溢出 | 两个异号操作数之差与被减数异号 |
| 无符号加溢出 | 最高位产生进位，`CF=1` |
| 无符号减借位 | `CF=1`（本章所用减法标志约定） |
| 有符号小于比较 | `SF != OF` |
| 无符号小于比较 | `CF=1` |
| binary32 规格化数 | $(-1)^S(1+f)2^{e-127}$ |
| binary32 非规格化数 | $(-1)^Sf2^{-126}$ |
| 浮点乘法 | $(M_AM_B)2^{E_A+E_B}$ |
| 浮点除法 | $(M_A/M_B)2^{E_A-E_B}$ |
| 浮点加减法 | 对阶 → 尾数运算 → 规格化 → 舍入 |

### 2. 特别容易混淆的内容

> [!warning] 易错点清单
> 1. 机器数与真值不是一回事，必须明确位宽和编码方式。
> 2. 补码的负数按位取反加 1；正数补码与普通二进制编码相同。
> 3. 最高位进位 `CF` 和带符号溢出 `OF` 的含义不同。
> 4. C 有符号整数溢出不是标准意义上的“必然绕回”。
> 5. 负数算术右移与 C 的负数整数除法可能采用不同的舍入方向。
> 6. `short`、`char` 参与计算可能先发生整型提升。
> 7. `0x12345678` 以大小端存储时，变的是字节顺序，不是其数值。
> 8. `0.1f` 的机器值一般不是数学上精确的 $0.1$。
> 9. IEEE 754 指数全 0、全 1 分别具有特殊意义，不能按普通规格化数解码。
> 10. 浮点加减法先对阶；浮点乘除法进行尾数乘除及指数加减。
> 11. 浮点 NaN 不满足普通实数的比较规则。
> 12. 在 C 中用 `printf` 输出数据时，要保证格式说明符与实参类型匹配。

### 3. 推荐复习顺序

先掌握**进制与补码转换**，再理解**位宽、类型转换、内存存储**，然后学习**ALU 标志与整数溢出**。在这些基础上进入 **IEEE 754 字段编码**，最后练习**对阶、规格化、舍入及实际代码中的精度问题**。

> [!summary] 一句话串联全章
> 计算机用有限位二进制来表示数据，**编码决定含义，位宽决定范围，类型转换改变解释或精度，运算电路只处理位模式，语言规则决定程序能否安全依赖结果。**
