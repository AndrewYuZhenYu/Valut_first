## 一、从高级语言到机器程序

### 1.1 指令的不同层次

| 层次 | 含义 | 典型形式 | 特点 |
| --- | --- | --- | --- |
| 高级语言语句 | 以程序逻辑为中心的表达 | `x = a + b;` | 接近人的思维 |
| 汇编指令 | 机器指令的助记符表示 | `addl %ebx, %eax` | 依赖具体 ISA |
| 机器指令 | 处理器能够识别的编码 | 字节序列 `01 D8` | 由操作码等字段组成 |
| 微指令 | 微程序控制器使用的内部控制命令 | 控制信号的编码 | 属于特定硬件实现 |
| 伪指令／汇编器指示 | 汇编器处理的符号或扩展表示 | `.globl`、`.long` 等 | 不一定对应单条机器指令 |

**机器指令和汇编指令通常具有直接的编码对应关系**，但汇编器还可处理标签、伪指令、宏和指令别名，因此不能把每一行汇编源代码都理解为一条机器指令。

> [!note] 硬件—软件接口
> 指令集体系结构（ISA）规定软件可以使用哪些机器指令及寄存器等资源；处理器内部可以采用不同的硬件结构实现同一种 ISA。**汇编语言反映的是程序员可见的机器模型，并不等于 CPU 内部电路的全部细节。**

### 1.2 ISA 与 ABI 的分工

**ISA（Instruction Set Architecture，指令集体系结构）**主要规定：

- 指令集合、指令格式及操作数类型；
- 寄存器的名称、位宽和用途；
- 地址计算、寻址方式、字节顺序；
- 控制转移、标志位和程序计数器等程序员可见行为。

**ABI（Application Binary Interface，应用程序二进制接口）**则规定目标程序间必须遵守的约定，例如：

- 函数参数和返回值放在哪里；
- 哪些寄存器由调用者保存，哪些由被调用者保存；
- 栈如何组织和对齐；
- 基本数据类型的大小、结构体布局及目标文件接口。

> [!important] 一句话区分
> **ISA 决定“机器能够执行什么”，ABI 决定“不同机器代码模块怎样正确协作”。** 相同 ISA 上的 Linux 和 Windows 可以采用不同 ABI，尤其是 x86-64 函数传参规则。

### 1.3 源程序转换的四个阶段

以 GCC 工具链为例：

| 阶段 | 输入 → 输出 | 核心工作 |
| --- | --- | --- |
| 预处理 | `test.c` → `test.i` | 展开宏、处理 `#include` 等 |
| 编译 | `test.i` → `test.s` | 翻译、优化并生成汇编程序 |
| 汇编 | `test.s` → `test.o` | 编码为可重定位目标文件 |
| 链接 | `.o` + 库 → 可执行文件 | 解析符号、完成必要的重定位 |

一个可以直接练习的 C 程序：

```c
#include <stdio.h>                    // 声明 printf 函数

int add(int x, int y) {               // 定义加法函数
    int result = x + y;               // 将两个形参相加
    return result;                    // 返回求和结果
}

int main(void) {                       // 程序入口
    int value = add(125, 80);         // 调用 add，结果为 205
    printf("%d\n", value);           // 输出 205
    return 0;                         // 正常结束程序
}
```

分阶段查看生成文件：

```bash
gcc -E test.c -o test.i          # 只预处理
gcc -S test.c -o test.s          # 生成汇编文件
gcc -c test.c -o test.o          # 编译、汇编生成目标文件
gcc test.o -o test               # 链接成可执行文件
objdump -d test.o                # 反汇编可重定位目标文件
objdump -d test                  # 反汇编可执行文件
gcc -O1 test.c -o test           # 开启一级优化后重新生成
```

- `-E`：预处理后停止；`-S`：生成汇编后停止；`-c`：生成目标文件但不链接。
- `-o` 指定输出文件；`-O1` 和 `-O2` 指定不同优化级别。
- `objdump -d` 给出机器字节、地址和对应汇编指令。
- 要专门生成 32 位 x86 代码，可在支持相应工具链的环境中使用 `-m32`；**64 位编译器的默认输出未必与本章 IA-32 示例相同**。

> [!example] 为什么同一个函数反汇编地址不同？
> 在课件的示例中，`test.o` 中函数的指令地址可以从相对偏移 `0` 开始，而完成链接的可执行文件中则位于另外的地址（例如 `0x080483d4`）。原因是目标文件尚未完成最终的程序地址布局；链接器需要布置代码和数据并处理重定位。

### 1.4 ELF 文件、程序段与运行时地址空间

常见 ELF 节（section）的作用：

| 节 | 通常存放的内容 | 常见属性 |
| --- | --- | --- |
| `.text` | 可执行机器代码 | 可读、可执行 |
| `.rodata` | 字符串常量等只读数据 | 只读 |
| `.data` | 已初始化的可写全局／静态数据 | 可读写 |
| `.bss` | 未显式初始化或零初始化的全局／静态数据 | 运行时占用空间，通常不直接存储全部零字节 |
| `.symtab` | 符号表 | 支持链接和分析 |
| `.debug*` | 调试信息 | 非程序正常执行所必需 |

运行过程中，还会有 **栈（stack）**、**堆（heap）** 和共享库映射等区域：

- **栈**：服务于函数调用、返回地址以及部分局部变量；在典型 IA-32 用户进程布局中朝低地址方向增长。
- **堆**：供 `malloc` 等动态存储分配机制使用；并不是程序的一切动态数据都严格从单一地址向上顺序生长。
- **代码／只读数据／可写数据区**：通常由可执行文件的可加载段映射到进程虚拟地址空间。

> [!warning] 区分“节”与“段”
> ELF 的 **section** 便于链接与组织，**segment**（由程序头表描述）主要指导装载器映射程序。课件绘制的 `0x08048000`、`0xC0000000` 等是特定历史 IA-32/Linux 示例，不是现代系统上的固定地址；ASLR、PIE、系统位宽等都会改变实际布局。

### 1.5 机器数据的字节序：小端与大端

以 32 位数据 `0x12345678` 从低地址 `A` 开始存储为例：

| 地址 | 小端序（x86） | 大端序 |
| --- | --- | --- |
| `A` | `78` | `12` |
| `A+1` | `56` | `34` |
| `A+2` | `34` | `56` |
| `A+3` | `12` | `78` |

**小端序：最低有效字节在最低地址；大端序：最高有效字节在最低地址。** 字节序不改变抽象整数的数学值，只改变多字节对象在内存中的字节排列。

## 二、IA-32 机器模型、寻址与常用指令

### 2.1 IA-32 寄存器

典型 IA-32 通用寄存器：

| 32 位寄存器 | 传统用途 | 低位子寄存器 |
| --- | --- | --- |
| `EAX` | 累加器、整数返回值 | `AX`（低16）、`AH`／`AL`（AX 的高／低8） |
| `EBX` | 基址寄存器 | `BX`、`BH`／`BL` |
| `ECX` | 计数器 | `CX`、`CH`／`CL` |
| `EDX` | 数据寄存器 | `DX`、`DH`／`DL` |
| `ESP` | 栈顶指针 | `SP` |
| `EBP` | 典型栈帧基址指针 | `BP` |
| `ESI` | 源变址寄存器 | `SI` |
| `EDI` | 目标变址寄存器 | `DI` |

另外，`EIP` 指示指令执行位置，`EFLAGS` 保存条件码及控制标志，`CS`、`DS`、`SS`、`ES`、`FS`、`GS` 为段寄存器。

> [!example] 同一寄存器的不同部分
> 若 `EAX = 0x1234ABCD`，则 `AX = 0xABCD`、`AH = 0xAB`、`AL = 0xCD`。写入 `AL` 只修改 `EAX` 最低 8 位，不自动把剩余位清零。

### 2.2 常用操作数长度

| 后缀 | 操作数宽度 | 常见名称 | 示例 |
| --- | --- | --- | --- |
| `b` | 8 位 | 字节 | `movb` |
| `w` | 16 位 | 字 | `movw` |
| `l` | 32 位 | 双字 | `movl` |
| `q` | 64 位 | 四字 | `movq`（主要用于 x86-64） |

IA-32 中典型 i386 System V ABI 的数据宽度：

- `char`：1 字节；`short`：2 字节；`int`、`long`、指针：4 字节。
- `long long`、`double`：8 字节；`float`：4 字节。
- `long double`：使用扩展精度表示，存储尺寸及对齐依具体 ABI；课件采用传统 i386 的 12 字节存储槽示例。

> [!important] 字长 ≠ 所有类型的大小
> **IA-32 的 `long` 是 4 字节**；在常见 x86-64 Linux 的 LP64 数据模型下，`long` 是 8 字节，而常见 64 位 Windows 的 LLP64 模型下仍为 4 字节。不要根据“64 位系统”直接推断所有 C 类型的尺寸。

### 2.3 AT&T 与 Intel 汇编语法

本章默认使用 **AT&T 语法**：

| 方面 | AT&T | Intel |
| --- | --- | --- |
| 寄存器 | `%eax` | `eax` |
| 立即数 | `$5` | `5` |
| 源、目的顺序 | `源, 目的` | `目的, 源` |
| 数据长度 | 通常用后缀 `b/w/l/q` | 可使用 `BYTE PTR` 等 |
| 内存操作数 | `8(%ebp)` | `[ebp+8]` |

例如：

```asm
movl $5, %eax                 # EAX ← 5
movl 8(%ebp), %edx            # EDX ← 内存[EBP+8]中的4字节
movl %edx, -4(%ebp)           # 内存[EBP-4]中的4字节 ← EDX
addl %edx, %eax              # EAX ← EAX + EDX
```

> [!warning] 语法与操作数限制
> - `%eax` 表示寄存器；`(%eax)` 表示“以 EAX 中数值作为地址”的内存单元。
> - `$8` 是立即数 8；`8(%ebp)` 是内存地址 `EBP+8`。
> - 一般的 `mov` 指令**不能直接进行内存到内存的传送**，需要寄存器中转。
> - 两个显式寄存器操作数通常必须符合相同位宽要求。例如 `addl %dx, %ax` 不是合法的标准 IA-32 指令写法。

### 2.4 存储器寻址方式：核心计算公式

32 位 x86 的典型有效地址形式：

$$EA = B + I\times S + D$$

- $B$：基址寄存器的值；
- $I$：变址／索引寄存器的值；
- $S$：比例因子，只能是 **1、2、4、8**；
- $D$：位移量（常量，可正可负）。

AT&T 对应语法：`D(B,I,S)`。某些字段允许省略。

| 写法 | 有效地址 |
| --- | --- |
| `(%eax)` | `EAX` |
| `12(%ebp)` | `EBP+12` |
| `(%ebx,%ecx)` | `EBX+ECX` |
| `8(%ebx,%ecx,4)` | `EBX+ECX×4+8` |
| `100(,%esi,8)` | `100+ESI×8` |
| `-6(%ebx,%edi)` | `EBX+EDI−6` |

> [!example] 数组元素的实际地址
> 假定 `float a[100]` 的首地址为 `104`，`sizeof(float)=4`，则：
>
> $$\operatorname{addr}(a[i])=104+4i$$
>
> `a[99]` 的首地址是 `104+99×4=500`。**元素首地址是 500，不代表数组占用到地址 500 为止**；这个元素实际覆盖地址 500～503。

二维数组 `short b[4][4]` 若首地址为 `504`，每元素 2 字节，则行优先排列：

$$\operatorname{addr}(b[i][j])=504+(i\times4+j)\times2=504+8i+2j$$

例如 `b[3][2]` 地址为 `504+24+4=532`。

如果 EBP 保存预先算好的 `504+8i`，ESI 保存 `j`，可以写：

```asm
movw (%ebp,%esi,2), %ax      # AX ← b[i][j]，每个 short 为2字节
```

> [!note] 寻址公式为什么重要？
> 它是理解**数组索引、指针运算、结构体成员访问和循环遍历**的共同基础。汇编里的“乘 4、乘 8”往往表示元素所占的字节数，而不是随意的数学运算。

### 2.5 指令编码（理解结构，不强制死记）

IA-32 机器指令可包含以下组成部分：**前缀 → 操作码 → ModR/M → SIB → 位移量 → 立即数**；实际指令并非全部字段都存在。

- **操作码 Opcode**：说明执行哪种操作；部分编码位还规定操作方向或数据宽度。
- **ModR/M**：包含 `mod`、`reg/opcode`、`r/m` 字段，决定寄存器或内存操作数的编码方式。
- **SIB**：包含 `scale`、`index`、`base`，支持比例变址寻址。
- **位移量**：参与内存地址计算；**立即数**：直接参与操作的常数。
- **前缀**：如 `LOCK`、`REP`、`0x66`（操作数宽度覆盖）、`0x67`（地址宽度覆盖）。

> [!tip] 编码分析的合理深度
> 对 `movl 8(%ebp), %eax`，先识别“读取 EBP+8 的 4 字节到 EAX”，再分析对应 ModR/M 字段即可。除专门要求机器码编码的题目外，不必机械背诵所有编码表。

### 2.6 数据传送指令：MOV、扩展、LEA、PUSH/POP

**MOV：移动数据，而不是移动数据的物理位置。**

```asm
movl $100, %eax              # EAX ← 100
movl %eax, %edx              # EDX ← EAX
movb $0xFF, %al              # 仅把 EAX 的最低8位写为 FF
```

**符号扩展与零扩展：**

```asm
movsbl %al, %eax             # 把8位 AL 按有符号数扩展为32位
movzbl %al, %eax             # 把8位 AL 按无符号数扩展为32位
```

若 `AL = 0xFF`：`movsbl` 之后 `EAX = 0xFFFFFFFF`（有符号值为 -1）；`movzbl` 之后 `EAX = 0x000000FF`（值为 255）。

**LEA：计算有效地址，但不访问这个地址中的数据。**

```asm
leal 8(%ecx,%edx,4), %eax   # EAX ← ECX + EDX×4 + 8
movl 8(%ecx,%edx,4), %eax   # EAX ← 内存[ECX + EDX×4 + 8]的4字节
```

> [!important] `lea` 与 `mov` 的根本区别
> `lea` 取的是**地址表达式的计算结果**，`mov` 使用内存操作数时取的是**该地址上的数据**。编译器还经常利用 `lea` 完成不需要访存的整数加法或乘常数运算。

**栈的 PUSH/POP**（在 32 位操作数环境下）：

```asm
pushl %eax                    # ESP ← ESP-4，然后内存[ESP] ← EAX
popl %ebx                     # EBX ← 内存[ESP]，然后 ESP ← ESP+4
```

栈采用 ==后进先出 LIFO==，栈顶由 `ESP` 指示。注意：**栈和堆是不同的内存使用机制**，不能仅因中文“堆栈”一词而将二者混同。

### 2.7 整数算术：ADD、SUB、INC、DEC、NEG、CMP

| 指令 | 主要效果 | 说明 |
| --- | --- | --- |
| `addl S,D` | `D←D+S` | 更新算术标志 |
| `subl S,D` | `D←D−S` | 更新算术标志 |
| `incl D` | `D←D+1` | 不改变 `CF` |
| `decl D` | `D←D−1` | 不改变 `CF` |
| `negl D` | `D←−D` | 在固定宽度下取补码相反数 |
| `cmpl S,D` | 按 `D−S` 更新标志 | **不保存相减结果** |

```asm
movl $12, %eax               # EAX ← 12
addl $5, %eax                # EAX ← 17
subl $3, %eax                # EAX ← 14
cmpl $10, %eax               # 用 14-10 设置条件码，EAX仍为14
```

**无符号和有符号加减共用同一条加减法指令**；区别在于如何解释结果与条件码。32 位二进制 `0xFFFFFFFF` 可解释为无符号 `4294967295`，也可解释为有符号 `-1`。

### 2.8 乘法、除法及隐含寄存器

**乘法**：

- 单操作数 `mull SRC`、`imull SRC`：分别执行无符号／有符号乘法，另一乘数隐含在 `EAX`，64 位结果存入 `EDX:EAX`。
- 单操作数 8 位乘法：`AL × SRC`，16 位结果进入 `AX`。
- 双操作数 `imull SRC,DST`：有符号相乘，低位截断结果存 `DST`。
- 三操作数 `imull $IMM,SRC,DST`：以立即数乘 `SRC`，低位结果送 `DST`。

> [!example] 同一位模式，符号解释不同
> 已知 `AL = 0xB4`，`BL = 0x11`：
>
> - `mulb %bl`：按无符号数计算 $180\times17=3060$，结果 `AX = 0x0BF4`。
> - `imulb %bl`：按有符号数计算 $(-76)\times17=-1292$，结果 `AX = 0xFAF4`。
>
> 两种结果的**低 8 位都为 `F4`**；高 8 位因符号解释不同而不同。

**除法**：32 位 `divl SRC`／`idivl SRC` 使用 `EDX:EAX` 组成的 64 位被除数，商放 `EAX`、余数放 `EDX`。有符号除法须正确形成被除数的符号扩展，常见准备指令为 `cltd`（又称 `cdq`）。除数为 0 或商不能装入目标寄存器等情况可触发除法异常。

### 2.9 按位逻辑、测试和移位

| 指令 | 含义 | 典型用途 |
| --- | --- | --- |
| `andl` | 按位与 | 保留指定的位 |
| `orl` | 按位或 | 将某些位置 1 |
| `xorl` | 按位异或 | 取反指定的位、清零寄存器 |
| `notl` | 按位取反 | 逐位取反，不改变标志 |
| `testl` | 进行与运算，仅更新标志 | 判断某些位是否为 1 |
| `shll`／`sall` | 左移，低位补零 | 位操作和乘 2 的幂 |
| `shrl` | 逻辑右移，高位补零 | 无符号数右移 |
| `sarl` | 算术右移，高位补符号位 | 带符号数右移的机器实现 |
| `rol`／`ror` | 循环移位 | 位旋转 |

```asm
movl $0xF0, %eax             # EAX ← 11110000(二进制)
andl $0x0F, %eax             # EAX ← 0，低4位全为0
testl %eax, %eax             # 不改变 EAX，只更新标志（此时 ZF=1）
```

```asm
movw $0xFF80, %ax            # AX 的有符号值为 -128
sarw $1, %ax                 # 算术右移1位，AX=FFC0，即 -64
```

> [!warning] 汇编右移与 C 语言右移不完全等同
> `sar` 会复制最高符号位；但 C 中**负数的有符号右移**应按具体 C 标准版本及实现规定判断。不要用“汇编这样执行”推导所有 C 平台必然如此。C 的负数左移还涉及未定义行为风险，不能只用数学“乘 2”解释。

### 2.10 EFLAGS 条件码：读汇编最重要的基础

| 标志 | 含义 | 主要判断 |
| --- | --- | --- |
| `ZF` | Zero Flag，零标志 | 运算结果是否为零 |
| `SF` | Sign Flag，符号标志 | 运算结果的最高位是否为 1 |
| `CF` | Carry Flag，进位标志 | 无符号加法是否产生进位，减法是否借位 |
| `OF` | Overflow Flag，溢出标志 | 有符号运算是否发生溢出 |
| `PF` | Parity Flag，奇偶标志 | 结果低 8 位中 1 的个数是否为偶数 |
| `AF` | Auxiliary Carry Flag，辅助进位 | 特定低位进位／借位情况 |

关键区别：**`CF` 主要服务无符号运算，`OF` 主要服务有符号运算**。`ZF` 反映是否为 0；`SF` 只是结果符号位，不能独立决定有符号数大小关系。

> [!example] 精算条件码
> 初始 `AX=0xFFFA`（有符号 -6），`BX=0xFFF0`（有符号 -16），执行：
>
> ```asm
> addw %bx, %ax              # AX ← AX+BX，按照16位宽度保留结果
> ```
>
> 16 位结果 `AX=0xFFEA`（有符号 -22），`BX` 不变；`CF=1`、`OF=0`、`ZF=0`、`SF=1`。
>
> 解释：无符号整数加法超过 `65535`，所以有进位；有符号值 `-6 + (-16) = -22` 仍在 16 位有符号范围内，所以没有有符号溢出。

### 2.11 条件跳转：先弄清 CMP 的减法方向

执行 `cmpl B,A`，本质上是比较 **`A−B`** 并更新条件码。下面令 `A` 为目的操作数、`B` 为源操作数：

| AT&T 条件跳转 | 跳转条件 | 对应关系 |
| --- | --- | --- |
| `je`／`jz` | `ZF=1` | `A==B` |
| `jne`／`jnz` | `ZF=0` | `A!=B` |
| `ja` | `CF=0` 且 `ZF=0` | 无符号 `A>B` |
| `jae` | `CF=0` | 无符号 `A>=B` |
| `jb` | `CF=1` | 无符号 `A<B` |
| `jbe` | `CF=1` 或 `ZF=1` | 无符号 `A<=B` |
| `jg` | `ZF=0` 且 `SF=OF` | 有符号 `A>B` |
| `jge` | `SF=OF` | 有符号 `A>=B` |
| `jl` | `SF≠OF` | 有符号 `A<B` |
| `jle` | `ZF=1` 或 `SF≠OF` | 有符号 `A<=B` |

```asm
cmpl %edx, %eax             # 比较 EAX-EDX，设置 ZF、CF、SF、OF
jg greater_label             # EAX>EDX（按有符号数）才跳转
```

> [!warning] 课件条件跳转表存在需要纠正的条件
> 标准关系应为 `jae: CF=0`、`jb: CF=1`、`jge: SF=OF`、`jl: SF≠OF`。不能把它们误写成额外附加的 `ZF` 条件。背诵时以本表为准，尤其区分 `ja`／`jg`、`jbe`／`jle`。

此外，`jmp` 是无条件跳转；`setcc` 按条件把目标 **8 位**操作数写为 0 或 1；`call` 与 `ret` 用于函数调用及返回。

### 2.12 一个隐藏的越界陷阱：无符号比较

```c
int sum_array(const int a[], unsigned len) {
    int result = 0;                    // 保存累加和
    for (unsigned i = 0; i <= len - 1; ++i) { // len=0时有危险
        result += a[i];                // 可能访问有效范围外的元素
    }
    return result;                     // 返回累加结果
}
```

当 `len=0` 时，`len-1` 在 32 位 `unsigned` 下得到 `0xFFFFFFFF`，初始 `i=0` 会满足无符号 `i<=len-1`，导致越界访问。

可以联系底层指令理解：

```asm
subl $1, %edx               # 若 EDX=0，则变成 FFFFFFFF
cmpl %edx, %eax             # 计算 EAX-EDX 设置标志
jbe loop_body                # 按无符号 <= 判断，EAX=0时会跳转
```

**正确的源代码修改方式是改写条件，而不是仅把 `unsigned` 改成 `int`：**

```c
int sum_array(const int a[], unsigned len) {
    int result = 0;                    // 保存累加结果
    for (unsigned i = 0; i < len; ++i) { // 用严格小于避免 len-1 下溢
        result += a[i];                // 只在有效索引范围内读取
    }
    return result;                     // 返回累加和
}
```

> [!important] 核心思路
> 不仅要知道 `jbe` 和 `jle` 的区别，还要知道**为什么编译器选择某种比较**：高级语言操作数的类型和通常算术转换规则，会影响机器层面选择无符号还是有符号条件跳转。

### 2.13 浮点运算与 SIMD 的基础

课件同时介绍了两套常见的浮点运算路径：

- **x87 FPU**：拥有 `ST(0)`～`ST(7)` 的浮点寄存器栈，寄存器内部可使用 80 位扩展精度格式。`flds`／`fldl` 从内存装入单精度／双精度数据；`fstp*` 保存并弹出栈顶；`fadd`、`fmul` 等执行运算。
- **MMX／SSE**：面向向量寄存器，将多个元素打包后用 SIMD（Single Instruction Multiple Data，单指令多数据）指令同时处理；SSE 的 `XMM` 寄存器为 128 位。

> [!example] x87 为什么可能产生额外精度差异？
> 中间结果若暂存在 80 位扩展精度寄存器中，与每一步都舍入到内存中的 64 位 `double` 并不一定完全一致。某些编译器或优化情境中，是否暂存于浮点寄存器、何时发生舍入，会改变最终的最低有效位。不能仅从一段 C 表达式就机械断定其机器层每步都以 64 位舍入。

> [!warning] SIMD 速度并非永远按元素数成倍提高
> 课件通过普通逐元素操作与 SIMD 运算的计时比较说明数据级并行潜力；实际加速仍取决于访存、编译器、指令集支持、数据对齐及测试方式。时间数字不能照搬为所有设备上的性能结论。


#### x87 指令进一步速查

| 指令家族 | 功能 | 理解重点 |
| --- | --- | --- |
| `flds`／`fldl` | 从内存加载32／64位浮点数到浮点寄存器栈 | 装入后可能采用80位内部表示 |
| `fildl` | 将32位整数转成浮点数后压入寄存器栈 | 不是直接复制整数位模式 |
| `fstl`／`fstpl` | 把浮点栈顶转为64位浮点存入内存；后者同时弹栈 | 可能发生舍入 |
| `fxch` | 交换栈顶与指定浮点寄存器 | 改变浮点栈内对象位置 |
| `fld1`、`fldz`、`fldpi` | 把常量1、0、π装入浮点栈 | 常量加载 |
| `fadd`、`fsub`、`fmul`、`fdiv` | 浮点四则运算 | 具体操作数顺序需查相应形式 |
| `faddp`、`fmulp` 等 | 运算并弹出浮点栈元素 | `p` 往往表示弹栈 |
| `fsubr`、`fdivr` 等 | 反向顺序的减法／除法 | 不能忽略操作数方向 |

> [!example] 从 C 代码理解 `fidivl`
> `double f(int x) { return 1.0 / x; }` 在课件的传统 x87 示例中使用 `fld1` 把 `1.0` 压入浮点栈，再用 `fidivl 8(%ebp)` 把整数形参转成浮点数并执行浮点除法。对于 `x=10`，数学结果是 0.1，但 0.1 无法用有限二进制浮点位精确表示，因此**是否经过寄存器暂存及舍入**可能影响浮点比较。

## 三、C 语言控制结构与函数调用的机器级表示

### 3.1 从机器层看一次函数调用

以两个 C 函数为例：

```c
int add(int x, int y) {               // 被调用函数：接收两个形参
    return x + y;                     // 把结果交回调用者
}

int caller(void) {                    // 调用函数
    int t1 = 125;                     // 第一个实参的来源
    int t2 = 80;                      // 第二个实参的来源
    int sum = add(t1, t2);           // 传递参数、跳转、取回返回值
    return sum;                       // 把205继续返回
}
```

机器级调用通常涉及六项任务：

1. 调用者准备实参（按 ABI 放入约定的寄存器或栈位置）。
2. 执行 `call`，把**返回地址**保存起来，并将控制交给被调用者。
3. 被调用者按需建立自己的栈帧、保存约定必须保持的寄存器。
4. 被调用者执行运算，生成返回值。
5. 被调用者按需恢复寄存器、释放栈帧。
6. 执行 `ret`，取出之前保存的返回地址，返回调用者。

> [!important] 什么是返回地址？
> 返回地址不是“调用函数的首地址”，而是**调用点之后应当继续执行的指令地址**。`call` 保存它，`ret` 使用它。

### 3.2 IA-32 函数栈帧及参数位置

在课件采用的传统 **i386 System V、以 EBP 作为帧指针** 的示例中：

| 相对 `EBP` 的位置 | 典型内容 |
| --- | --- |
| `EBP+16` | 第 3 个按栈槽传递的 32 位参数 |
| `EBP+12` | 第 2 个参数 |
| `EBP+8` | 第 1 个参数 |
| `EBP+4` | 返回地址 |
| `EBP+0` | 上一层栈帧的 `EBP` |
| `EBP−4`、`EBP−8`…… | 当前函数的部分局部变量、保存的数据等 |

下面给出手写的、符合传统 32 位调用接口的示意汇编函数（不承诺与某个优化级别的 GCC 输出逐字相同）：

```asm
.globl add                     # 把 add 导出为可链接的全局符号
add:
    pushl %ebp                # 保存调用者旧的 EBP
    movl %esp, %ebp           # 建立本函数栈帧基址
    movl 8(%ebp), %eax        # EAX ← 第一个参数 x
    addl 12(%ebp), %eax       # EAX ← x+y，结果通过 EAX 返回
    popl %ebp                 # 恢复调用者的 EBP
    ret                       # 从栈中取出返回地址并跳转
```

**为什么第一个参数在 `EBP+8`？** 进入被调用函数前，实参已经在栈中；`call` 又压入 4 字节返回地址，函数的 `pushl %ebp` 再压入 4 字节旧帧指针，因此第一个参数相对新 `EBP` 是正偏移 8。

> [!note] 这不是所有函数的固定布局
> 现代编译器可**省略帧指针**，优化中间局部变量，或使用寄存器传参；x86-64 约定也不同。`EBP+8` 是理解课件指定 32 位调用模式的典型结构，而不是任何架构通用的规定。

### 3.3 函数序言、主体和尾声

传统栈帧建立：

```asm
pushl %ebp                    # 保存旧帧指针
movl %esp, %ebp              # EBP 指向当前栈帧基址
subl $16, %esp               # 预留16字节空间供局部数据等使用
```

函数返回前：

```asm
leave                         # 等价于先 movl %ebp,%esp 再 popl %ebp
ret                           # 弹出返回地址并转移控制
```

**栈帧大小不由 C 变量个数直接决定**：局部变量可能存在寄存器中；编译器可能增加填充和对齐空间，也可能优化掉部分变量或整个栈帧。

### 3.4 调用者保存与被调用者保存寄存器

在本章所用 **i386 System V ABI** 下，主要约定是：

| 类别 | 典型寄存器 | 谁承担保存责任 |
| --- | --- | --- |
| 调用者保存（caller-saved） | `EAX`、`ECX`、`EDX` | 调用者若要跨调用保留这些旧值，应自己保存 |
| 被调用者保存（callee-saved） | `EBX`、`ESI`、`EDI`、`EBP` | 被调用者若修改，应在返回前恢复 |
| 栈指针 | `ESP` | 调用结束后必须满足 ABI 要求的栈平衡 |

因此，对于很简单的叶子函数（不调用其他函数），编译器常可优先使用 `EAX`、`ECX`、`EDX` 以避免不必要的保存恢复操作。

> [!warning] 现场保存不等于全部寄存器都必须压栈
> 过程调用必须维护的是 **ABI 约定要求保持的程序状态**；不意味着每一次函数调用都必然将所有寄存器保存到栈中。

### 3.5 参数传递：传数值还是传地址？

**C 语言参数始终按值传递**：传入基本变量得到值的副本；传入指针时，复制的是指针值（地址），被调用函数可通过该地址修改原对象。

下面对比两个 `swap` 函数。按值版本：

```c
void swap_value(int x, int y) {       // x、y是实参值的副本
    int temp = x;                     // 暂存形参x
    x = y;                            // 只改变当前函数中的x
    y = temp;                         // 只改变当前函数中的y
}
```

按地址版本：

```c
void swap_address(int *x, int *y) {   // 接收两个 int 对象的地址
    int temp = *x;                    // 读取x指向的原对象
    *x = *y;                          // 修改第一个原对象
    *y = temp;                        // 修改第二个原对象
}
```

调用：

```c
int a = 15;                           // 原始变量a
int b = 22;                           // 原始变量b
swap_value(a, b);                     // a、b仍是15和22
swap_address(&a, &b);                 // a变为22，b变为15
```

> [!important] 一定要分清两次“复制”
> `swap_address(&a,&b)` 仍然是**按值传参**：复制的是 `&a` 和 `&b` 两个地址值。能够修改原对象，是因为函数对指针进行了**间接寻址**，而不是 C 自动采用了“引用传递”。

### 3.6 静态局部变量与非静态局部变量的存储

```c
int counter(void) {                  // 每次调用共享同一静态局部变量
    static int total = 0;            // 通常位于静态存储区，生命周期贯穿程序
    int step = 1;                    // 自动存储期的局部变量
    total += step;                   // 每次调用使 total 增加1
    return total;                    // 返回本次累积结果
}
```

- `total` 是静态存储期对象，通常在 `.data` 或 `.bss` 一类区域，不随函数调用结束销毁。
- `step` 是自动存储期对象，可能分配在栈上，也可能被编译器保存在寄存器中，甚至被优化掉。
- **作用域**描述标识符在哪些代码位置可见；**生存期／存储期**描述对象什么时候存在，不能混同。

> [!warning] 未初始化的局部变量
> 对未初始化的自动局部变量直接读取，例如 `int x; printf("%d",x);`，其行为不能当作“输出栈里原有的一个固定随机数”来理解；可能涉及不确定值或未定义行为，并且优化器可能产生与简单栈图不同的结果。应先初始化再使用。

### 3.7 递归调用为什么占用更多栈空间？

```c
int nn_sum(int n) {                    // 递归求1到n的和
    if (n <= 0) {                     // 终止条件，避免无限递归
        return 0;                     // 基础情形结果为0
    }
    return n + nn_sum(n - 1);         // 当前n + 下一层递归结果
}
```

当 `nn_sum(3)` 执行时，出现嵌套调用 `nn_sum(3) → nn_sum(2) → nn_sum(1) → nn_sum(0)`。每一层都需要保存自己的返回位置及必要状态，因此活动调用层数越多，栈消耗通常越大。

使用循环改写：

```c
int nn_sum_loop(int n) {              // 迭代版本
    int result = 0;                   // 累加器
    for (int i = 1; i <= n; ++i) {    // 逐个加入1到n
        result += i;                  // 更新当前累加结果
    }
    return result;                    // 返回总和
}
```

| 对比项 | 一般递归实现 | 迭代实现 |
| --- | --- | --- |
| 调用层数 | 随 `n` 增加 | 通常不随 `n` 增加 |
| 附加栈空间 | 通常为 `O(n)` | 通常为 `O(1)` |
| 计算次数 | 此示例为 `O(n)` | 此示例为 `O(n)` |
| 注意事项 | 可能发生栈耗尽 | 大量相加仍可能导致有符号整数溢出 |

课件给出了具体旧式 GCC 汇编的每层指令数和栈帧大小；这些是**该示例编译结果的特征**，不能推广成“每次递归总是 16 字节、16 条指令”。

### 3.8 if / else 的底层实现

```c
int greater(int a, int b) {          // 返回两数中的较大者
    if (a > b) {                     // 根据比较结果选择分支
        return a;                    // 条件为真时返回a
    } else {
        return b;                    // 否则返回b
    }
}
```

传统未做特殊优化的机器级实现通常包含：

1. 用 `cmp` 对两个值做减法比较，仅更新条件码。
2. 用 `jcc`（条件跳转）进入对应分支。
3. 分支执行结果通常汇合在公共结束位置，或直接返回。

下面是一个独立的 IA-32 示例：

```asm
# 前提：EAX中存a，EDX中存b，结果返回EAX
cmpl %edx, %eax             # 比较a-b，更新标志位
jg done                     # 若a>b，则EAX已经是较大者
movl %edx, %eax             # 否则令EAX←b
done:
```

其中 `jg` 适合**有符号整数**比较；对无符号整数需相应使用 `ja`。

### 3.9 短路求值 `&&`、`||`

```c
int positive_value(const int *p) {   // 参数可以是空指针
    if (p != NULL && *p > 0) {       // p为空时绝不执行后面的*p
        return *p;                   // 读取有效对象的值
    }
    return 0;                        // 空指针或非正数返回0
}
```

`&&` 的短路性质意味着：左边为假，不再计算右边。机器层面通常可用“先比较指针是否为空 → 条件不满足则跳转 → 读取指针指向的数据”的控制流实现。不能把这类条件误当成始终计算两个子表达式的按位 `and` 指令。

### 3.10 switch-case 与跳转表

```c
int sw_test(int a, int b, int c) {
    int result;                        // 用于保存结果
    switch (a) {                       // 按a选择执行路径
        case 15:
            c = b & 0x0f;             // 没有break，继续执行case 10
        case 10:
            result = c + 50;          // a=15或a=10都能执行这里
            break;
        case 12:
        case 17:
            result = b + 50;          // 两个标签共享一个处理分支
            break;
        case 14:
            result = b;               // 直接取b
            break;
        default:
            result = a;               // 其他情况返回a
    }
    return result;                     // 返回最终结果
}
```

这个例子可以采用**跳转表**：编译器先计算 `i=a-10`，检查 `i` 是否超出 0～7 的范围，然后根据 `i` 查表取得目标代码地址，再间接跳转。

> [!note] 为什么不一定生成多个 if？
> 当 `case` 值在相对紧密的区间内分布时，跳转表可能减少连续比较。若取值稀疏、分支很少或编译策略不同，仍可能使用条件跳转链。**跳转表是常见实现，不是 C 语言语法强制的实现。**

### 3.11 三种循环的机器级规律

| 循环形式 | 条件检查典型位置 | 主要控制特征 |
| --- | --- | --- |
| `while` | 循环体之前 | 可能一次都不执行 |
| `do...while` | 循环体之后 | 至少执行一次 |
| `for` | 初始化一次；每轮判断、更新 | 可归结为初始化 + 条件跳转 + 循环体 + 更新 |

用 C 代码直接对照：

```c
int count_while(int n) {             // while形式
    int i = 0;                       // 初始化计数器
    while (i < n) {                  // 每轮先检查条件
        ++i;                         // 循环体
    }
    return i;                        // 返回迭代次数
}
```

```c
int count_do_while(int n) {          // do...while形式
    int i = 0;                       // 初始化计数器
    do {
        ++i;                         // 先执行一次循环体
    } while (i < n);                 // 在末尾检查是否继续
    return i;                        // n<=0时仍返回1
}
```

优化后的循环甚至可能不保留一个与 C 源代码逐一对应的“`i` 存储单元”；编译器只要保证语言语义，就可以重排计算。

### 3.12 逆向工程：从汇编恢复算法

课件展示了如下函数的关键运算：

```asm
leal (%eax,%eax), %edx       # EDX ← 2×EAX
movl %ebx, %eax             # EAX ← 当前x
andl $1, %eax               # EAX ← x最低位
orl %edx, %eax              # EAX ← 2×旧result | (x&1)
shrl %ebx                   # x无符号右移1位
```

如果这样的操作重复执行 32 轮，并且起始 `result=0`，其高级语言核心可以写成：

```c
unsigned reverse_bits(unsigned x) {  // 按32位unsigned来处理
    unsigned result = 0;             // 初始化翻转结果
    for (int i = 0; i < 32; ++i) {   // 处理每一个位位置
        result = (result << 1) | (x & 1u); // 左移并接入x的最低位
        x >>= 1;                     // 丢掉已处理的最低位
    }
    return result;                    // 返回32位逆序后的位串
}
```

> [!tip] 逆向分析的五步法
> ① 先确认输入、输出所在寄存器；② 跟踪每次写寄存器后的新值；③ 识别 `cmp`／`jcc` 构成的循环；④ 将 `lea`、`and`、`or`、移位组合成表达式；⑤ 用一个简单输入（如最低位为1）手工验证语义。

## 四、复杂数据类型的内存分配与访问

### 4.1 数组为什么能用一个公式定位元素？

C 数组元素的共同特征是：**同类元素连续存放，每个元素占用的字节数相同**。若元素类型为 `T`，首地址为 $A$，则

$$\operatorname{addr}(a[i])=A+i\times\operatorname{sizeof}(T)$$

实际计算时注意区分：

- 数组下标 `i` 是**元素序号**，不是直接的字节偏移量。
- `sizeof(T)` 是**单个元素字节数**。
- `a[i]` 表示数组第 `i` 个元素；`&a[i]` 表示该元素地址。

对于课件的 `short A[4]`，若 `EDX` 保存数组首地址，`ECX` 保存 `i`，则：

```asm
movw (%edx,%ecx,2), %ax      # AX ← A[i]，i乘2是short的字节宽度
```

> [!important] 两种“加法”
> **机器地址加法**按字节计算；**C 指针加法**按指向元素的大小自动缩放。因此 `p+1` 并不一定等于地址数值加 1。

### 4.2 全局／静态数组与自动数组

全局数组的例子：

```c
int buf[2] = {10, 20};             // 全局已初始化数组，通常在.data中

int sum_global(void) {             // 累加全局数组
    int sum = 0;                   // 初始累加和
    for (int i = 0; i < 2; ++i) {  // 遍历两个数组元素
        sum += buf[i];             // 每次读取对应元素
    }
    return sum;                    // 返回30
}
```

如果数组首址在 `EDX`，下标 `i` 在 `ECX`、累加和在 `EAX`，访问语句可采用：

```asm
addl (%edx,%ecx,4), %eax     # 把buf[i]的4字节值加到EAX
incl %ecx                    # 下标i加1，不改变CF
```

自动数组的例子：

```c
int sum_local(void) {               // 函数内创建局部数组
    int buf[2] = {10, 20};          // 典型未优化实现中分配在当前栈帧
    return buf[0] + buf[1];         // 返回30
}
```

在某个使用 `EBP` 定位局部数组的栈帧中，可以出现：

```asm
movl $10, -8(%ebp)            # 令buf[0]=10
movl $20, -4(%ebp)            # 令buf[1]=20
leal -8(%ebp), %edx          # EDX ← buf的首地址
```

> [!warning] 全局／静态与局部的本质差异
> `static` 存储期数组和自动存储期数组的差异是**生存期及存储方式**；“全局数组一定在固定地址”“局部数组一定在栈中”只是分析未优化机器代码时常用的简化模型。编译优化及实际装载机制可能改变具体布局。

### 4.3 数组与指针的联系及区别

```c
int a[4] = {2, 4, 6, 8};           // 定义包含4个int元素的数组
int *ptr = &a[0];                 // 指针保存第一个元素地址
int first = *ptr;                 // 读取a[0]，即2
int third = *(ptr + 2);          // 指针前移两个int元素后读取a[2]，即6
```

在这个条件下，以下表达式关系成立：

$$a[i]\equiv *(a+i)\equiv *(ptr+i)\equiv ptr[i]$$

数组与指针仍有重要区别：

| 表达式／对象 | 含义 |
| --- | --- |
| `a` | 在大多数表达式中转换成 `&a[0]` |
| `ptr` | 一个独立指针变量，其存储内容是地址 |
| `sizeof(a)` | 整个数组大小，若 `int` 为4字节则为16字节 |
| `sizeof(ptr)` | 指针对象本身的大小，IA-32通常为4字节 |
| `&a` | 指向**整个数组**的指针，类型是 `int (*)[4]` |
| `a + 1` | 地址增加 `sizeof(int)` |
| `&a + 1` | 地址增加 `sizeof(a)`，也就是整个数组大小 |

> [!example] 看懂指针加法
> 假设 `int` 占 4 字节，`ptr=0x1000`，则 `ptr+1=0x1004`，`ptr+3=0x100C`。编译器可使用比例因子 4 的变址寻址计算对应地址。

### 4.4 二维数组的行优先存储

```c
int a[3][4] = {                    // 3行4列，共12个int
    {1, 2, 3, 4},                  // 第0行
    {5, 6, 7, 8},                  // 第1行
    {9, 10, 11, 12}                // 第2行
};
```

C 的多维数组采用==行优先（row-major）==布局。对 `T a[M][N]`：

$$\operatorname{addr}(a[i][j])=A+(iN+j)\times\operatorname{sizeof}(T)$$

当列数为 4、`int` 宽 4 字节时：

$$\operatorname{addr}(a[i][j])=A+16i+4j$$

> [!tip] 机器寻址比例因子只有 1、2、4、8，怎么办？
> 对二维数组，编译器可能先将 `i×N` 或 `i×N×sizeof(T)` 计算到一个寄存器中，再结合 `j` 使用合法比例因子寻址。**公式可以出现乘16，单条 x86 比例变址指令的 SIB 比例因子仍只能选1、2、4、8。**

### 4.5 指针数组并不等于二维数组

```c
int row0[3] = {1, 2, 3};            // 第一行，3个int连续存储
int row1[3] = {4, 5, 6};            // 第二行，另一个独立数组
int *rows[2] = {row0, row1};        // 指针数组，每个元素存一个地址
int value = rows[1][2];            // 通过第二个指针读取值6
```

- `int a[2][3]`：六个整数在一个完整数组对象中连续存储。
- `int *rows[2]`：首先存储两个**指针值**；指针所指的行可以分布在不同地址，不保证连成同一二维数据块。
- `rows[i][j]` 需要先读取 `rows[i]` 中的地址，再据此取对应行的第 `j` 个元素。

> [!warning] 切勿只看下标语法
> `a[i][j]` 和 `rows[i][j]` 的外观一样，但在内存中定位元素的方法不同。前者可用完整的行跨度直接计算；后者需要读取指针数组成员。

### 4.6 结构体：基址加成员偏移量

课件给出的结构体可规范书写为：

```c
struct cont_info {
    char id[8];                      // 证件编号，8字节
    char name[12];                   // 名字，12字节
    unsigned int post;               // 邮政编码，IA-32下通常4字节
    char address[100];               // 地址，100字节
    char phone[20];                  // 电话，20字节
};
```

在课件假定的 i386 对齐条件下，成员偏移是：

| 成员 | 相对结构体首地址偏移 | 占用字节 |
| --- | ---: | ---: |
| `id` | 0 | 8 |
| `name` | 8 | 12 |
| `post` | 20 | 4 |
| `address` | 24 | 100 |
| `phone` | 124 | 20 |

该示例总体占用 **144 字节**。当结构体对象首地址在 `EDX`，读取 `post` 可写：

```asm
movl 20(%edx), %eax           # EAX ← 对象post成员的32位值
```

**核心规律：**

$$\operatorname{addr}(s.member)=\operatorname{addr}(s)+\operatorname{offset}(member)$$

C 语言可用 `offsetof` 查看成员偏移：

```c
#include <stddef.h>                   // 声明标准宏offsetof

size_t pos = offsetof(struct cont_info, post); // 获取post偏移
```

### 4.7 结构体按值传递与通过指针修改

```c
struct Student {
    int id;                          // 学号
    int score;                       // 分数
};

void change_copy(struct Student s) { // 复制结构体的当前成员值
    s.score = 100;                   // 只修改局部副本
}
```

```c
void change_original(struct Student *s) { // 接收结构体对象地址
    s->score = 100;                  // 通过地址修改原对象
}
```

用法：

```c
struct Student alice = {1, 80};      // 初始化对象
change_copy(alice);                  // alice.score仍为80
change_original(&alice);             // alice.score变成100
```

- `s->score` 等价于 `(*s).score`，先取指针指向的结构体，再访问成员。
- 按值传递结构体需要传递**整个结构体的值**；在课件所采用的 32 位 ABI 示例中常体现为参数区复制。
- 通过指针传递通常只需复制一个地址，但程序仍必须保证指针有效、指向的对象允许修改。
- 结构体返回与参数传递的细节受 ABI 影响；不能把 IA-32 栈传递机制直接推广到所有 64 位环境。

### 4.8 联合体 union：多个成员复用同一段空间

```c
union Value {
    char c;                          // 1字节成员
    short s;                         // 2字节成员
    int i;                           // 4字节成员
};
```

**结构体**的成员通常位于各自的存储区；**联合体**的全部成员从同一个起始位置重叠布局。联合体的总大小足以容纳最大成员，并满足对齐要求。本例在常见 IA-32 环境下占 4 字节。

> [!example] 相同位序列可有不同解释
> 若将浮点数 `10.0f` 的 IEEE 754 单精度位模式按 32 位无符号数观察，可得到 `0x41200000`，对应十进制 `1092616192`。注意这个整数不是把 `10.0f` 做数值类型转换得到的 `10`，而是解释**同一组位**所得到的结果。

为了在代码中清楚、可移植地检查位模式，可使用 `memcpy`：

```c
#include <stdint.h>                   // uint32_t
#include <string.h>                   // memcpy

uint32_t float_bits(float value) {    // 取得浮点数据的原始32位位模式
    uint32_t bits = 0;                // 为目标32位整数准备空间
    memcpy(&bits, &value, sizeof bits); // 复制对象表示，不做数值转换
    return bits;                      // 返回位模式
}
```

上述代码的数值解释还以平台提供 32 位 `float`、IEEE 754 格式等条件为前提。联合体读取非最近写入成员存在语言规则和可移植性限制；**重解释字节**与**数值转换**必须分开理解。


#### 联合体与嵌套结构：为什么能表达不同形态的数据？

课件进一步展示了通过联合体嵌套结构体，令同一存储区域承担不同角色。下面用较短的标准 C 示例呈现相同思想：

```c
struct Node {
    int kind;                          // 先记录当前应使用哪一种成员
    union {
        int number;                    // 类型一：保存一个整数
        struct Node *next;            // 类型二：保存下一个节点的地址
    } value;                           // 两种成员共享这一段空间
};
```

- `value.number` 和 `value.next` **占用同一段联合体存储区**，不应把它们当成可同时独立保存的两个成员。
- `kind` 是额外的**判别字段**，由程序决定当前哪个成员的值有效。
- 当 `next` 被当作链表指针使用时，节点必须仍然有效，指针也必须指向合法节点或为空指针。

另一种典型用途是表示寄存器的不同宽度视图：一个 32 位寄存器可以看成完整 32 位、低16位或各字节；但在可移植 C 程序中，要注意**联合体成员重解释与字节序、实现规定之间的关系**，不能以为该内存重叠技巧自动保证所有平台布局相同。

### 4.9 字节对齐：为什么编译器会插入“空字节”？

**对齐**是指数据的起始地址满足特定整数倍要求。若类型的对齐要求为 $K$，一般要求

$$\operatorname{addr}(object)\bmod K=0$$

例如一个需要 4 字节对齐的 `int`，其起始地址常为 `0,4,8,12,...`。若一个多字节数据跨越存储访问边界，可能增加硬件处理成本；但现代处理器对非对齐访问的支持和性能因指令、内存类型、硬件代际而异。

在课件指定的典型 **i386 System V ABI** 下：

| 类型（典型） | 字节数 | 常见对齐要求 |
| --- | ---: | ---: |
| `char` | 1 | 1 |
| `short` | 2 | 2 |
| `int`、`float`、指针 | 4 | 4 |
| `double` | 8 | 4 |
| `long long` | 8 | 4 |

注意 `double` 在该 32 位 ABI 下可以**大小为 8、对齐为 4**；这与常见 x86-64 System V ABI 的 `double` 按 8 字节对齐不同。

### 4.10 结构体布局的三条规则

1. **成员对齐**：将每个成员放在符合它的对齐要求的最早可用位置。
2. **整体对齐**：结构体整体对齐要求通常不小于成员中最严格的对齐要求。
3. **尾部填充**：结构体总大小需适合连续构造结构体数组，使每个数组元素中的成员仍满足对齐要求。

下面对比两个结构体：

```c
struct S1 {
    int i;                           // 偏移0～3
    char c;                          // 偏移4
    int j;                           // 偏移8～11，前有3字节填充
};
```

```c
struct S2 {
    int i;                           // 偏移0～3
    int j;                           // 偏移4～7
    char c;                          // 偏移8，末尾可能补3字节
};
```

在 `int` 按 4 字节对齐的条件下：**`sizeof(struct S1)=12`，`sizeof(struct S2)=12`**。虽然第二个结构体的最后一个有效成员止于第 8 字节，尾部仍需填充以保障结构体数组正确对齐。

> [!warning] 不要只把各成员的 sizeof 相加
> `4+4+1=9` 是 `S2` 的**成员原始字节数**，不是完整 `sizeof(struct S2)`。结构体数组尤其需要考虑尾部填充。

### 4.11 调整成员顺序节省存储空间

原始定义：

```c
struct RecordA {
    char a;                          // 占1字节
    int b;                           // 需4字节对齐，可能出现填充
    char c;                          // 占1字节
    short d;                         // 需2字节对齐
};
```

合理重排：

```c
struct RecordB {
    int b;                           // 先放4字节数据
    short d;                         // 再放2字节数据
    char a;                          // 放1字节数据
    char c;                          // 继续放1字节数据
};
```

常见 4 字节 `int` 对齐环境下：

| 对象 | 单个对象 | 64 个元素的数组 |
| --- | ---: | ---: |
| `struct RecordA` | 12 B | 768 B |
| `struct RecordB` | 8 B | 512 B |

节省 **256 字节**，约为原数组占用空间的三分之一。成员顺序调整可能破坏已定义的外部二进制接口和数据格式，因此**已有 ABI／持久化布局不可随意重排**。

### 4.12 对齐控制：`#pragma pack`、`packed`、`aligned`

课件还介绍了指定布局的扩展：

```c
#pragma pack(push, 1)                // 临时将成员最大对齐限制为1
struct PackedItem {
    char type;                       // 偏移0
    int value;                       // 紧随其后，通常偏移1
};
#pragma pack(pop)                    // 恢复之前的打包设置
```

在相应编译器支持时，`sizeof(struct PackedItem)` 通常为 5，而非自然对齐下的 8。

GCC/Clang 扩展示例：

```c
struct PackedData {
    char c;                          // 第一个成员
    int n;                           // 可紧挨着c存放
} __attribute__((packed));           // 使用紧凑布局
```

```c
struct AlignedData {
    int number;                      // 唯一数据成员
} __attribute__((aligned(16)));       // 将类型整体对齐要求提高到16
```

- `packed` **降低布局填充**，不一定更高效；某些平台上直接访问非对齐成员还可能受硬件限制。
- `aligned(16)` 提高指定对象或类型的对齐要求，通常也会影响数组元素的步长。
- `#pragma pack`、`__attribute__` 属于实现相关扩展，不能当作全部 C 编译器都统一支持的 ISO C 语法。

> [!tip] 自己观察实际布局
> 可以使用 `sizeof`、`_Alignof`（C11）和 `offsetof` 验证平台布局，而不是凭经验猜测成员偏移。特别是 `#pragma pack(1)`、`pack(2)`、`pack(4)` 与 `aligned(...)` 组合时，**成员对齐、整体对齐、尾部填充**需要分别考虑。

## 五、越界访问、缓冲区溢出与程序安全

### 5.1 数组越界为什么危险？

C 语言中的下标访问与指针运算建立在地址计算之上，通常不会由机器指令自动完成 C 数组边界检查。

```c
int a[2] = {10, 20};                 // 合法索引只有0和1
int first = a[0];                    // 合法读取
int second = a[1];                   // 合法读取
```

如果使用 `a[2]`、`a[-1]` 或向对应地址写入数据，就会越过数组对象边界。==数组越界访问属于未定义行为==，不能保证读到某个固定值，也不能保证一定产生段错误。

### 5.2 缓冲区与字符串结束符

对 `char buffer[10]`：

- 缓冲区共有 10 字节。
- 作为以 `\0` 结尾的 C 字符串时，最多安全存储 **9 个非零字符 + 1 个 `\0`**。
- 复制超长字符串可能写到相邻对象或栈帧控制信息所在位置。

> [!warning] “16 字节缓冲区复制 25 个字符”不是统一攻击阈值
> 课件的固定偏移实验说明了**溢出可能破坏相邻栈内容乃至返回地址**。但具体超出多少字节会覆盖什么数据，依赖编译器生成的布局、栈保护和系统配置，不能把某个实验偏移当成可跨环境套用的常量。

### 5.3 从栈帧理解溢出的后果

传统 IA-32 栈帧可以同时容纳局部字符数组、保存的 `EBP` 和返回地址。若输入写入越过数组末尾，可能污染：

- 相邻局部变量，引起不正确的计算或输出；
- 保存的寄存器值，破坏函数返回后的状态；
- 调用控制数据，引起异常控制流或崩溃。

并非只有栈上的数组才会产生溢出：堆对象和静态对象同样可能被越界访问破坏。程序是否立即崩溃也不是判断越界是否存在的可靠方法。

### 5.4 用边界检查防止越界写入

课件使用 `strcpy` 展示“源字符串长度超过目的数组容量”的风险。对已知容量的字符数组，更安全的例子是：

```c
#include <stdio.h>                    // 声明fgets和printf

int main(void) {                       // 标准C程序入口
    char buffer[16];                  // 只容纳16字节
    if (fgets(buffer, sizeof buffer, stdin) == NULL) { // 限制最多读取15个字符并留结束符
        return 1;                     // 读取失败或没有获得字符串
    }
    printf("%s", buffer);             // 将输入作为数据输出
    return 0;                         // 正常结束
}
```

这里的 `fgets` 最多将 `sizeof(buffer)-1` 个字符及一个终止空字符写入数组；但**过长输入可能被截断，剩余内容仍留在输入流**，如果业务必须接收完整行，需要额外处理截断情况。

> [!important] 安全规则
> **每次向缓冲区写入时，写入数据加终止字节都不得超过目标容量。** 对不可信输入同时检查长度、合法性和完整性；只换掉一个函数名并不足以解决所有安全问题。

### 5.5 三类典型防护措施

| 防护 | 核心机制 | 限制 |
| --- | --- | --- |
| ASLR（地址空间布局随机化） | 随机化代码、库、栈等映射的位置 | 降低地址可预测性，但不能修复越界代码 |
| 栈破坏检测／栈保护 | 在敏感栈对象与控制数据附近放置检查值，返回前检测 | 可检测某些覆盖，但不能捕获所有越界 |
| 不可执行数据区域（NX/DEP） | 将某些数据映射区域标记为不可执行 | 抑制代码注入执行，并不阻止内存破坏本身 |

还应利用编译器警告、静态分析、运行时检测（如 AddressSanitizer）和代码审查查找越界问题。防护之间是**相互补充**，而不是单一技术保证绝对安全。

### 5.6 `argc`、`argv`、程序装载

标准 C 的常见程序入口：

```c
int main(int argc, char *argv[]) {    // argc为参数数量，argv为字符串指针数组
    if (argc < 2) {                  // 检查是否提供额外命令行参数
        return 1;                    // 缺少必要参数则退出
    }
    return 0;                        // 正常结束
}
```

- `argc` 包含 `argv[0]`；常见环境中 `argv[0]` 为程序名称或路径。
- `argv[argc]` 是空指针，表示参数数组结束。
- 在 POSIX 系统中，`execve` 用于以新程序映像替换当前进程映像；**执行成功不返回到旧程序**，失败则返回 `-1` 并设置错误信息。
- `envp` 可以通过特定平台机制传递环境字符串数组，但 `main` 的三参数形式是**常见扩展，不是标准 C 必须提供的入口签名**。

### 5.7 一个类型不匹配的隐藏错误：`printf`

```c
#include <stdio.h>                    // 声明printf

int main(void) {                       // 标准入口
    double a = 10.0;                  // 定义双精度浮点变量
    printf("a = %.1f\n", a);         // 使用%f，输出a = 10.0
    return 0;                         // 正常结束
}
```

`printf` 是可变参数函数，格式字符串决定后续参数如何解释。若把 `double` 配上 `%d`，则格式要求 `int`、实际却传入 `double`，发生**未定义行为**。

在课件的传统 IA-32 和 x86-64 示例中，之所以会观察到不同的输出，是因为 ABI 对浮点参数与整数参数的传递位置不同；但**不能把 IA-32 一定打印 0、x86-64 一定打印随机数当成 C 语言规则**。

## 六、x86-64 与 IA-32 对照

### 6.1 x86-64 的主要扩展

x86-64（AMD64／Intel 64）在兼容既有 x86 体系的基础上扩展：

- 传统 32 位 GPR 扩展为 64 位，如 `EAX → RAX`、`ESP → RSP`、`EBP → RBP`。
- 新增 `R8`～`R15`，形成 16 个通用整数寄存器。
- 可使用低位别名，如 `R8D`、`R8W`、`R8B`，以及 `DIL`、`SIL`、`BPL`、`SPL`。
- 整数寄存器数量、数据宽度和函数参数传递方式发生变化。
- `XMM` 向量寄存器用于常见标量与向量浮点运算；x87 仍然是架构历史的一部分，但现代 64 位编译器通常优先使用 SSE/AVX 等路径。

> [!note] 名词辨析
> **x86-64 不等于 IA-64**。IA-64 是不同的指令集架构；x86-64 是向后兼容的 x86 扩展。另须区分 64 位通用寄存器和 128 位 XMM 寄存器：早期 MMX 的 `MM0`～`MM7` 是 64 位，而非 128 位。

### 6.2 x86-64 的子寄存器特性

```asm
movq $-1, %rax               # RAX ← FFFFFFFFFFFFFFFF
movl $1, %eax                # 写EAX后RAX高32位被清零，RAX=1
movb $2, %al                 # 只改RAX低8位，此时RAX=2
```

**重要区别：在 64 位模式下写入 32 位通用寄存器，目标 64 位寄存器的高 32 位自动清零。** 写入 8 位或 16 位子寄存器通常不会发生这种整体清零。

### 6.3 x86-64 常用指令

| 指令 | 主要用途 |
| --- | --- |
| `movq` | 传送 64 位数据 |
| `movabsq` | 将需要完整 64 位立即数的值加载到寄存器 |
| `movsbq`、`movswq`、`movslq` | 从 8／16／32 位有符号扩展为 64 位 |
| `movzbq`、`movzwq` | 从 8／16 位零扩展为 64 位 |
| `addq`、`subq`、`imulq` | 64 位加、减、乘 |
| `leaq` | 计算 64 位有效地址或整数表达式 |
| `pushq`、`popq` | 以 8 字节为单位操作栈 |

```asm
movslq %edi, %rax             # 将有符号32位EDI扩展到64位RAX
leaq (%rdi,%rsi,2), %rax      # RAX ← RDI + 2×RSI，不访问内存
```

### 6.4 Linux x86-64 System V 的整数参数传递

最常见的**前六个整数／指针参数**（按这类参数的顺序）使用：

| 参数顺序 | 64 位寄存器 | 32 位参数对应部分 |
| --- | --- | --- |
| 第1个 | `RDI` | `EDI` |
| 第2个 | `RSI` | `ESI` |
| 第3个 | `RDX` | `EDX` |
| 第4个 | `RCX` | `ECX` |
| 第5个 | `R8` | `R8D` |
| 第6个 | `R9` | `R9D` |

普通整数返回值通常放在 `RAX`／`EAX` 中；`call` 会把 8 字节返回地址压栈，`ret` 会将其取出并恢复对应的栈指针位置。超过可用参数寄存器数的参数按 ABI 约定使用栈或其他特定机制。

> [!warning] 这张表不能机械套到全部函数参数
> 浮点／向量参数通常使用 `XMM` 寄存器，并且实际参数分类、结构体传值、可变参数函数、栈对齐等有更完整的 ABI 规则。**不能简单认为函数的第 2 个参数必然在 RSI**：例如含有浮点参数的函数就要按参数类别判断。

### 6.5 Windows x64 的主要传参区别

| 对比项目 | Linux x86-64 System V | Windows x64 常见调用约定 |
| --- | --- | --- |
| 前四个整数／指针参数 | `RDI, RSI, RDX, RCX` | `RCX, RDX, R8, R9` |
| 前四个浮点参数 | 通常从 `XMM0` 等向量寄存器分配 | 通常按参数位置选 `XMM0`～`XMM3` |
| 更多整数参数 | 可继续用 `R8, R9` 等 | 超出前四个的通常转到栈上传递 |
| 栈帧附加规则 | System V 有自身对齐与寄存器约定 | 通常要求调用者准备 32 字节 shadow space |

> [!important] 同样是 64 位，为什么反汇编看起来差很多？
> 核心不一定是 C 程序不同，而是 **ABI 与编译器目标平台不同**。阅读反汇编时先确认是 IA-32、Linux x86-64 还是 Windows x64，再判定参数位置。

### 6.6 64 位数据对齐

在常见 **x86-64 System V LP64 ABI** 中：

| 类型 | 常见大小 | 常见对齐 |
| --- | ---: | ---: |
| `char` | 1 B | 1 B |
| `short` | 2 B | 2 B |
| `int`／`float` | 4 B | 4 B |
| `long`、指针、`double` | 8 B | 8 B |
| `long double`（传统 x87 扩展格式） | 16 B 存储槽 | 16 B |

这可以与 IA-32 的 `double` 为 8 字节、但只要求 4 字节对齐作对比。实际 ABI、编译器扩展或特殊指令可能进一步改变某些数据的对齐规则。

## 七、典型例题、易错辨析与复习速查

### 7.1 例题：写出机器级地址表达式

> [!example] 题目
> 已知一个 `short b[4][4]` 的首地址是 `0x1000`，`sizeof(short)=2`。求 `b[2][3]` 的地址，并说明应怎样利用 IA-32 比例变址寻址访问它。

**解答：** 每行 4 个元素，占 8 字节，所以

$$\operatorname{addr}(b[2][3])=0x1000+2\times8+3\times2=0x1016$$

如果 `EDX = 0x1010`（即第 2 行首地址）、`ECX=3`，则可用：

```asm
movw (%edx,%ecx,2), %ax       # 从0x1010+3×2=0x1016读取short
```

> [!warning] 易错点
> 不要写成 `0x1000+2×4+3`，因为这里的 `4` 是列数，不是字节宽度。

### 7.2 例题：无符号和有符号比较的分歧

> [!example] 题目
> 执行 `cmpl %ebx,%eax`，已知 `EAX=0xFFFFFFFF`、`EBX=1`，分别按无符号和有符号整数解释，`ja` 和 `jg` 是否跳转？

- 无符号解释：`EAX=4294967295`，大于 1，所以 **`ja` 跳转**。
- 有符号解释：`EAX=-1`，小于 1，所以 **`jg` 不跳转**。

> [!important] 判题关键
> 寄存器中的 `0xFFFFFFFF` 没有自行标注“有符号”或“无符号”。**使用哪一种条件跳转，决定把这一比特模式按哪一种比较意义来判断。**

### 7.3 例题：分析参数在传统 IA-32 栈帧中的位置

> [!example] 题目
> 对 `int add(int x,int y)`，假设使用标准序言 `pushl %ebp; movl %esp,%ebp`，形参 `x`、`y` 与返回地址相对 `EBP` 的偏移分别是多少？

**解答：** `x` 在 `8(%ebp)`；`y` 在 `12(%ebp)`；返回地址在 `4(%ebp)`。旧 `EBP` 保存在 `(%ebp)`。若 `add` 直接返回 `x+y`，则加法结果可以放到 `EAX`。

### 7.4 例题：计算结构体和结构体数组大小

> [!example] 题目
> 假定 `char` 大小／对齐为1，`short` 为2／2，`int` 为4／4。求下列结构体及其 10 元素数组的大小。

```c
struct Example {
    char a;                          // 偏移0
    int b;                           // 为满足4字节对齐，从偏移4开始
    short c;                         // 偏移8
};
```

**解答：**

- `a` 占偏移 0；偏移 1～3 是内部填充。
- `b` 占偏移 4～7；`c` 占偏移 8～9。
- 结构体最大对齐为 4，尾部补偏移 10～11 两字节，所以 `sizeof(struct Example)=12`。
- 数组占用 `12×10=120` 字节。

### 7.5 例题：分析数组越界与未定义行为

> [!example] 题目
> 一段代码声明 `char name[8]`，之后尝试保存一个包含 8 个普通字符的以零结尾的字符串，是否安全？

**解答：** 不安全。8 个字符本身需要 8 字节，结束符 `\0` 还需要 1 字节，总共需要 **9 字节**，超过数组容量 8。必须缩短内容或增加缓冲区容量，并使用能验证目标容量的写入逻辑。

### 7.6 课件细节与纠错清单

整理时应特别辨别以下问题，避免将历史示例、特定机器现象或笔误误当作通用规则。

| 容易出现的误读 | 正确理解 |
| --- | --- |
| 把“机器指令”和全部汇编源代码看成机械一对一 | 机器指令通常有对应汇编表示，但标签、伪指令、宏不一定对应单条机器码 |
| 把小端序理解为“整个数从右往左写” | 小端序只规定多字节数据在**各内存地址**上的排列，不能混淆位序和字节序 |
| `lea` 会读取目标地址中的数据 | `lea` 计算有效地址表达式，**不进行该内存数据读取** |
| 把 `CF=1` 和 `OF=1` 理解为同一类溢出 | `CF` 对应无符号进／借位，`OF` 对应有符号溢出 |
| `jae: CF=0 或 ZF=1`；`jb: CF=1 且 ZF=0` | 正确分别是 **`jae: CF=0`**、**`jb: CF=1`** |
| `jge: SF=OF 或 ZF=1`；`jl: SF≠OF 且 ZF=0` | 正确分别是 **`jge: SF=OF`**、**`jl: SF≠OF`** |
| `addl %dx,%ax` 能执行 32 位加法 | 源／目的宽度不一致，该写法**不合法**；若想执行 16 位加法应写 `addw %dx,%ax` |
| 把 16 位补码的最大无符号数误写为 65535 后仍按补码取反规则减去位模式 | 必须按 **$2^{16}=65536$** 处理 16 位负数补码的无符号解释 |
| 把变量在栈上的先后顺序当成 C 语言保证 | 局部变量布局由 ABI、编译器及优化决定，不保证源代码顺序 |
| 以为 `sizeof(struct)` 永远是成员大小简单相加 | 必须计算成员对齐、内部空隙与末尾填充 |
| 认为 `printf("%d", double值)` 在某平台必然输出 0 | **格式与实参类型不匹配是未定义行为**，观察结果不是语言保证 |
| 认为缓冲区溢出一定会立即崩溃 | 越界写可能暂时没有可见异常，也可能破坏控制信息或产生不可预测结果 |
| 将示例里的固定代码地址和 16B 栈帧推广到所有系统 | 地址、帧大小、栈上参数位置要以目标平台 ABI 和实际生成的机器码为准 |

### 7.7 自测练习（先独立完成，再看答案）

**题 5｜条件跳转**：执行 `cmpl %ebx,%eax`，若 `EAX=3`、`EBX=5`，应选择 `jl` 还是 `jg` 才能在**有符号小于**时跳转？

**题 6｜指针运算**：在 32 位 `int` 占 4 字节的环境中，指针 `int *p` 的数值地址为 `0x1000`，`p+3` 的地址是多少？

**题 7｜数组布局**：若 `int a[2][5]` 首址为 `0x2000`，`sizeof(int)=4`，求 `a[1][3]` 的地址。

**题 8｜过程调用**：在传统 i386 栈帧模型下，函数怎样获得第 2 个 `int` 参数？在此模型中哪个寄存器通常承载整数返回值？

**题 11｜x86-64**：Linux x86-64 System V 中第 1、2、3 个整数参数通常放在哪三个寄存器？同平台 32 位 `movl` 写入 `EAX` 后对 `RAX` 高 32 位有什么影响？

<details>
<summary>展开自测参考答案</summary>

1. 前者把立即数 8 写入 `EAX`；后者从内存地址 `EBP+8` 读取 4 字节到 `EAX`。
2. `EAX=100+5×4+12=132`。改为 `movl` 后，结果取决于地址 132 处的内存数据，不能仅由地址表达式算出。
3. `AL=0x78`、`AH=0x56`、`AX=0x5678`。
4. `EAX=0xFFFFFFFF`、`CF=1`（无符号减法借位）、`ZF=0`。
5. `jl`，表示有符号小于，即 `SF≠OF`。
6. `0x1000+3×4=0x100C`。
7. `0x2000+(1×5+3)×4=0x2020`。
8. 第 2 个栈上 `int` 参数一般从 `12(%ebp)` 读取；整数返回值通常在 `EAX`。
9. 通常为 8 字节：`c` 1 字节、填充 3 字节、`x` 4 字节。
10. 最多 5 个普通字符，另外 1 字节给 `\0`。
11. 分别为 `RDI`、`RSI`、`RDX`；写 `EAX` 会将 `RAX` 高 32 位清零。

| `cmp` + `jcc` | 通过减法标志判断并控制跳转 |
| `call` 与 `ret` | 保存返回地址／恢复返回地址 |
| `EBP+8` | 传统 IA-32 栈帧里的首个参数 |
| `RDI,RSI,RDX,RCX,R8,R9` | Linux x86-64 的前六个整数／指针参数寄存器 |
| `a[i]` | 首地址 + 下标×元素大小 |
| `a[i][j]` | 行优先：首地址 + (行×列数 + 列)×元素大小 |
| `s.member` | 结构体首址 + 成员偏移量 |
| `union` | 多成员共享同一段存储空间 |
| `sizeof(struct)` | 对齐、内部填充、尾部填充 |
| `strcpy`／越界写 | 检查目标缓冲区容量和终止符空间 |
| x87 与 SSE | 传统浮点寄存器栈与 SIMD／向量寄存器 |

> [!summary] 最终复习主线
> 1. **转换**：C 源程序经过预处理、编译、汇编、链接，生成可执行机器代码。
> 2. **执行**：ISA 决定指令／寄存器／地址模型，ABI 决定数据布局及调用约定。
> 3. **表达**：高级语言的算术、数组、条件、循环和函数调用，最终由数据传送、计算、比较、跳转和栈操作共同完成。
> 4. **存储**：数组依靠元素大小和下标定位，结构体依靠成员偏移，联合体共享存储空间，所有布局都可能受到对齐规则影响。
> 5. **安全**：机器按地址访问内存不等于 C 数组访问总是合法。理解栈帧、越界和 ABI，有助于解释程序异常并写出更可靠的代码。
